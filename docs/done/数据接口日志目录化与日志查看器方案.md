## 一、背景与动机

### 1.1、现状

当前运行日志由两个 callback 模块写入 `logs/{时间戳}/`：

- `AI/utils/llm_callbacks.py`：LLM 调用 → `{layer}/{seq:03d}_{NodeName}/req.md + res.md + meta.json`；LangChain 工具调用 → `.../tools/{seq:03d}_{tool}/req.json + res.txt`。均为文件夹式，阅读友好。
- `AI/utils/dataprovider_log.py`：`@dataprovider_log` 装饰器（41 处，全在 `AI/dataflows/interface.py`）→ 节点目录下平铺 `{接口名}.json`，结构为 `{name, desc, req, res}`。**res 绝大多数是 markdown 字符串（Provider 契约"返回格式统一为 str"），塞进 JSON 后阅读与检索都不方便**（用户反馈，见 `logs/2026-08-19_223929/market/001_International_Event_Extraction_Analyst/get_central_bank_calendar.json`）。
- 附带缺陷：同一节点内同一接口被多次调用时，`{接口名}.json` 后写覆盖先写，日志丢失。
- 无任何日志浏览工具，查看历史运行只能手动翻文件。

### 1.2、目标

1. dataprovider 调用日志改为文件夹式：`{seq:03d}_{接口名}/req.json + res.md + meta.json`，与 LLM 目录约定一致；序号按所属节点目录独立计数，重复调用不覆盖。
2. 新增 Streamlit 日志查看器（`streamlit run AI/logviewer/app.py`），可浏览 run → layer → 节点 → 各类日志，markdown 直接渲染；兼容历史旧格式 `{接口名}.json`（标记"旧格式"展示）。

## 二、架构设计

新目录树（相对旧版仅 dataprovider 行变化，其余不变）：

```
logs/{时间戳}/
├── market/
│   ├── 001_International_News_Analyst/
│   │   ├── req.md
│   │   ├── res.md
│   │   ├── meta.json
│   │   ├── 001_get_central_bank_calendar/   ← dataprovider 调用（新格式）
│   │   │   ├── req.json     ← 绑定后的完整入参
│   │   │   ├── res.md       ← 结果为 str（多数接口，markdown 契约）
│   │   │   └── meta.json    ← {name, desc, seq, ts, res}
│   │   └── tools/
│   │       └── 001_{tool}/req.json + res.txt
│   └── 002_US_News_Analyst/ …
├── sector/ …
├── stock/ …
└── reports/ …
```

查看器架构：`AI/logviewer/app.py`（Streamlit UI，纯展示）→ `AI/logviewer/logs_reader.py`（纯函数读取层，无 streamlit 依赖，供测试共用）。

### 2.1 数据模型设计

新格式目录内文件（写入者：`dataprovider_log._write`）：

| 字段/文件 | 内容 | 写入者 | 说明 |
|-----------|------|--------|------|
| `req.json` | 绑定后的入参 dict | `_write` | `_safe_json(req)` |
| `res.md` | 调用结果（str 时） | `_write` | markdown 契约 |
| `res.json` | 调用结果（非 str，如 get_stock_info dict） | `_write` | 二选一 |
| `meta.json` | `{name, desc, seq, ts, res}` | `_write` | `res` 记实际结果文件名 |

`_RunState` 新增 `dp_counters: Dict[str, int]`（key = agent 目录相对路径，`/` 归一化）。

## 三、详细设计

### 3.1 计数器与落盘格式改造（AI/utils/llm_callbacks.py + dataprovider_log.py）

#### 3.1.1 模块设计

- `_RunState.__init__` 增加 `self.dp_counters: Dict[str, int] = {}`；新增 `next_dp(agent_dir: str) -> int`（+1 后返回）；`reset(log_dir)` 追加 `self.dp_counters.clear()`。
- `dataprovider_log._write(name, doc, req, res)` 重写落盘部分（装饰器、`_bind_req`、`_agent_dir`、desc 提取不变）：
  - `seq = _run.next_dp(rel)`，`rel = str(agent_dir.relative_to(_run.log_dir)).replace("\\", "/")`
  - 创建 `{agent_dir}/{seq:03d}_{_sanitize(name)}/`，写 `req.json`；`isinstance(res, str)` → `res.md`，否则 `res.json`；写 `meta.json = {name, desc, seq, ts: _ts(), res: 文件名}`
  - 控制台摘要改为 `[DP] ts → rel::name::seq`
- 两个模块 docstring 的目录树同步更新，注明旧格式仅存在于历史 run、由 viewer 兼容展示。

#### 3.1.2 三方依赖能力评估

本模块不依赖外部库/API（仅 pathlib + json）。

#### 3.1.3 风险与验证方式

- 风险：`_run` 全局单例，测试需 `reset()` 隔离；Windows 路径需归一化；`_agent_dir()` 预测目录分支（LLM 调用尚未发生）与计数器交互需正确。
- 验证：`tests/utils/test_dp_log_format.py`（重复调用不覆盖、dict 结果、中文接口名、reset 归零、未初始化跳过）。

#### 3.1.4 文件变更清单

| 路径 | 改动 |
|------|------|
| `AI/utils/llm_callbacks.py` | `_RunState` 加 `dp_counters`/`next_dp`，`reset` 清空；docstring 目录树 |
| `AI/utils/dataprovider_log.py` | `_write` 改文件夹式落盘；docstring |

### 3.2 日志查看器（AI/logviewer/）

#### 3.2.1 模块设计

- `logs_reader.py`（纯函数）：`LOGS_ROOT`（环境变量 `LIVEPROFIT_LOGS_DIR` 优先，否则 `Path(__file__).resolve().parents[2] / "logs"`）；`list_runs()`（`\d{4}-\d{2}-\d{2}_\d{6}` 目录，最新在前）；`list_layers`/`list_nodes`（`\d{3}_` 前缀）；`list_dp_calls(node)` 返回 `("new"|"legacy", Path)`（目录 vs 平铺 json 文件即新旧判别，排除 meta.json/tools）；`parse_legacy(p)`；`read_json`/`read_text`（缺失/坏 JSON → None）；`list_report_files(run)`。
- `app.py`（Streamlit）：`layout="wide"`；sidebar 选 run（默认最新，`@st.cache_data(ttl=5)` 只缓存目录列表 + 刷新按钮）→ layer → 节点；主区 4 个 tab：
  1. 节点上下文：req.md/res.md 用 `st.markdown`，meta.json 用 `st.json`；缺失 → `st.info`
  2. DataProvider：每调用一个 expander（旧格式前缀"⚠️ 旧格式"），req → `st.json`，res str → `st.markdown`、dict → `st.json`；>100KB 折叠
  3. Tools：`tools/NNN_tool/` expander，req.json → `st.json`，res.txt → `st.code`
  4. 运行报告：reports/*.md → `st.markdown`，*.json → `st.json`

#### 3.2.2 三方依赖能力评估

- `streamlit>=1.40.0`（已在依赖中）：`st.tabs`/`st.expander`/`st.markdown`/`st.json`/`st.cache_data` 均为此版本稳定 API；`st.testing.v1.AppTest`（≥1.28 提供）用于冒烟测试。**无新增依赖**。

#### 3.2.3 风险与验证方式

- 风险：中断 run 缺 res.md；logs/ 根目录有 backups/、event_study_daily.log 噪音；旧格式坏 JSON。
- 验证：`tests/utils/test_logs_reader.py`（fixture 树 + monkeypatch 环境变量）；`tests/utils/test_logviewer_smoke.py`（AppTest 无异常）；真实 logs/ 下人工检查旧格式节点渲染。
