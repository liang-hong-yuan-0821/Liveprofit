## 一、背景与动机

### 1.1、现状

- `get_industry_sector_performance(days)`（Tushare tushare_provider.py:770-819 / AKShare akshare_provider.py:1051-1130）与 `get_concept_board_heat_rank(days)`（Tushare :821-965 / AKShare :1148-1220）当前只输出 N 日聚合排名：底层接口（sw_daily / stock_board_industry_hist_em / stock_board_concept_hist_em）本就返回逐日序列，但 `df.tail(days+1)` 后只取首末 close 计算聚合涨跌幅，**中间逐日数据被丢弃**。
- 板块新闻分析师 prompt（sector_news_analyst.py:44-49）明确要求判断"哪些行业在领涨/领跌？**持续多长时间了？**"，但现有数据只给区间涨幅，无法回答持续性。

### 1.2、目标

两个接口输出中追加「近 10 个交易日逐日涨跌幅」章节（保留现有聚合排名表），使分析师能判断趋势持续性。逐日表固定覆盖最近 10 个交易日（即使 days 参数 = 20）。

## 二、架构设计

不改变现有架构：不新增 Provider 方法、不新增接口函数、消费方（sector_news_analyst days=10、sector_tech_analyst days=20）调用代码零改动。新增一个共享纯函数模块（仿 limit_ladder_utils.py 先例）。

### 2.1 数据模型设计（输出契约，两 provider 一致）

章节格式：

```
## 近10个交易日逐日涨跌幅（行业×日期，列头 MM-DD）
（覆盖 08-06 ~ 08-19，共 10 个交易日；最新列 08-19（盘中）为盘中未定稿数据）

| 行业 | 08-06 | 08-07 | … | 08-19（盘中） | 近10日累计 |
|------|-------|-------|---|--------------|-----------|
| 银行 | +0.1% | -0.3% | … | +0.6% | +3.21% |
```

- 行序：行业表按聚合表原序、**不截断**（Tushare 申万一级 31 个；AKShare 为东财全行业名单约 86 个板块，含一级+二级）；概念表按热度排序 TOP30（与聚合表排名一致）。
- 单元格 `+0.1f%`（窄列）；累计列 `+0.2f%`（与现有聚合表精度一致）。
- 累计口径：
  - 行业表（close 序列）：(第10日close / 区间前一日close − 1)，days=10 时与聚合 pct 精确一致；
  - Tushare 概念热度表（dc_index 快照只有当日 pct）：累计 = 逐日 pct 复利 Π(1+pct_i)−1，caption 注明「累计列为逐日快照涨跌幅复利计算」；
  - 标题统一标注覆盖区间（起始~结束 MM-DD）。
- 盘中标注：`_is_intraday_trading_time()` 为真且最新日期 == 今日 → 列头 `MM-DD（盘中）`。
- 降级：
  - 2~9 个交易日 → 注「仅覆盖 N 个交易日」（N = 逐日表列数）+ 缺口脚注（周末不入清单；全市场缺失的工作日入清单，口径见 3.1 compute_gap_dates）；
  - <2 天 → 不渲染表格，输出一行 `> 近10日逐日涨跌幅数据不足（仅 N 天），已省略。`（`> ` blockquote 前缀为输出字面量，沿用现有「数据缺口」blockquote 惯例 tushare_provider.py:1437）。
- **门控契约不变**：整个返回仍以 `#` 开头；所有新增失败路径的返回串一律不以 `#` 开头（sector_rotation_analyst.py:146-153 的 startswith 判定）。

## 三、详细设计

### 3.1 共享纯函数模块 `AI/dataflows/providers/daily_matrix_utils.py`（新建）

#### 3.1.1 模块设计

仿 `limit_ladder_utils.py` 先例，供两个 provider 复用：

- `fmt_date_short(d) -> str`："20260819" / "2026-08-19" / datetime → "08-19"
- `daily_pct_from_closes(dates, closes) -> {date: pct}`：相邻 close 算当日涨幅（11 行 → 10 个）
- `master_dates_from_series(series_map, n=10, min_coverage=0.5) -> [date]`：优先取最长序列的最近 n 天；当该口径不满足 min_coverage 时改用「覆盖 ≥min_coverage 板块的最近 n 天」口径
- `compute_gap_dates(window_start, window_end, covered_dates) -> [date]`：**缺口口径的唯一权威定义**——窗口 = 覆盖日期并集的日历跨度 [min, max]（**不用 master_dates 本身做窗口**：master_dates 由覆盖日期生成、每个日期必有板块覆盖，差集会恒为空）；gap = 窗口内全部周一~周五 − 覆盖日期并集（周末排除；全市场缺失的工作日含节假日入清单，与采集器 skipped 语义一致）
- `format_daily_matrix(rows, master_dates, *, title, caption, intraday_date, cum_label, gap_dates) -> str|None`：master_dates<2 → None（调用方省略+附注）；**gap_dates 统一按展示窗口（master_dates 覆盖区间）过滤后再生成脚注**——行业路径结果本就 ⊆ 窗口（过滤幂等），概念路径 skipped 中的窗口外探测日期（如运行当天无数据）被剔除，保证两路径脚注口径一致

#### 3.1.2 三方依赖能力评估

本模块不依赖外部库/API（仅标准库 + pandas DataFrame 输入）。

#### 3.1.3 风险与验证方式

- 风险：日期格式差异（Tushare "YYYYMMDD" / AKShare datetime/str）→ 统一 `pd.to_datetime` 后取 MM-DD。
- 验证：纯函数单测（见测试清单）。

### 3.3 Tushare 概念热度 + 共享采集器（tushare_provider.py:821-965、1348-1438）

#### 3.3.1 模块设计

**共享采集器提取** `_collect_concept_daily_snapshots(days, today_df=None, today_date=None) -> (snapshots: {YYYYMMDD: df} 升序, skipped)`：从 `_collect_concept_daily_top_gains` Step 1 提取，语义逐字节保持（max_probe=days*3、`_DC_CONCEPT_DAILY_CACHE` 仅非当日写入、`_prune_daily_cache(cap=30)`、工作日缺口记 skipped）。`today_df/today_date`：heat_rank Step 1 已探测到的当日快照直接注入，**不重复调 API、不写缓存**。

**`get_concept_daily_top_gains` 重构**：改为消费采集器（Step 2 TOP N + 跨日上榜统计、Step 3 格式化不动）。**输出文本逐字节兼容——现有 test_concept_daily_gains.py 全部用例不改即通过（回归基线）**。

**`get_concept_board_heat_rank` 新增 Step 4**（heat_list 排序后）：`snapshots, skipped = self._collect_concept_daily_snapshots(days=10, today_df=idx_df, today_date=trade_date)`；逐日行 = 热度 TOP30，单元格 = 当日快照 `pct_change`（概念当日不存在 →「—」）；累计 = 复利。**skipped（工作日缺口日期清单）传入 `format_daily_matrix` 的 `gap_dates` 生成「数据缺口」脚注（周末不入清单，沿用采集器口径）**；skipped 与 compute_gap_dates 语义一致（全市场缺失的工作日，周末排除），实现时以同一 fixture 数据做单测互验；skipped 中的窗口外探测日期（如运行当天无数据）由 format_daily_matrix 的窗口过滤剔除，互验 fixture 须显式覆盖「今天缺数据」场景。

**API 成本**：每进程新增约 9 次历史交易日 + 约 4-5 次周末/节假日探测（共约 13-14 次 dc_index 调用，周末探测返回空表）。预热仅当同进程 sector_news 先实际调用 heat_rank 时生效（工具循环由 LLM 决定、不保证调用），届时 sector_rotation 的 top_gains 历史日命中共享缓存；未预热则 top_gains 成本与现状相同。另注意：注入的今日快照不入缓存 → top_gains 的今日探测始终 +1 次调用。
