# 全市场日线本地库（store 包）踩坑

> 一句话结论：store 六表（public schema）是旧实现，2026-09-13 已随证券市场数据库统一方案删除——统一实现为 `db/instrument/`（market schema）；本文件的写入/事务/回填约定已原样迁入 db/instrument 并继续有效。

## 历史窗口不能选未来上市股；新股ATR空值需核实暖机（2026-09-26）

- **北交所因子双码**：2025-07-25 的 `stk_factor_pro` 同日同时返回 `430017.BJ` 与 `920017.BJ`，两行原始收盘价同为22.08，但 `atr_qfq` 分别为1.1535/1.15924。按旧码全量映射会出现重键，也不能凭收盘价断定两个复权指标相等。主库使用新码时优先直接匹配新码因子行；只有新码缺席才接受对照表旧码行，并逐行校验原始收盘价。映射冲突保留缺口，不选择任意一行。
- **新股ATR暖机可跨可信停牌**：2016-06-30的601611.SH及07-07/08的300515.SZ无日线，逐日`suspend_d`有唯一S、无R/时段，独立`daily`也无行；旧暖机核验要求上市后每个交易所交易日都存在个股日线，导致07-01至11共5个源ATR空值误列失败。暖机窗口以实际有效日线根数计，并且每个跳过的交易所日都必须由独立S与日线交叉验证为全天停牌；没有证据的缺日线不能默许为暖机。2016定向重跑7日失败0。

- **表象**：2025因子回填请求到001220.SZ等2026年才上市的代码，连续收到空响应；001325.SZ等2025年底上市代码仅有10或2根日线，ATR全空又被归为上游故障。
- **根因与正确姿势**：历史证券池及缺口快照必须都加`list_date <= end`，否则当前上市状态会污染过去年份。ATR全空不得直接判缺采或暖机；[上游ATR为20日窗口](https://tushare.pro/document/2?doc_id=328)，样本实测第21根才首次非空，故只有上市日至区间末独立交易日最多20根、上游因子日期与本地日线日期逐日完全吻合时才可记为ATR暖机，其余保留失败。组合因子MA60的60日预热属于另一口径。
- **验证**：2025窗口误选代码均为2026上市；001325.SZ年内10根、001369.SZ与001396.SZ各2根。001233.SZ、001285.SZ、001386.SZ本地因子ATR首个正值均在第21根；新股预热、本地缺一天及20/21根边界在`tests/db/instrument/test_stock_factor_backfill.py`验证，31项通过。

## 历史因子只遍历现存股票与失败仍报成功（2026-09-25）

- **表象**：2016–2025全历史因子缺口超过千万证券日；旧`_stock_factor_codes`和覆盖快照只包含`list_status='L'`，因此窗口内退市股票永远不会补。首批20代码中3只2001–2004年已退市、2016年后无日线，旧清单仍请求它们并失败，CLI却以退出码0结束。
- **根因与正确姿势**：历史回填证券池包含窗口内退市股，排除窗口起点前已退市股；每票以本地日线和必需列判断断点，不能只看因子行数。部分失败必须使CLI非零退出并保留失败代码，源重试要有界。
- **验证**：`000001.SZ`上游2016/2020/2025样本均返回正值ATR；首批20代码17成功，2016/2017年因子缺口分别下降3,699/3,670。3个窗口外代码经主库退市日/日线核对后从旧失败清单移除。

## 日线存在不代表复权与量化因子完整（2026-09-25）

- **基金因子空列与整行缺采须分开（2026-09-26）**：2026年1月至9月21日已有基金日线却没有对应`factor_daily`的证券日达348,480、分布175个交易日；近三日因子行已存在，但9月24日421只基金MA250为空、42只ATR为空。后者用基金`list_date`与独立XSHG交易日历逐票验证，MA250空值均在前250交易日，ATR空值均在前20交易日；不能将这些正常源暖机算作每日更新失败，也不能仅凭本地已存日线根数认证暖机，因为本地历史本身可能缺采。新增按日缺因子行的有界回填入口，源收盘价必须与本地未复权日线一致；未知上市日仍为PARTIAL；独立日历超窗时，须追加上游逐票上市以来历史查询，代码/日期唯一/未截断/原价有效且与本地完整日期及原价逐项一致，才能按有效样本根数认证。仅本地计数或任一日期/价格不一致均不放行。验证：348,480条历史因子已补入；34项MA250空值涉及12只基金，上游分别仅249根或219根，全部与本地日期和原价一致；相关定向验证已覆盖历史缺一天仍不认证。

- **基金整日空源也必须报失败（2026-09-26）**：2026-09-22至24的股票日线/复权完整，但场内基金日线三日均为0行；原`fetch_day_frames`只拒绝股票整日空，并只检查股票日线代码是否有配对复权，股票数据正常时基金空响应可随整日成功落库。按独立交易日历重跑后基金日线分别补2147/2133/2133行，基金配对复权缺口0。现在有基金目录代码时拒绝基金整日空响应，基金日线必须逐代码匹配同日正数复权；最近交易日全基金无日线须进入有界重试并使写后质量报错。上交所2026年9月25–27日中秋休市，不能按自然日最大日期误报A股缺口；本次A股最后交易日为9月24日。`tests/db/instrument/test_frames_validation.py`和`test_incremental.py`定向33项通过，主库只读质量查询三日无缺口。

- **表象**：2026-09-22/23股票日线各有约5,500行，复权因子却整日0行；原增量只看最新日线日期便跳过三日窗口，原历史回填也以日线存在跳过。`factor_daily`旧行虽有MA，新增`atr_qfq`全空。
- **根因与正确姿势**：不同事实表必须各自按证券和日期验收，不能以任一表的最大日期或行存在作共同水位。增量重拉最近三日并扫描已有股票日线的复权缺口；单日源帧检查日期、重复键、正数因子和股票日线代码对应复权；持久层再查日线/复权/可信状态，异常返回非零任务状态。历史技术因子另按必需列回填；源不可用时保留缺口。2026-09-25真实库定向修复后，已有股票日线对应复权缺口0；76项相关定向测试通过。

## 位置与表（2026-08-30，已迁移）

- 原 `AI/dataflows/store/` 六表（public schema）已删；新落点 `db/instrument/`（market schema）：instrument_daily / adj_factor / sector / sector_member 等 11 表。写入工具在 `db/instrument/dao/_common.py`、采集在 `db/instrument/ingest/`。

## 分类约定（已废弃）

- 原 `stock_daily` / `adj_factor` 靠 `is_fund_ts_code()` 前缀函数分类——前缀函数已退役：统一显式列 `instrument.instrument_type`（index/stock/fund，源表即类型）；横截面分类过滤走 EXISTS 子查询按 instrument_type 过滤（db/instrument/dao/instrument_daily.py get_cross_section）。

## 写入约定

- 批量写入 COPY → 临时表（表名带 pid+随机后缀）→ `INSERT ... ON CONFLICT`；清洗顺序 close NaN 行显式 drop（close 列 NOT NULL）→ 其余 NaN→None（**必须先转 object dtype**——float64 列上 `where(cond, None)` 会把 None 压回 NaN）；幂等策略由调用方控制（决策 5）：回填 `DO NOTHING`、增量最近 3 交易日 `DO UPDATE`（覆盖 tushare 日终修正）。

## 实测踩坑（2026-08-30 集成验证）

1. **`CREATE TEMP TABLE (LIKE 表)` 默认不复制 DEFAULT 表达式** → 带 `DEFAULT now()` 的 NOT NULL 列（updated_at）在 COPY 时被填 NULL 违例；必须写 `LIKE ... INCLUDING DEFAULTS`。
2. **pandas `Series.apply` 的 dtype 推断不可靠**：单行且结果均匀时推 int64、多行含 None 时把 int 整体压回 float64（单测会骗过）——整数列转换（如 concept.count，tushare 返回 float 300.0）必须用显式 `dtype=object` 的列表推导，否则 COPY 报 `invalid input syntax for type integer`。
3. **批量写入的 SQL 级失败会使事务 abort**，下一段 DB 写入报 "current transaction is aborted"——按来源/批次隔离的采集循环中，每段失败分支必须 rollback 恢复干净状态，且**成功段必须独立 commit**（否则后段失败的回滚把前段成果一并清空，实测 dc 失败清空 ths 899 概念）。
4. **概念成分响应含重复 con_code** 时，同一 INSERT 批次提出两行相同 PK 会报 `ON CONFLICT DO UPDATE cannot affect row a second time`——Provider 归一化与 DAO 双保险 drop_duplicates。

## 事务约定

- 单日提交（库内无"半截日"）；概念采集按来源独立提交、基本信息刷新独立提交（逐日失败 rollback 不得静默丢弃 35 分钟概念采集）；commit 失败（事务可能已 abort）需 rollback 恢复干净状态再继续。

## 回填与增量（入口已迁）

- 回填：`python -m db.instrument.ingest.backfill [--start 2016-01-01] [--end 今天] [--retry-missing] [--skip-concepts]`；普通断点续跑按库内已入库交易日集合跳过，但这只能作性能优化，**不能证明复权与因子完整**；修复已有日线日期使用显式`force_existing_days`。禁止以`max(trade_date)`截断；`--skip-concepts`可在板块数据新鲜时跳过重采；失败清单`logs/stock_backfill_failures.json`原子写入。

## 已写因子行不能掩盖未认证指标（2026-09-26）

- 表象：按日回填首次写入PARTIAL记录，第二次只查因子整行不存在而跳过，报告错误归零；按证券入口则日期/原价匹配即可SUCCESS。
- 正确姿势：两个入口共用必需指标与暖机认证，待补选择持续检查空列；额外逐票历史请求在规划、采集、复核之间共享明确预算和缓存，预算用尽不认证、不清pending。基金已有日线缺复权也须与股票一起进入有界增量修复，不能仅检查最近三日。
- 验证：隔离库旧日基金复权缺失入队、补复权后出队；单测验证已写PARTIAL仍在待补、已证日历暖机出队、共享预算不超限。2026全期只读复核上游历史请求36次、未认证日期0。

## 日因子源缺首日行与历史不足（2026-09-26）

- 表象：2026年五只新股上市首日stk_factor_pro按日和按代码均无行，旧日回填只对“有行但ATR为空”运行暖机核验，使五日一直PARTIAL。
- 正确姿势：源缺个别代码也进入独立暖机核验（上市日期、交易日历、实际最多20根日线、缺日必须有独立停牌证明）；通过时只标历史不足，不生成因子行，不声称源数据已补齐。老股或未证明缺日仍缺采，整个市场空源仍失败。
- 验证：五只list_date与首根日线日期一致，15项纯Mock及独立review PASS。2026年暖机复核无超窗ATR/MA60缺口且无未证明无日线日期。

## 股票同码因子也须核对源价格（2026-09-26）

- 表象：历史日因子回填只给BSE旧码映射做close对照，同代码来源未执行该检查。
- 正确姿势：同码和别名都在写前核源close为有限正值并与本库日线匹配；缺列、错误代码日期、价格不一致均拒绝。旧记录未保存源close时不得声称已完成来源价格验证。
- 验证：本次2026批次952,580行源close全部有效且与日线一致；价格拒绝反例、别名优先级测试及独立review通过。
