# Tushare 代理端点与数据接口坑

> 一句话结论：日线消费必须先 `_sort_asc_by_trade_date` 升序归一（端点返回降序）；全市场拉取禁区间查询（静默截断）；因子取自 idx_factor_pro/stk_factor_pro（禁自算）；代理端点能力必须实测。

## 复权因子可存在于无日线停牌日（2026-09-26）

- **表象**：2015年两只新股`300456.SZ`/`300466.SZ`的`adj_factor`比`daily`多199个日期；定向历史窗口脚本按日期集合相等校验时中止，未写入。
- **根因与正确姿势**：上游在全天停牌日延续复权因子，因子存在并不证明当日有交易日线。按代码和日期与真实日线交集写入可交易价格配对因子；独有因子日期只作待查线索，须以独立`suspend_d`及无日线验证停牌，不能补造价格。
- **验证**：32只2015年上市新股写421根日线及配对因子；199个独有因子日期均由两只股票的全天S覆盖，2016年暖机核验的前置未核实交易日降为0。此为定向历史窗口，不代表2015全市场完整。

## ETF当前`etf_type`不能判定回转规则（2026-09-26）

- **表象**：`etf_basic`对510300.SH、510500.SH、159915.SZ、511010.SH、518880.SH五只均返回“纯境内”；后三类中的国债、黄金与股票ETF无法由该字段区分T+0/T+1。
- **正确姿势**：把`etf_type`仅当境内/跨境粗分类；按证券、标的、历史交易所公告与生效日确定股票/债券/黄金规则，2026年目录只当2026年观察，不倒填历史。无逐证券历史规则时研究资格保留未知。
- **验证**：2026-09-26实源五只代码及`index_code`核对，ETF历史规则证据索引见任务附件。

## 北交所开市前旧码事件误挡全市场状态（2026-09-26）

- **表象**：2018年逐日状态补采243日中145日UNAVAILABLE，独立停牌源从2018-05-09开始连续5日不可用；原误判为ST历史源空。逐端点重查2018-05-09、06-01、12-06发现`stock_st`各有82–89条，限价、日线和停牌端点也均有当日数据；但`suspend_d`混入833994.BJ等北交所开市前的旧码。
- **根因**：`get_full_market_trade_status_df`和`get_verified_full_day_suspensions_df`将所有旧`.BJ`停牌事件送入2021年后代码映射，遇到一只无映射就返回`None`，连当日沪深股票有效数据一起丢弃。
- **正确姿势与验证**：先按2021-11-15北交所开市边界排除开市前`.BJ`事件；开市后逐码核身份，已映射代码转换，仍在当日股票池中的转板旧码保留原身份，未知身份不得产生否定停牌结论。实源2018-05-09/06-01/12-06复合状态恢复3511/3515/3561行，5月9/15独立停牌候选恢复232/216行；定向测试通过。异常接口须逐端点检查，不能只见复合状态`None`就归因ST空源。

## 北交所转板旧码没有920映射（2026-09-26）

- **表象**：2021年独立停牌源从北交所开市日11月15日起连续5日`UNAVAILABLE`，年度批次熔断；同期301089.SZ停牌5日无法为上市初期ATR暖机提供完整证据。
- **根因**：`suspend_d`含832317.BJ、833994.BJ、833874.BJ三只申请转往沪深交易所的旧码；它们没有920新码，原逻辑要求所有旧码都在`bse_mapping`，使当日全部沪深及北交所停牌数据返回`None`。
- **正确姿势与验证**：映射表中存在的旧码按一一对应关系换码；无映射的旧码在状态提供器须存在于当日活跃股票目录，在独立停牌入库层须通过`market.instrument`当日资格检查。否则留未知。修复后2021-11-15至12-31的35个交易日停牌源全部成功，三只转板旧码各获35日全天停牌证据，301089.SZ和001317.SZ的5日停牌也恢复；对应Provider回归测试通过。

## 历史名称查询有截断、重复和区间空洞（2026-09-26）

- **BaoStock替代源点测**：[BaoStock官方PyPI接口样例](https://pypi.org/project/baostock/)列出历史日线`tradestatus/isST`；本环境`query_history_k_data_plus(..., frequency='d', adjustflag='3')`返回这两个字段，停牌的`600074.SH`在2019-12-30至2020-01-07仍有`tradestatus=0,isST=1`，可补Tushare完整状态之外的独立逐票证据。**禁止**把`query_all_stock(day)`的`code_name`当历史名称：2023-01-03对已观测Tushare状态比较有324处不一致，`688622.SH`返回今天的`*ST禾信`而同日历史K线`isST=0`，`688309.SH`今日名不带ST但同日历史K线`isST=1`。BaoStock历史K线字段须逐票批量核覆盖、与非空Tushare日交叉核对后才能入库；历史名单查询只能作代码池线索。
- **2016全年核验**：3,035只沪深股票的704,145个有效证券日全部有BaoStock历史`isST`，与已有Tushare完整状态262,739行的ST布尔值差异0。`tradestatus`不能单独裁决全天停牌：`600656.SH`2016-05-12报1但成交量/额空且价格平，Tushare独立S+无日线证实全天停牌。2016年Bao报未交易的62,598证券日均无Tushare日线，可在同日完整日线响应为空、无R/S-R未定时冲突且批次全量认证后作为独立交叉证据；Bao报交易的正值不能覆盖可信停牌。
- **双源入库边界**：Bao历史`isST`按全年独立日历与当日有效股票池校验完整性，再逐票与已有Tushare状态交叉核验；仅VERIFIED批次的无冲突证券日可补完整状态的ST字段。2020年951,986条和2021年1,062,370条虽全年全覆盖，分别有2/1条与Tushare ST值分歧；原始双方值逐项存`stock_st_source_conflict`，完整日输入显式携带逐证券`st_conflict`，只排除冲突证券，不因少数冲突丢弃同日其余已核验股票。后续同年份重采若与已有VERIFIED批次的ST值冲突，仍拒绝切换版本。复合状态`source=tushare+baostock`显式记录混合来源，下游审计、补采和研究覆盖须同口径识别。2016-01-04最初写2,806条，`000033.SZ`和`600656.SH`当日无Tushare行情/S事件，事后公告不能偷渡进当日研究状态；交叉确认Bao未交易与独立日线为空后，才能另行补足全天无交易事实。

- **ST变更事件补充实测**：官方[`st`接口](https://tushare.pro/document/2?doc_id=423)可按`imp_date`取风险警示变更；本环境对`20190401`返回1条`600321.SH`从*ST转ST，对`20190402`返回2条撤销*ST，与相邻`stock_st`名单91→89的数量关系吻合。但同一个`st`请求偶发“没有接口访问权限”，再次请求可成功；`stock_st`空源日连续重试3次仍空。事件只能作为待核的历史重建证据，必须核完整性、实施日期、名称及双侧名单，不能把空事件或偶发鉴权失败推成全市场非ST。
- **双侧桥接反例**：2019四个孤立空源日的`st`事件桥接虽与后一正常日名单精确吻合，2020-01-02却差`600074.SH`一只，且该股至2020-06-02才退市。逐票`namechange`仍显示2018-05-03至2020-04-09为`*ST保千`，跨年无日线；相邻`stock_st`名单可能改变了长停牌股票纳入范围。相邻数量吻合不能替代逐代码比较；即使逐代码吻合也不证明事件源无同日遗漏。2021两个抽样空源日桥接吻合，仍不宜生成全市场阴性。

- **表象**：2016年初与2020-01-02的`stock_st`及`bak_basic`都为空；代理全市场`namechange`无论指定2016或2025公告范围都返回恰好10,000行、跨2006–2026，日期过滤不生效。逐票`600725.SH`有同一名称区间重复两行，`000001.SZ`在2006-10-09至2007-06-19间没有名称区间。
- **正确姿势**：历史名称只能逐票取、去重并验区间连续性、代码和公告/生效日期；在非空`stock_st`日期交叉核对。单票`*ST`区间可构成阳性线索，区间空洞或全市场截断不能推出阴性，也不能填造整日非ST。官方[namechange文档](https://tushare.pro/document/2?doc_id=100)只定义接口，代理实际能力以此实测为准。
- **新增实测**：2019-04-01、10-24、11-04、11-28的`stock_st`与`bak_basic`均为空，但`daily`、`stk_limit`、`suspend_d`非空。复合状态在这些日期应保持UNAVAILABLE；四日的ST名单不能由空源推断全市场阴性。
- **2020逐日扩展**：2020全年状态补采12日UNAVAILABLE（1月2日、2月20/25日、3月16日、4月23日、6月18日、7月8/20日、8月3/4/24日、11月20日）；原始`stock_st`与`bak_basic`在12日均0行，但主库股票日线各有3,796–4,138行。逐日证据见任务附件`historical_st_upstream_probe_2020.json`，仍按未知保留，不能借相邻日期填阴性。
- **2021逐日扩展**：2021-01-29和03-16两个状态不可用日的`stock_st`与`bak_basic`原始响应均0行，同日本地股票日线5,003/5,111行。逐日证据见任务附件`historical_st_upstream_probe_2021.json`；空名单不能解释为全市场非ST。
- **公告目录能力边界**：官方`anns_d`文档写明可按代码/日期返回公告PDF URL且需单独权限；本环境代理对有已知原公告的`300362.SZ` 2020-05-08至12日、`600701.SH` 2020-05-20至25日及`600485.SH` 2020-05-01至16日查询均0行。无法据此判断是权限还是代理历史缺失，也不能把空公告查询当作无停牌公告；这些原件须从交易所/公司公告网站另核。

## 长停牌期间代理缺S与北交所旧代码公告（2026-09-26）

- **代码身份补充实测**：2025-04-30 的 `suspend_d` 用 `835305.BJ` 标注停牌，`daily`/`stk_limit` 和主库目录用 `920305.BJ`；2025-06-16 的 `suspend_d` 与 `stock_st` 用 `839680.BJ`，同日行情用 `920680.BJ`。逐日状态采集必须先用经一一对应校验的 `bse_mapping` 翻译事件和 ST 名单，再与现行代码池合并。`stk_limit` 同时带 43 个不属于对照表的 `900xxx.BJ` 旧行，不能要求整个限价源都能映射。映射缺失或映射后 ST 重键时保持未知。实源复核 2025-04-30 的 `920305.BJ` 转为可信全天停牌，避免误报缺日线。

- **表象**：2025-05-26至06-09的920808.BJ无日线，代理逐日`suspend_d`也无该股S；920680.BJ在2025-04-30、06-16、06-27、06-30同样缺行情与S，状态采集只保留这些证券日未知。公告使用旧代码872808/839680，当前目录和审计使用920808/920680。
- **根因与正确姿势**：代理停复牌事件不保证覆盖整个连续停牌区间；不能把“无日线、无S”一律判漏采，也不能从空S单独推定全天停牌。逐票重查行情，核对[北交所代码对照](https://www.bse.cn/service/code_mapping.html)，引入公司/交易所公告的原始URL、发布日期、适用日期及范围。后出复牌公告只能在其公布后作为历史as-of证据，不得回填成当日已知。
- **验证**：2025年二季度14个证券日经公司/交易所PDF证实并落`market.suspension_evidence`；2025年上半年审计的未解释缺日线余1，完整状态仍缺16，未对空白状态猜值。

## 历史状态局部缺证据不应拖垮整日（2026-09-25）

- **状态复合事实与独立停牌事实分离（2026-09-26）**：2016年初`stock_st`空，不能写`trade_status_daily.is_st=false`，但2016-06-30的`601611.SH`仍可凭同日唯一无时段S、无R及独立`daily`空核实全天停牌。独立源观察写`market.suspension_source_daily`并按日重新验证/撤销；只用于事后行情缺口分类，不能冒充完整ST状态或原始公告的当日可得时间。

- **表象**：2017-01-03有5只股票既无当日`daily`也无可信S事件，旧 `get_full_market_trade_status_df` 因此返回`None`，使其余3,031只股票的ST、板块与停牌状态无法入库。2016年首5日及2020-01-02的`stock_st`返回空，这与少数代码缺行情是不同缺口。
- **根因与正确姿势**：全局源帧有效、历史ST名单非空后，把没有日线且没有S事件的代码单列未知，其余代码照常写入；缺`stk_limit`价格可保留空值，但不得据此推断可成交。没有可信ST名单时整日拒绝，不把空名单解释为全市场非ST。补采排序先处理完全未采日期，避免局部未知日期重复占满批次。
- **验证**：2017-01-03入库3,031条，5只未知；2025年首5交易日全量成功，2016年首5日仍保持未知；相关定向测试通过。

## 当前北交所代码的早期上市日期不可直接用作历史交易所资格（2026-09-25）

- **表象**：主库71只`.BJ`代码的`list_date`早于2021-11-15开市，`920000.BJ`样例为2020-12-23；2021-01-04按当前目录构池出现约49只无历史涨跌停价的北交所代码。
- **根因与正确姿势**：北交所[新旧代码对照表](https://www.bse.cn/service/code_mapping.html)明确注明，原精选层平移公司的“上市日期”是原精选层挂牌日期，不能证明该代码在北交所已上市；历史证券池、交易规则与研究准入需另取交易所上市时点证据，不得靠当前后缀或首根日线反推完整历史池。北交所官方确认2021-11-15开市，已作为不可早于的下界。
- **验证**：主库只读聚合71只早于开市，代理2017/2019/2021逐日源点测；历史研究继续标证据不足。
- **2021暖机补充**：920089/920092/920680/920720/920981.BJ的主库日线在北交所开市或其目录上市日前已有记录，是现代码的历史回溯序列；技术指标暖机按当日可进入股票池的有效日期起计算，不能把这些前置日线误计为已上市交易根数。年度核验脚本已按`max(list_date,2021-11-15)`过滤并将回溯代码单列；2021因子余28,733条重算仍在暖机窗口内。

## 历史 stk_limit 原始行数大于当日上市池（2026-09-25）

- **表象**：2026-08-26～28各有3/3/4只股票无日线且无状态；原始 `stk_limit` 分别返回7,760/7,764/7,768行，旧代码按 `>=6000` 拒绝整日状态。
- **根因与正确姿势**：原始结果含非当日上市证券；行数超过6,000不代表当日上市池被截断。先用历史上市/退市日期建立当日池，校验每只股票有 `stk_limit` 行或同日可信 `suspend_d` 的S事件，再只保留当日池的限价。若覆盖不足仍拒绝；不得把缺日线直接当漏采或合成价格。
- **验证**：三日当日池5,550/5,550/5,551，活跃证券的限价均被覆盖；十个缺日线证券日同日 `daily` 为0且 `suspend_d` 全为S。状态入库后逐日质量缺口0，38项相关测试通过。

## 旧停牌状态误标与日内停牌（2026-09-25）

- **2016五只历史盘中停牌实证（2026-09-26）**：000159.SZ 2月22日、000510.SZ 3月16日、000533.SZ 3月25日、000659.SZ 8月18日、000711.SZ 10月19日均有真实日线和同日单条S，但代理`suspend_timing`为空。逐只公司原始公告分别明确上午盘中、盘中、下午起、盘中即时、下午盘中临时停牌；原件与次日/随后公开日见任务附件`suspension_evidence_2016_intraday_five.json`。不能因S且有日线就报日线异常，也不能虚构具体分钟时段；后发公告需按`published_on`门控历史研究。

- **新边界**：官方`suspend_d`的`suspend_timing`字段在本项目代理可用，显式请求后11笔“有日线且同日S/R”均返回S的盘中时段，旧查询未请求字段才曾误称其时段未知；7笔“无日线且同日S/R”仍为空。必须持久化范围与原始时段，不能只存`is_suspended`。空时段仍**不等于全天**：603056.SH于2026-01-09有真实日线，代理S/R时段皆空，但[公司公告](https://static.cninfo.com.cn/finalpage/2026-01-14/1224932970.PDF)明确当日午间起停牌。反向审计须逐证券交叉日线，并为公告留独立证据模型。
- **秒级时段补充实测**：2022年5只北交所上市首日有日线且同日R+S，`suspend_timing`为`09:59:32-10:09:32`等秒级区间，旧解析只收`HH:MM-HH:MM`，导致全年有日线状态缺5条。支持分钟/秒混合精度并校验秒值、正时长、多个区间先后无重叠后，5条均定向入库`intraday`；不能把S+日线误称全天停牌或缺行情。35项Provider状态测试通过，2022年最终有日线状态缺0。

- **表象**：主库2026-09-17/18各有608/607条`is_suspended=true`，其中596/595条有真实日线；研究者若只看布尔值会误以为这些日线异常。
- **根因与处理**：两天旧状态写于9月21/22，当前按`trade_date`重新读取代理仅有13/14个S事件。用现行经校验的状态采集器重写两天各5,565条后，S数降为13/14，带日线S数降为1/2。全库仍有30个“有日线且S”的证券日，逐项重查上游全部具有非空`suspend_timing`，是日内停牌，不应被解释为全天无行情；现有日级`is_suspended`表示存在停牌事件，执行约束对该日保守阻断。源没有持久保存日内时段，精细盘中可交易性仍缺。
- **防复发**：历史审计新增单日“停牌且有日线”超过50证券的异常门禁，防止类似批量误标静默通过；少量日内停牌仍需按源时段人工或结构化复核。

## 端点子日志（2026-08-25 引入）

- `wrap_tushare_api(api)`（dataprovider_log.py）在 `_connect`/trading_calendar 建 api 后包装 `query`，端点调用落在当前 DP 调用目录的 `tushare/{seq:03d}_{api_name}/`（req/res/meta.json，viewer 在 dataprovider 展开内嵌套展示）；仅 tushare 数据源 + run 内有 DP 上下文时落盘，`LIVEPROFIT_TUSHARE_LOG=0` 可关闭。
- **坑 1**：tushare DataApi 的 `__getattr__` 对任意未知属性返回 `partial(self.query, name)`（truthy）→ 包装器幂等/探测标志判定必须查实例 `__dict__`，`getattr` 会误判"已包装"导致完全不落盘。
- **坑 2**：ThreadPoolExecutor 不自动传播 contextvars（Py3.12 实测）→ `_run_with_timeout` 已用 `contextvars.copy_context()` + `ctx.run` 显式带入；任何新增"在 worker 线程内读 contextvar"的代码必须同样显式复制，勿假设自动传播。
- 端点调用超时（`_api_call` 返回 None）后 worker 仍会补写日志（上下文已复制），「DP res 显示超时、tushare 展开却有成功记录」并存属预期诊断行为。
- `_connect` 的连通性探测调用（stock_basic limit=1）在 DP 上下文内会被记录，meta 带 `probe=true`（viewer 显示「🔌 连通性探测」角标）。
- 单次结果 records 超 500 行截断（`truncated=true` + `row_count` 元数据）。

## Future 超时后迟到的本机网络拒绝（2026-09-24）

- **表象**：`_api_call()` 已因 `FutureTimeout` 返回 `None`，但请求线程仍在运行；线程稍后才抛 Windows `WinError 10013`。只在调用线程的 `Future.result()` 异常分支识别，会永远漏掉迟到异常，后续采集可能把本机策略拒绝当作普通上游空结果。
- **根因**：`ThreadPoolExecutor.shutdown(wait=False)` 不取消运行中的 I/O；Future 超时只代表等待方停止等待，不代表底层请求已经结束。
- **正确姿势**：在传给 worker 的调用包装层中捕获并保留特殊网络拒绝，再重新抛出给 Future；调用线程超时后返回仍遵守 Provider 契约，但迟到异常会锁存供采集边界与后续请求识别。保留状态需线程安全、幂等，不能把所有异常都升级成本机网络错误。
- **代码与验证**：`AI/dataflows/providers/cn/tushare.py::_run_with_timeout`、`TushareProvider._remember_network_access_error`；`tests/dataflows/providers/test_tushare_store_methods.py::test_network_permission_error_is_retained_if_worker_fails_after_timeout` 用 Event 控制真实后台线程先超时、再抛 WinError 10013，验证 typed error 留存且后续调用不再碰源。
