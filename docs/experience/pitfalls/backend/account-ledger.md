# 已发生账户事实不能被本地余额门禁丢弃

> 真实成交或外部资金流先作为不可变事实保留；本地账本余额异常应显式诊断并阻止新增风险，不得以拒绝入账掩盖差异。

## 本地登记时间不能当历史可见时间（2026-09-30）

- **表象**：迟到更正/撤销与原成交生效在同一历史日，单一`as_of`同时筛生效和登记会让“今天已知的历史余额”仍显示旧成交；直接用较晚登记事件补历史研究又会产生穿越。
- **根因**：业务生效时间、数据库行登记时间、事务提交可见时间和券商上游发布时间不是同一事实。
- **正确姿势**：诊断重放显式分`effective_as_of`和`recorded_as_of`，持久读取先核基线在两个截止上已存在；改期更正替代错记的旧日期事实。`recorded_at`只能表示本地登记事件，不能单独授研究as-of或生产账户认证。
- **验证**：纯账本9项与隔离PG定向1项通过，独立Code Review PASS；真正提交/上游可见性仍需独立证据。

## 外部资金流净额不能证明逐笔完整（2026-09-30）

- **表象**：单位化收益仅核期末减期初累计流，漏掉等额入金与出金仍能返回已知收益；同刻两笔流可重复使用同一流前现金。
- **根因**：累计净额会抵消事件，流前市值也不是仅靠累计流可证明连续的事实。
- **正确姿势**：要求账本期间完整有效资金流事件ID有序清单逐笔对账，缺清单或同刻流调换顺序保持未知；同一生效时刻连续流核前一笔金额后的现金、持仓及价格。市值和清单本身仍须独立来源认证。
- **验证**：`test_account_valuation.py`覆盖抵消遗漏、同刻两笔及逆序，9项纯测通过；独立R1两major修后delta PASS，顺序门禁另经delta PASS。

## 审核签名只绑定自报摘要（2026-09-30）

- **后续发现**：原成交报告本身也只在写入时算摘要，复核读取只比存储值；直接SQL插入业务字段与自报摘要不一致的报告仍可被正确签名。现让报告写入及复核记录/读取共用规范摘要并在读取时重算，隔离SQL伪摘要反例被拒（`test_fill_reviews.py` 3 passed，独立复核PASS）。这仍不证明券商账户归属与原件真伪。

- **表象**：0041初版复核对0036声明的`payload_sha256`签名，但不重算声明字段；直接SQL可插入字段与自报摘要不一致的不可变声明，持钥人签名后仍会通过读取验签。
- **根因**：把数据库里的摘要字段当作对字段内容的证明；仅有摘要格式约束和不可变触发器不能证实初始行的摘要正确。
- **正确姿势**：声明写入和审核读取共用同一规范序列化，读取时用源报告、替代报告及声明全部字段重算摘要，再验签并重读原件字节。签名用途按原成交与撤销/更正分域，避免跨用途重放。
- **验证**：`test_fill_resolution_reviews.py`用直接SQL伪摘要反例；相关隔离PG16项、独立R1 major修复后delta PASS。签名仍不证明券商原件与账户归属。

## 局部成交反转遗留生命周期锚点（2026-09-30）

- **表象**：0043初版撤原首笔BUY并写替代成交后，现金、持仓和订单更新，`PositionLifecycleState.initial_fill_id/initial_fill_price`及风险容量、目标、止盈、高水位仍引用原成交。
- **根因**：生命周期由首笔成交初始化，新的确认路径见已有active lifecycle便早退；只逆运算现金/持仓和平均成本不能重建状态机历史。
- **正确姿势**：完整逐事件生命周期重放落地前，在任何账本/生产投影修改前拒生命周期关联成交的撤销或更正，原报告及修订声明继续保留作诊断。
- **验证**：`test_fill_posting_stage.py`隔离库中注入已关联订单反例，13项通过；独立CR R1 major修复后delta PASS。真实已持久化`initial_fill_id`样本及完整重放仍是后续门禁。

## 超范围成交被严格重放拒绝（2026-09-30）

- **表象**：初版`AccountLedgerStore.append_trade`调用严格`replay_account_balance`，超本地基线买入使现金为负、超持仓卖出使数量为负时抛错，已报告事实无法持久保存。
- **根因**：把规划/输入认证的“不能批准此订单”与对账的“已发生交易须照实入账”混成同一门禁。基线可能滞后，且实际成交可能偏离建议。
- **正确姿势**：纯重放默认保留严格模式供输入校验；诊断账本写入和回读使用容错模式，保留有来源引用、明确费用的事实，输出`NEGATIVE_CASH`/`NEGATIVE_HOLDING`并让后续风险准入拒绝未解决偏离。不能把自声明来源或诊断余额提升为券商认证的可卖量。
- **验证**：`test_account_ledger_store.py`覆盖超额取款、超额买入、超持仓卖出，5项隔离PG、相关账户组27项通过；独立Code Review R1发现此缺口，R2修复核验PASS。当前还未接真实`OrderFillEvent`同事务写入与生产风险阻断，属于后续T4门禁。
