# 证券交易规则不能用普通股票默认值覆盖全部品种

交易数量、价格tick和可卖日需要证券身份、执行日期和规则来源共同确定；规则字段齐全不等于来源已经认证。

## 普通100股整手覆盖科创逐股规则（2026-09-29）

- **表象**：`position_planner.py`和`execution_constraints.py`按固定100股取整；研究开盘代理最初也直接接`lot_size=100`，无法表达科创板最低200股、其后可逐股递增。ETF虽然有100份交易单位，股票ETF与部分债券/黄金/跨境/货币ETF的T+0/T+1不同。
- **根因**：把股票或ETF类型当成完整交易规则，没有证券/板块/有效期/来源版本；当前规则还可能被误用于历史日期。
- **正确姿势**：`InstrumentTradingRule`显式证券、有效期、日期级发布日期、来源引用、tick、最低/递增/最高买入量与回转日。按证券及执行日唯一解析；日期级同T日发布无法证明收盘前可得，保守拒绝；开盘代理再以CN日历核T及下一开市日。普通100股与科创200+逐股、休市T/跳日、缺/重叠/晚发布规则的33项纯测和独立Code Review PASS。0025又分表保存原文字节与逐证券解释，读取重算hash、保留冲突来源；4项隔离PG及独立Code Review PASS。来源URI/发布日期仍由调用方声明，尚无官方原件认证或生产规划器接线，不能据此放行真实BUY或历史收益。
- **后续验收**：共享BUY规划器显式规则路径对价格tick及全部容量/费用缩量统一使用规则格点；min=200、step=10、max=235且220股毛额可付但费用后不足时，最终降至210股的反例通过。直接规划时行情日必须等于估值日。69项定向纯测和独立delta复核PASS；真实BUY入口尚未传认证规则，不能用此算术验收代替生产准入。

## 抓取官方原件后不能丢掉采集事实（2026-09-29）

- **表象**：只将HTTPS抓到的原文字节/最终URI写入0025来源表，会和手填相同URL/字节的诊断记录完全同形；请求URI、抓取时刻和每次重采事件消失。
- **根因**：来源原件与本地采集事件属于不同审计事实，仅用原件表无法说明取得路径；更不能用本地`recorded_at`推断官方发布时间。
- **正确姿势**：0026追加不可变采集事件，FK原件并保留请求/最终URI、原文hash、本机抓取和DB记录时刻；同一原件重抓各留一事件，读取时重核原文hash和URI。采集器逐跳及最终核官方HTTPS域，限制响应大小并处理`IncompleteRead`。16项离线、5项隔离PG测试及独立Code Review PASS；事件只证明本次本地抓取，发布日期和逐证券规则解释仍需独立审核。

## 日期和数值预检要与数据库类型一致（2026-09-29）

- **表象**：初版持久化只预检最高数量和步长是否超PG int4，漏了最低数量；用Decimal原始指数核`numeric(18,8)`精度会把`0.010000000`误拒。集成测试共享模块级数据库，第二用例还误将第一用例相同证券的记录计入本用例来源数量。
- **根因**：存储前预检未覆盖全部同类型字段，十进制表示精度与实际数值精度混淆；模块级库不会逐用例清空。
- **正确姿势**：最低/递增/最高买入量都核int4边界，tick先`normalize()`再判断小数位；同模块集成用例使用独立证券身份或显式清理。隔离PG回读尾随零tick、超界最低量及完整37项定向回归通过。
- **官方依据**：[上交所科创板交易说明](https://edu.sse.com.cn/tib/qa/c/4866268.shtml)、[上交所ETF回转交易问答](https://www.sse.com.cn/assortment/fund/etf/question/c/c_20240118_5734755.shtml)。这些页面的发布日期和覆盖范围须按历史执行日另行核验，不能反推此前规则。
