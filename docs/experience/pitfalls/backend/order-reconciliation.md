# 在途订单不能由内部目标变更视作已撤

券商在途或部分成交订单的剩余数量继续占用现金/可卖量；只有可信终态回执和账本对账能释放预留。

## 无意图首仓分批成交不能只推进数量（2026-10-01）

- **表象**：首仓目标200，原单两笔各100成交后持仓已200，生命周期仍ENTRY_PENDING；归档政策且保留来源时第二笔还会被初始化路径的PUBLISHED检查拒绝。
- **根因**：后续阶段转换只在intent_id非空分支，普通首仓没有意图；既有生命周期续填仍经过新首填政策门禁。
- **正确姿势**：以未修订首CONFIRM的原order证明身份，按有效成交累计与冻结初仓目标核对；足额与本次成交共用一次版本推进，其他订单持仓不能作证，后继目标/对账不能覆盖。ARCHIVED仅豁免同一原单及同冻结策略/政策的续填，新首填/新订单继续拒绝；两种来源是否保留均要验。
- **验证**：`test_initial_entry_completion.py`27项隔离PG通过（含幂等、版本步、有效更正量、错锚、新订单及源版本变更拒绝），已有成交/首填定向5项通过，独立R2 Code Review PASS。完整生命周期历史及来源认证仍未完成。

## 成交修订不能重开旧意图或重置待对账（2026-09-30）

- **表象**：部分成交撤销后累计量归零，订单由`_apply_delta`回到`PROPOSED`，可经通用状态取消释放预留；旧订单已满、旧意图`COMPLETED`且后继意图`ACTIVE`时，迟报更正会把旧意图重开，撞活动意图唯一索引，真实修订回滚。
- **根因**：用当前累计成交量推断券商是否接触订单，并把旧成交修订当作旧意图重新执行；两者都丢失事件历史。
- **正确姿势**：成交修订后原单保留`RECONCILIATION_REQUIRED`；有后继活动意图时保持旧历史终态，后继意图和关联活动单共同转待对账。组合锁下同事务写现金/持仓及隔离状态，可信终态前继续保留预留。
- **验证**：生命周期隔离PG71项、T4 stage14项通过；独立系统审查R1三major修后delta PASS。外部券商终态仍未认证。

## 成交幂等键不能只按字符串早退（2026-09-30）

- **表象**：`confirm_fill/correct_fill/void_fill`按全局`idempotency_key`直接返回已有事件，跨订单、跨操作或不同数量复用会返回无关成交并报告成功。
- **根因**：唯一键只防重复写入，不证明这次请求与原请求相同。
- **正确姿势**：初查与并发唯一冲突回滚后的重读均核操作类型、订单/原成交、数量/价格/日期、来源和备注；同键异内容抛明确冲突。
- **验证**：跨订单、跨操作及数量变化反例；生命周期隔离PG71项、独立delta CR PASS。

## 表象（2026-09-29）

`LifecycleOrderService.set_order_status`原允许把`EXECUTING`、`PARTIALLY_FILLED`或`RECONCILIATION_REQUIRED`经通用PATCH直接标为`CANCELLED/REJECTED/SUPERSEDED`。`PositionLifecycleManager._materialize_delta`在目标归位、反向或同向超目标时又可把`PARTIALLY_FILLED`自动置`SUPERSEDED`，而反向`EXECUTING`与新单可并行。这些状态变化让`planning_account`不再计算旧单剩余预留，实际券商却可能继续成交。

## 根因与正确姿势

内部目标意图、建议单状态、券商真实订单是三种事实。状态接口没有券商终态回执，就不能据调用方声明释放在途预留。安全的内部过期仅适用于未成交、未报出的`PROPOSED`；券商在途/部分成交与新目标冲突时转`RECONCILIATION_REQUIRED`，保留剩余预留及订单绑定的旧intent，并只记录新的日目标，不能以新意图覆盖旧绑定。迟报真实成交仍需入账。若目标数量相同但原因代码不同，也属于意图替换，必须在替换前核查绑定。

代码落点：`backend/modules/quant_strategy/application/lifecycle_service.py`和`position_lifecycle_manager.py`。隔离PG覆盖目标归位、反向、同向超目标及同数量不同原因，并在RECON后确认迟报成交；生命周期60项通过。独立CR连续三轮指出各分支缺口，最终原因差异修复尚未取得独立PASS，不能据单测宣称全链路验收。券商回执真伪与终态核对属于T4。

## 补充边界（2026-09-29）

迟报成交不仅可能发生在部分成交状态，也可能把待对账订单填满；后续成交撤销或缩量更正又会把它变回未满。订单和旧意图必须在整条修订链保持`RECONCILIATION_REQUIRED`，否则未满且零成交的`PROPOSED`可经通用取消释放预留。`intent_id=NULL`的券商在途旧单不得自动绑定新意图；直接意图写入口即使尚无活动意图，也须在组合锁内检查所有活动订单。针对这些更正与入口反例，隔离PG生命周期67项通过；独立R1/R2均发现major，末轮修复尚无独立PASS。
