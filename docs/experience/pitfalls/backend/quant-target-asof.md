# 量化目标决策日与行情截至日混用

组合目标必须使用已确认的行情截至日；下一交易日的决策不能要求或读取该决策日尚未产生的收盘价。

## 执行BUY的旧信号单日成交额旁路（2026-09-29）

- **表象**：执行loader新增T日20开市日ADV后，约束器在旧`execution_market`缺字段时回退`raw_amount`；已持久化扫描信号仍能由`EntryBatchService`建BUY。普通规划器无行情时甚至曾虚构极大金额。
- **根因**：把新增证据字段当可选优化，而旧JSONB信号及直接目标规划仍消费旧单日字段；函数级通过不代表批次重放安全。
- **正确姿势**：loader按独立开市日历逐日核20日金额；所有BUY统一要求显式、有限、正数ADV20，缺键/畸形值拒绝；旧信号在隔离PG消费回归中确认0订单。保护SELL不受BUY流动性门禁阻断。已通过47项纯测、97项隔离PG回归及独立R2审查。

## 表象（2026-09-28）

`PortfolioTrialInput`允许`evaluation_as_of < decision_date`，但股票候选、基准、ETF代表选择器最初以`decision_date`检查行情尾日。9月24日行情做9月28日决策时会选出空集合；若调用方反而填9月28日行情，则可能越前。试验入口最初只检查最后一行，未来日期藏在非末尾也未被明确拒绝。

## 根因

组合业务决策日与已确认行情的最后日期是不同事实；`intent=None`同时覆盖非调仓、缺证据和无候选，不能代替输入完整性判定。

## 正确姿势与验证

股票/ETF候选、基准及ETF代表选择显式按`evaluation_as_of`核验行情；入口遍历所有候选/基准日期和ETF事实日期，拒绝晚于该日的数据。周/月调仓标志和冷却继续按`decision_date`。生产目标另需证明完整候选全集、冻结trial/version绑定，不能把`None`转成`cash_only`。

代码：`stock_inputs.py`、`stock_medium_momentum.py`、`stock_short_reversion.py`、`etf_dual_momentum.py`、`etf_defensive_allocation.py`、`trial_executor.py`。2026-09-28相关纯回归232 passed，独立R1两项major修复后R2 PASS；跨9月24日到28日ETF选集/目标及非末尾未来行均有测试。

## 股票指数基准快照不能混入证券池或污染基金快照（2026-09-28）

- **表象**：研究reader原只取stock/fund，股票试验的沪深300基准仅靠测试手工构造。第一次补指数读取时只核`instrument_type='index'`，会收下上市前/退市后误行；后续覆盖审计虽只针对股票，DatasetBuilder仍解析基金单独快照中异常的可选指数行，导致基金快照错误失败。
- **根因**：基准指数与股票/基金候选是不同事实集合，且目录类型、上市有效期、行情截至日、交易日历连续性须分别核验；可选跨资产表不能无条件影响目标资产质量。
- **正确姿势**：指数读取限定index类型及非空上市日至退市日前，单列`benchmark_daily`；股票快照按as-of和独立日历校验代码/日期/有限正收盘，基金单独快照跳过该表；历史来源可得时点保留未认证。隔离DB 23项、覆盖/快照32项与两次独立R2审查PASS。

## 可空证券代码不可直接进入布尔比较（2026-09-28）

- **表象**：基准输入诊断器用`row["ts_code"] != "000300.SH"`判断错代码，nullable string列的一行`pd.NA`会得到`pd.NA`而非布尔值，`if`随即抛“boolean value of NA is ambiguous”，导致缺证据没有转为可诊断空序列。
- **根因**：pandas三值空值语义与Python布尔分支不兼容；同一模块的窗口行判断也有相同表达式。
- **正确姿势**：代码身份先`isinstance(value, str)`再比较，两个消费点同步修改；构造nullable string列`pd.NA`反例。`test_benchmark_input_builder.py`定向10项通过，独立R2审查PASS。

## 本地输入缺口不能混作来源认证缺口（2026-09-28）

- **表象**：首次股票组合门禁汇总把`StockUniverseAudit.evidence_issues`整体放入`certification_issues`；该字段同时含`dataset: not READY`、本地行问题和独立覆盖问题，导致同一行错误在本地与认证两类重复出现。
- **根因**：既有审计字段是面向报告的混合问题清单，不能作为具有不同业务门禁语义的认证集合直接复用。
- **正确姿势**：本地输入问题从候选gap、全集差异、基准缺日、快照质量分别组装；认证问题只从快照认证字段、独立覆盖状态、基准来源及账户锁内来源组装。非READY/本地坏行反例验证不会误入认证集合；相关24项纯测与独立R2审查PASS。

## 历史总根数会掩盖近期复权窗口缺口（2026-09-28）

- **表象**：ETF候选已有251根历史日线，最近20个交易日第6日缺一根复权因子；旧逻辑跳过缺因子日后仍剩250根、ADV20只核日成交额，错误生成候选。股票转换器有同类路径。
- **根因**：上市后累计有效bar下限与最近20个交易日逐日可用性是两项独立约束，前者不能替代后者。
- **正确姿势**：股票/ETF均对最近20个独立交易日逐日核日线、有效收盘、有效复权因子与金额；ETF原价ATR仍单列核验。两个251根缺第245根因子的反例使候选为空；相关23项纯测通过，独立ETF/股票delta复核PASS。

## 本地写入轨迹时间不能冒充历史可得时间（2026-09-29）

- **表象**：`instrument_daily.updated_at`只保存最后一次覆盖时间，`adj_factor`原无时间列；给四表加修订触发器后，若把触发时的`observed_at`当成截止时已可见，又会在长事务晚于截止时间提交时发生越前。安装前的存量与今天回填旧交易日也不能倒推过去已见。
- **根因**：交易日、源发布时间、本地触发时间、事务提交可见时间和研究决策时间是五种事实。触发器记录写入事件，但不会自动证明源发布时间或提交时点。
- **正确姿势**：`market.fact_revision`只作本地写入修订轨迹；`read_fact_as_of`的PRESENT不得用于收益认证或目标授权。另取独立原件/发布时间与提交可见证明，并与快照内容绑定。四表主键原地修改、TRUNCATE均拒绝以免旧键悬挂或清空轨迹；隔离库7项和独立R2审查PASS。
