## 一、总体结构

一个 PostgreSQL 16 实例、一个 liveprofit 库，两个 schema 分工：

```
liveprofit（PostgreSQL 16）
├── public（应用域）
│   ├── 平台域（backend 建表，alembic 迁移 0001/0002/0004）
│   │   analysis_tasks / task_outbox / analysis_reports（0002 加 has_unavailable_sections 投影列）
│   │   macro_information
│   │   watchlists / watchlist_items / portfolios / portfolio_positions
│   │   agent_prompt_overrides（0004，analysis_tasks 加 rerun_from_node_id 列）
│   └── 事件研究域（AI/eventStudy/db/schema.sql 建表，含 pgvector）
│       assets / events / event_impacts / market_context / predictions
└── market（证券市场数据库，db/instrument/schema.sql 建表，alembic 不管市场表）
    ├── 标的三件套：instrument / instrument_daily / adj_factor
    ├── 因子宽表：factor_daily
    ├── 信息表：stock_info / fund_info（主表差异数据按资产类拆表）
    ├── 板块体系（同花顺，ths/dc 多来源）：sector / sector_member / sector_daily
    └── 行业体系（申万 SW2021，与板块是两套体系）：industry / industry_member
```

- **非 PG 存储**（不属本表结构）：Redis——任务队列/Broker、事件流、事件研究待审核草稿（决策 10）；Chroma——新闻文本向量检索。
- **已删旧表**（2026-09-13，证券市场数据库统一方案落库）：public 的 `concept_hotness_snapshots`（迁移 0006）、`market_assets` / `market_bars_daily` / `market_index_factors`（迁移 0007，DROP 前已备份 `logs/backups/pg_backup_20260913_legacy_tables.sql`）；eventStudy 的 `market_data` / `industry_codes`；原 store 六表（`AI/dataflows/store` 旧实现整体删除）。

## 二、market schema（证券市场数据库，11 表）

建表与 31 行申万 SW2021 行业字典种子均出自 [db/instrument/schema.sql../../../db/instrument/schema.sql)（幂等，可重复执行；全部语句显式 `market.` 前缀）。读取一律走 `db/instrument/dao/`（DAO 模块名 = 表名；成分表并入所属字典模块：sector_member → dao/sector.py、industry_member → dao/industry.py）。后端市场数据读路径唯一连接源 = `db.instrument.get_connection` 工厂（MarketDataService 注入 market_conn；SQLAlchemy 侧已无市场读模型残留）。

| 表 | 用途 | 主键 | 关键列 / 备注 |
|------|------|------|------|
| instrument | 标的主表：股票/基金/指数统一目录，一代码一行 | ts_code | name / instrument_type（index/stock/fund，源表即类型）/ list_status（L/D/P，基金行 NULL）/ list_date / delist_date / data_source（tushare/akshare）/ updated_at。**无 market 列**——US/KR 原 symbol 与 CN 代码格式天然不冲突，ts_code 全局唯一 |
| instrument_daily | 统一日线：指数+个股+基金同构一张表，未复权原值 | (ts_code, trade_date) + 反向索引 (trade_date, ts_code) | open/high/low/close（NOT NULL，NaN 行写入前 drop）/pre_close/change/pct_chg/vol（手）/amount（千元）/source（实际成功源）/updated_at。停牌日无行 |
| adj_factor | 复权因子：股票 adj_factor 与基金 fund_adj 接口共用 | (ts_code, trade_date) + 反向索引 | adj_factor（无除权除息 = 1.0）。停牌标的仍更新因子，行数 ≥ 日线行数属预期 |
| factor_daily | 技术因子宽表：指数∪个股列并集，**不自算**（上游 idx_factor_pro/stk_factor_pro 原值；因子行自带全历史窗口，区间首根即有值） | (ts_code, trade_date) + 反向索引 | close（对齐自检列）；指数∪个股共有：ma_bfq_{5,10,20,60} / boll_{mid,upper,lower}_bfq / macd_{dif,dea}_bfq, macd_bfq；仅个股：ma_bfq_250 / rsi_bfq_{6,12,24}（指数行 NULL） |
| stock_info | 股票信息表：stock_basic 差异列 | ts_code | exchange（SSE/SZSE/BSE）/ market（上市板块：主板/创业板/科创板/北交所）/ area。无 industry 列——行业归属走申万体系 |
| fund_info | 基金信息表：fund_basic 差异列，恒场内（按 market='E' 过滤拉取） | ts_code | management / custodian / fund_type / benchmark / market（E=场内/O=场外，本表恒 'E'）/ m_fee / c_fee / 申购赎回日期等 |
| sector | 板块字典：同花顺板块体系（行业/概念/特色三类，type 区分；ths/dc 多来源，与 type 正交） | (source, sector_code) | name / type（N=概念/I=行业/S=特色；首期存量恒 'N'，I/S 增量采集后续阶段；dc 无此口径存 NULL）/ count（来源口径快照）/ exchange / list_date |
| sector_member | 板块成分映射（~12 万行，多来源） | (source, sector_code, ts_code) + ts_code 索引 | 不存成分股名——JOIN instrument 取权威名称 |
| sector_daily | 板块日线：ths/dc 板块指数日行情；**热度 heat_v1 现场计算的数据底座**（backend 读本表现算，不落快照表、不进 Redis） | (source, sector_code, trade_date) + 反向索引 | open/high/low/close/pre_close/change/pct_chg/vol/amount/turnover_rate/updated_at。heat_v1 = pct×0.6 + vol 变化×0.4 |
| industry | 行业字典：申万 SW2021 等多来源（与同花顺板块是两套体系：申万=互斥完备分类，sector=多对多标签） | (source, industry_code) | name（统一裸 name，与 sector 对齐）/ count（首期 NULL）。已幂等种子 31 行 SW2021 一级行业 |
| industry_member | 行业成分关系（与 sector_member 同构；首期建空表——成分采集后续阶段） | (source, industry_code, ts_code) + ts_code 索引 | ts_code 与 instrument 对齐 |

**通用规则**：表名单数、列名 snake_case；时间序列表一律 (ts_code, trade_date) 复合主键 + (trade_date, ts_code) 反向索引；`trade_date` DATE，行写入时间全表统一 `updated_at` TIMESTAMPTZ；单位 = 上游原值口径不换算（价格元、vol 手、amount 千元）；代码格式：CN = 6 位数字 + .SH/.SZ/.BJ，US/KR = 原 symbol（如 .INX）。

### 3.2 事件研究域（AI/eventStudy/db/schema.sql，含 pgvector）

约定：全部表不设外键（决策 7，关联由应用层保证）；PG 只存正式/已处理数据，待审核草稿存 Redis（决策 10）。

| 表 | 用途 | 备注 |
|------|------|------|
| assets | 事件研究资产表 | asset_id BIGSERIAL PK；ticker 唯一；行情数据不在此表（读 market.instrument_daily） |
| events | 事件表：仅人工处理过的事件（approved/ignored） | embedding VECTOR(1024)（bge-m3）；trading_day = 事件对齐后的交易日 t0；event 量级暂不建 HNSW 索引 |
| event_impacts | 事件影响：仅人工确认过的正式记录 | 影响标注模块写入 |
| market_context | 市场环境快照：一行 = 某日全部市场 | — |
| predictions | 预测表：仅显式保存 / 离线回测时写入 | — |
