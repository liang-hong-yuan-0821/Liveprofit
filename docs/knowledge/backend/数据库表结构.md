## 一、总体结构

一个 PostgreSQL 16 实例、一个 liveprofit 库，两个 schema 分工：

```
liveprofit（PostgreSQL 16）
├── public（应用域）
│   ├── 平台域（backend 建表，alembic 迁移 0001/0002/0004）
│   │   analysis_tasks / task_outbox / analysis_reports（0002 加 has_unavailable_sections 投影列）
│   │   macro_information
│   │   watchlists / watchlist_items / portfolios / portfolio_positions
│   │   agent_prompt_overrides（0004，analysis_tasks 加 rerun_from_node_id 列）
│   └── 事件研究域（AI/eventStudy/db/schema.sql 建表，含 pgvector）
│       assets / events / event_impacts / market_context / predictions
└── market（证券市场数据库，db/instrument/schema.sql 建表，alembic 不管市场表）
    ├── 标的三件套：instrument / instrument_daily / adj_factor
    ├── 因子宽表：factor_daily
    ├── 本地事实修订：fact_revision（日线/复权/因子/复合状态写入事件）
    ├── 信息表：stock_info / fund_info（主表差异数据按资产类拆表）
    ├── 板块体系（同花顺，ths/dc 多来源）：sector / sector_member / sector_daily
    └── 行业体系（申万 SW2021，与板块是两套体系）：industry / industry_member
```

- **非 PG 存储**（不属本表结构）：Redis——任务队列/Broker、事件流、事件研究待审核草稿（决策 10）；Chroma——新闻文本向量检索。
- **已删旧表**（2026-09-13，证券市场数据库统一方案落库）：public 的 `concept_hotness_snapshots`（迁移 0006）、`market_assets` / `market_bars_daily` / `market_index_factors`（迁移 0007，DROP 前已备份 `var/data/backups/pg_backup_20260913_legacy_tables.sql`）；eventStudy 的 `market_data` / `industry_codes`；原 store 六表（`AI/dataflows/store` 旧实现整体删除）。

## 二、market schema（证券市场数据库）

建表与 31 行申万 SW2021 行业字典种子均出自 [db/instrument/schema.sql](../../../db/instrument/schema.sql)（幂等，可重复执行；全部语句显式 `market.` 前缀）。读取一律走 `db/instrument/dao/`（DAO 模块名 = 表名；成分表并入所属字典模块：sector_member → dao/sector.py、industry_member → dao/industry.py）。后端市场数据读路径唯一连接源 = `db.instrument.get_connection` 工厂（MarketDataService 注入 market_conn；SQLAlchemy 侧已无市场读模型残留）。

| 表 | 用途 | 主键 | 关键列 / 备注 |
|------|------|------|------|
| instrument | 标的主表：股票/基金/指数统一目录，一代码一行；股票日线目标集合的上市事实来源 | ts_code | name / instrument_type（index/stock/fund，源表即类型）/ list_status（股票 L/D/P/G/U，其中上游 UN 归一 U；基金行 NULL）/ list_date / delist_date / data_source（tushare/akshare）/ updated_at。**无 market 列**——US/KR 原 symbol 与 CN 代码格式天然不冲突，ts_code 全局唯一 |
| instrument_daily | 统一日线：指数+个股+基金同构一张表，未复权原值 | (ts_code, trade_date) + 反向索引 (trade_date, ts_code) | open/high/low/close（NOT NULL，NaN 行写入前 drop）/pre_close/change/pct_chg/vol（手）/amount（千元）/source（实际成功源）/updated_at。停牌日无行 |
| adj_factor | 复权因子：股票 adj_factor 与基金 fund_adj 接口共用 | (ts_code, trade_date) + 反向索引 | adj_factor（无除权除息 = 1.0）。停牌标的仍更新因子，行数 ≥ 日线行数属预期 |
| factor_daily | 技术因子宽表：指数∪个股列并集，**不自算**（上游 idx_factor_pro/stk_factor_pro 原值；因子行自带全历史窗口，区间首根即有值） | (ts_code, trade_date) + 反向索引 | close（对齐自检列）；指数∪个股共有：ma_bfq_{5,10,20,60} / boll_{mid,upper,lower}_bfq / macd_{dif,dea}_bfq, macd_bfq；仅个股：ma_bfq_250 / rsi_bfq_{6,12,24}（指数行 NULL） |
| fact_revision | 四张量化事实表的本地写入事件修订；不是上游发布时间或提交可见时间证书 | id + (fact_table, ts_code, trade_date, observed_at DESC, id DESC) 索引 | INSERT/实质UPDATE/DELETE完整业务行JSONB；忽略单纯`updated_at`变更；证券日主键原地修改和清表拒绝；建表前存量无历史记录 |
| stock_info | 股票信息表：stock_basic 差异列 | ts_code | exchange（SSE/SZSE/BSE）/ market（上市板块：主板/创业板/科创板/北交所）/ area。无 industry 列——行业归属走申万体系 |
| fund_info | 基金信息表：fund_basic 差异列，恒场内（按 market='E' 过滤拉取） | ts_code | management / custodian / fund_type / benchmark / market（E=场内/O=场外，本表恒 'E'）/ m_fee / c_fee / 申购赎回日期等 |
| sector | 板块字典：同花顺板块体系（行业/概念/特色三类，type 区分；ths/dc 多来源，与 type 正交） | (source, sector_code) | name / type（N=概念/I=行业/S=特色；首期存量恒 'N'，I/S 增量采集后续阶段；dc 无此口径存 NULL）/ count（来源口径快照）/ exchange / list_date |
| sector_member | 板块成分映射（~12 万行，多来源） | (source, sector_code, ts_code) + ts_code 索引 | 不存成分股名——JOIN instrument 取权威名称；成分关系可先于 IPO 上市发布，不能作为股票日线目标集合或上市日期事实 |
| sector_daily | 板块日线：ths/dc 板块指数日行情；**热度 heat_v1 现场计算的数据底座**（backend 读本表现算，不落快照表、不进 Redis） | (source, sector_code, trade_date) + 反向索引 | open/high/low/close/pre_close/change/pct_chg/vol/amount/turnover_rate/updated_at。heat_v1 = pct×0.6 + vol 变化×0.4 |
| industry | 行业字典：申万 SW2021 等多来源（与同花顺板块是两套体系：申万=互斥完备分类，sector=多对多标签） | (source, industry_code) | name（统一裸 name，与 sector 对齐）/ count（首期 NULL）。已幂等种子 31 行 SW2021 一级行业 |
| industry_member | 行业成分关系（与 sector_member 同构；首期建空表——成分采集后续阶段） | (source, industry_code, ts_code) + ts_code 索引 | ts_code 与 instrument 对齐 |

**通用规则**：表名单数、列名 snake_case；时间序列表一律 (ts_code, trade_date) 复合主键 + (trade_date, ts_code) 反向索引；`trade_date` DATE，行写入时间全表统一 `updated_at` TIMESTAMPTZ；单位 = 上游原值口径不换算（价格元、vol 手、amount 千元）；代码格式：CN = 6 位数字 + .SH/.SZ/.BJ，US/KR = 原 symbol（如 .INX）。

### 交易状态与历史来源隔离（2026-09-26）

| 持久对象 | 职责与读取契约 |
|---|---|
| `trade_status_daily` | 原始复合状态观察；保留停牌范围、原始时段、ST、板块及限价，写入和源间比对使用原表 |
| `stock_st_source_batch` / `stock_st_source_observation` | 不可变独立历史 ST/交易标志批次及逐证券日事实；批次记录哈希、采集时间、覆盖校验；`scope_codes=NULL`为全沪深年度池，显式代码数组为定向年度池 |
| `stock_st_source_conflict` | 保存同一证券日的双方 ST 分歧，不静默选定任何一方 |
| `trade_status_effective`（视图） | 从原始复合状态中排除已登记 ST 冲突证券日；补采、覆盖、审计、研究和执行统一读取，避免各链路自行遗漏隔离条件 |
| `suspension_source_daily` / `suspension_evidence` | 独立上游交叉验证、公司或交易所原件的停牌事实；停牌证据不能替代未知 ST 字段 |

冲突原始行继续保留；普通含糊停牌清理也不得删除已登记 ST 分歧的原始记录。视图当前不会自动采用 `stock_st_adjudication` 中的裁定，裁定消费流程尚未启用。定向批次不能提供全市场ST名单，只能以明确未交易事实与当日Tushare ST/日线/停复牌源交叉校验；R或有时段S矛盾时仍未知。源表存在并不等于研究数据通过资格门禁；历史可得时点仍由研究快照规则约束。

### 3.3 成交版本步与分批首仓（代码迁移0050，2026-10-01）

`fill_lifecycle_version_steps`沿用0048表，一笔成交至多一行，以`fill_event_id`为主键及递延成交外键，`lifecycle_id`指向所属生命周期。0050增强既有保护，ORM约束同步；未改写0048/0049历史迁移。

| 字段/机制 | 当前代码契约 |
|---|---|
| `origin=LOCAL_CAUSAL` | `version_before/version_after`均非空，前版本≥1，后版本=前版本+1；由生命周期更新触发器捕获 |
| `origin=UNATTRIBUTED` | 两个版本均为空；只保存成交关联，不编造版本因果 |
| 插入校验 | 拒绝直接INSERT；LOCAL_CAUSAL核父触发、事务关联成交ID及捕获时版本，递延核成交LIVE绑定、生命周期及组合一致性 |
| 多笔同事务 | 每笔捕获自己的版本步；提交时不要求早先事件的后版本等于生命周期最终版本 |
| 不可变/迁移 | 拒UPDATE/DELETE/TRUNCATE；升级先锁表核旧记录，异常拒升不补造；0050降级只撤新增保护，保留全部事实 |

生命周期首仓订单可能没有`intent_id`。`LifecycleOrderService`对原首笔未修订CONFIRM所属订单，用有效成交累计核冻结政策初仓目标；足额才把`ENTRY_PENDING`推进`INITIALIZED`，与该笔成交共用一次版本递增。其他订单成交不证明原首仓完成，待对账或后继目标冲突不覆盖；超目标或订单累计与成交日志不符时保留成交并转待对账。既有生命周期的原单续填可沿用已归档政策，仍核冻结策略/政策身份及原首笔锚；该例外不适用于新首填或新订单。

### 3.4 生命周期操作历史基础结构（代码迁移0051至0054，2026-10-02）

| 表 | 职责与身份 |
|---|---|

| `position_lifecycle_operations` | 生命周期操作序号/前驱、命令步骤、三部分快照、政策/版本、来源和变化全集摘要 |
| `quant_execution_operation_sources` | 类型化多源引用、可删除任务/信号身份快照、订单原行像及命令级未绑定订单结果 |
| `quant_execution_operation_changes` | 逐次OLD/NEW变化及命令全局顺序；0052/0053单订单状态及0054无生命周期组合的多未绑定BUY捕获 |

六表只追加，拒UPDATE/DELETE/TRUNCATE；0051过渡阶段拒所有LIVE INSERT。0052为命令、来源、变化三表安装未绑定状态命令受控INSERT校验；0053再启用已绑定单订单状态操作头，两个创建输入表仍拒LIVE INSERT。三个旧流（日事实修订、意图修订、成交版本步）新增可空命令/操作复合FK，旧行及旧写者保留`LEGACY_UNLINKED`，未伪造关联。

0051在锁住生产者后为每个旧生命周期生成`MIGRATED_BASELINE/BLOCKED/UNKNOWN_PRIOR`，不造过去操作或建单输入；所有未绑定旧单（含没有生命周期的组合）保留命令级未知结果及原行像。迁移行像以`__raw_row_json__`原文为物理类型与精度权威，同对象其他键只作规范数值解释视图，不据其重建JSONB原数字类型。`managed_state`排除捕获时间、活来源引用及原文，账户持仓标`ACCOUNT_OBSERVED`，旧仓闭仓后新仓不改变旧观察。

`load_migration_baseline`从字段重算命令、操作、来源及原文/解释摘要并核预期全集，始终返回`UNKNOWN_PRIOR`且`continuous_history_known=False`。未发现基线返回None，不能解释为账户无缺口。旧业务写者目前仍可变更当前投影，0051只冻结迁移边界；0052/0053窄命令封口已实现，全入口捕获及连续还原依后续3ar任务实现。

`load_order_status_command_replay`只读支持`order-state:v1`单未绑定订单结果：先按组合/请求键核原始规范字节，同键异请求拒绝；再核前驱清单、完整物理列、精确原文与类型敏感解释、全部变化链/摘要及结果结论。结果snapshot schema 1含`schema_version/outcome/reason_code/before_row/after_row/missing_sources/change_count/changes_sha256`，变化捕获时间摘要统一UTC六位微秒。每步状态UPDATE只允许状态/revision/更新时间变化且revision加1，不读当前订单补历史。读端不认证事实完整性、事务封口或执行权限，三个字段`database_sealing_verified/continuous_history_known/execution_authorized`均False；已绑定操作链及其他命令不在此读端范围，生产入口未启用。

0052数据库入口`public.lc_record_unbound_order_status`接独立规范原请求字节、组合ID和操作者引用，不接受客户端清单；先拒已有XID，再锁组合和订单，核未绑定/revision后冻结恰一结果清单。真实UPDATE触发逐行保存OLD/NEW原文，最后插唯一APPLIED/NO_STATE_CHANGE/BLOCKED结果并封口；命令级递延约束核完整变化链、摘要和实际最终订单。捕获/入口/核验固定UTC与ISO,YMD。同键同请求只核原封存结果后重放，不拿当前订单补历史。

封口GUC只用于关联；guard要求表owner身份，changes还核嵌套触发。入口及助手函数默认撤销PUBLIC执行，迁移先校owner并按组合→订单锁表；生产角色授权未配置。清空GUC或提前SET CONSTRAINTS后，同事务所有其他订单INSERT/UPDATE/DELETE仍按当前XID拒绝，`ix_lc_unbound_command_transaction`部分索引支持事务检查。后续独立事务的旧写者仍可改当前行且不捕获，因此不能证明连续历史。应用`stage_unbound_order_status_command`不提交/回滚，调用方负责事务；结果三个认证字段仍False，既有生产API未接。

| 标的 | `market.instrument` | 主表：股票/基金/指数统一目录，一代码一行；通用列 ts_code/name/instrument_type/list_date/delist_date/list_status/data_source/updated_at（**无 market 列**——US/KR 原 symbol 与 CN 代码格式天然不冲突，ts_code 全局唯一；**exchange 属股票差异列，放 stock_info**）；**差异数据一律进信息表，不塞主表** |
| 日线 | `market.instrument_daily` | 交易日行情（股票/基金/指数同构一张表，store 决策 1 已证无差距），主键 (ts_code, trade_date) |
| 复权因子 | `market.adj_factor` | 主键 (ts_code, trade_date) |
| 技术因子 | `market.factor_daily` | 指数∪个股列并集宽表，与日线同频对齐 |
| 板块 | `market.sector` + `market.sector_member` | 同花顺板块体系字典 + 成分关系：行业/概念/特色三类板块（**type 区分 N/I/S**，与 source（ths/dc）正交）；首期存量仅概念板块（恒 'N'），'I'/'S' 增量采集后续阶段；PK (source, sector_code) |
| 板块日线 | `market.sector_daily` | 板块指数日行情（ths/dc 口径），PK (source, sector_code, trade_date)；热度现场计算的数据底座（heat_v1 热度 = pct×0.6 + vol×0.4，backend 读本表现场算，不落快照表不进 Redis——concept_hotness_snapshots 已删）；**dc 源每日增量积累**（dc_daily 窗口型端点，历史自采集启动日积累不回溯——ths_daily 全历史能力已实测、暂缓；板块概念Treemap方案 2026-09）——热度口径 = dc（原口径不变） |
| 行业 | `market.industry` + `market.industry_member` | 申万 SW2021 字典 + 成分关系（**与同花顺板块是两套体系：申万=互斥完备分类，sector=多对多标签**），**与 sector 完全对称：列 source / industry_code / name / count；主键含 source（industry PK (source, industry_code)、industry_member PK (source, industry_code, ts_code)），多来源共存（SW2021 等）；industry_code 为 tushare index_classify 原名，名称列统一 name（与 sector 对齐）** |
| 信息表 | `market.{instrument_type}_info` | fund_info / stock_info；主表差异数据按资产类拆信息表，命名后缀 `_info`（不用 `_extension`）；**列名沿用 tushare 原名（含跨表同名不同口径的 market：stock_info.market=上市板块、fund_info.market=场内/场外 E/O，与 tushare stock_basic/fund_basic 现状一致）** |

命名及写入强制约束见 [行情与数据源约束](../../standards/ai/行情与数据源约束.md#证券市场命名与持久层约束)。
