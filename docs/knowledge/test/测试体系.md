# 测试体系

正式测试集中在根 `tests/`，采用领域（backend/frontend/ai/data）→业务模块→unit/integration/contract→功能文件；跨域流程位于 e2e，辅助代码位于共享或模块内 support。backend 的 API/router、业务 Worker 随业务模块组织，通用平台能力归 platform，平台迁移归 migrations。

[tests/README.md](../../../tests/README.md) 是目录和运行约定的维护入口；[suites.json](../../../tests/suites.json) 声明模块、代码路径与直接关联回归。`python -m tests.run --module <模块> --level unit` 定向运行，`--related` 增加登记的直接关联模块；该索引不能替代变更影响分析及关键正确性门禁。

文件级定位以测试顶部注释 JSON 为单一来源，登记用途、业务关键词、实际被测文件及依赖环境，按需指定关联文件。`python -m tests.index` 静态生成 [机器索引](../../../tests/catalog.json) 摘要、`tests/catalog/<领域>/<模块>.json` 详情与 [测试文件索引](测试索引.md) 模块导航、`测试详情/<领域>/<模块>.md`，不执行测试；`--query` 按需求关键词查询，`--source` 按改动代码反查。查询默认返回摘要，按需使用 `--details` 或读取候选模块详情；场景名称、行号及说明自动提取并仅存于详情，模块级关联继续由 suites 维护。`--check` 核验说明完整、路径有效、生成物未过期。agent 读取候选场景与断言后才能决定更新或新增测试；索引不证明覆盖充分，也不代替资源隔离核查。

根 conftest 负责轻量配置与默认资源门禁。真实 LLM/toolkit/memory、外部源、DB/Redis及 E2E 需要显式许可，其中真实 LLM/toolkit/外部源只能由用户手动启用；目录和标记不能证明数据库隔离。真实依赖初始化放在局部 fixture 中。前端依赖仍在 frontend，独立 Vitest/Playwright 配置及启动器从项目根发现集中测试，应用 Vite 根目录保持 frontend。

存量行为变化更新已有功能测试，新独立功能新增文件。复杂 bug 的临时复现/诊断脚本可放 backend/bugs；正式功能测试永久保存回归场景，经修复前失败、修复后通过及关联回归后清理临时脚本。数据修复、迁移及审计资产按生命周期管理保留。
