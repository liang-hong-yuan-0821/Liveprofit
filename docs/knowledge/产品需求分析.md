## 一、产品定位与范围

### 1.1 产品是什么

Liveprofit 是一个**本地单人使用的 AI 投研工作台**。操作者可在同一应用中完成以下闭环：

- 浏览全球市场指数、热门概念和已审核的宏观事件信息；
- 维护自己的自选分组、关注标的、手工组合及持仓；
- 对单只股票或全市场提交 AI 分析任务；
- 实时观察分析进度、取消尚未完成的任务，并查看最终状态；
- 阅读市场、板块、个股和交易决策组成的结构化分析报告；
- 针对输入事件执行事件研究预测，阅读方向、累计异常收益（CAR）、样本数及相似历史事件。

首期是 loopback local-only 应用，即仅在本机使用，不提供多用户协作、登录、账号、权限、成员管理、远程访问或管理员后台。

### 1.2 产品目标

| 目标 | 用户价值 | 完成标准 |
|------|----------|----------|
| 市场信息集中浏览 | 无需在多个数据源之间切换即可获取大盘、热点与事件研究信息 | 大盘页在同一页面直接展示市场、板块、信息三个区块，并明确数据来源与更新时间 |
| 投资关注对象本地化管理 | 将关注标的与实际手工持仓沉淀为可维护资产 | 可完成分组、标的、组合、持仓的创建、修改、排序、删除及冲突恢复 |
| AI 分析过程可见 | 长耗时分析不再是黑盒，用户可以确认当前阶段、重试过程与最终结果 | 创建后进入可刷新恢复的任务详情；进度中断时仍能以任务正式状态继续观察 |
| 分析结论可阅读、可追溯 | 让不同层级的投研结论、风险提示与数据来源清晰呈现 | 成功任务可打开最新结构化报告；未请求、不可用和可用区块被明确区分 |
| 事件影响可快速研判 | 针对新的宏观/行业事件，快速获得基于历史样本的预测参考 | 可提交事件文本与资产等参数，展示预测结果或明确的繁忙/超时处理方式 |

### 1.3 首期范围与非目标

**范围内**

本地单人使用、大盘浏览、自选和组合维护、AI 任务、任务进度、报告、事件研究预测

**首期不包含**

- 登录、注册、账户设置、权限、组织/成员、审计后台
- 用户在页面自行配置指数资产、前端静态维护指数或概念名单
- 报告历史版本选择、报告编辑、报告导出/分享
- 前端根据本地规则自行产生投资结论或绕过后端直接调用数据 Provider
- 跨分组移动、批量排序、组合与 AI 仓位建议自动合并
- 事件研究历史管理、异步预测任务列表、自动轮询重试
- 美国（US）、韩国（KR）、中国（CN）以外的市场

### 1.4 核心术语

| 术语 | 定义 | 与相近概念的区别 |
|------|------|------------------|
| 分析任务 | 一次单股或全市场 AI 分析请求及其执行过程 | 不是报告，也不是任务进度事件列表 |
| 分析层级 | 请求 AI 分析时选择的市场、板块、个股、筛选、仓位等分析范围 | 是任务输入，不等同于报告区块是否有可展示内容 |
| 任务状态 | 后端保存的任务正式状态，如排队、运行、重试中、成功、失败、已取消 | 是页面判断任务最终结果的唯一依据；SSE 仅用于进度体验 |
| attempt（尝试次数） | 同一任务因可重试问题重新投递后的当前执行次数 | 不是一条新的用户任务，也不代表用户再次提交 |
| 任务进度事件 | 排队、开始、阶段进度、完成、失败、取消等实时通知 | 仅在任务详情的有限时间线中展示，不是永久运行记录 |
| 报告区块 | 市场、板块、个股、决策等结构化报告的独立区域 | 各区块分别标记为可用、不可用或未请求 |
| 自选分组 | 用于组织关注标的的本地分组 | 不等于组合；不记录数量和成本 |
| 组合 | 用户手工维护的本地持仓集合 | 不会自动接受 AI 的仓位建议 |
| 宏观信息 | 已审核通过的事件研究信息投影 | 不从新闻抓取、预测响应或 AI 报告文本临时拼装 |
| 热门概念 | 后端按固定算法计算出的概念热点快照 | 前端只展示排名和原因，不自行计算"热门" |
| 幂等键 | 标识一次创建意图的唯一键，同一键重复提交返回同一任务 | 不是任务 ID；用户修改任一输入后即为新意图、新键 |
| 读模型 | 后端面向页面组装好的专用查询结果（如看板摘要、报告区块状态） | 不是任务/报告的原始存储结构，前端不做二次拼装 |
| 新鲜度 | 数据快照相对"当前可用"的程度：FRESH / STALE / UNAVAILABLE，与开闭市状态（OPEN/CLOSED）正交 | 不是错误态；语义见 3.1.3.4 |
| Cursor 分页 | 用服务端返回的 next_cursor 游标逐页追加读取 | 不允许用 offset、页码或本地排序替代 |
| 有效交易日 | 服务端对用户请求日期校正后的实际分析交易日 | 不等于用户请求日期；校正说明单独展示 |
| revision | 自选/组合资源的乐观并发版本号 | 不是 updated_at；写操作携带，冲突时前端重新拉取 |
| 报告区块状态 | AVAILABLE / UNAVAILABLE / NOT_REQUESTED | 由后端按区块给出，不由字段缺失推断 |

| UI 元素 | 展示内容 | 交互行为 | 操作后结果/边界处理 |
|---------|----------|----------|---------------------|
| 应用标识 | Liveprofit 产品名称/标识 | 点击 → 返回大盘页 | 跳转 /market；不清除当前已保存的业务数据 |

| 侧栏折叠 | 侧栏展开/收起状态 | 点击 → 展开或收起侧栏 | 立即更新全局布局并在本机保存 |
| 页面加载态 | 骨架、加载提示 | 无主动操作 | 数据读取期间占位；不将加载误显示为无数据 |
| 页面空态 | 无数据说明与可选操作入口 | 按页面提供"新建""重试"等操作 | 空态属于正常业务状态时不显示系统错误 |
| 页面错误态 | 可理解的错误摘要、请求标识（如可用）、重试入口 | 点击重试 → 重新读取/提交当前资源 | 仅 retryable=true 的错误显示显式重试；不可重试错误只提供返回或刷新后重新查询 |
| 404 资源不存在 | 专用不存在文案与返回路径 | 点击返回 → 上级列表或 /ai | 不显示成系统崩溃；不建立任何实时连接或循环重试 |

### 2.4 全局数据协议（🟦【建议默认值】以版本化 OpenAPI 为准）

> 本节是 5.1 节规则的契约化表达，也是三章各页 DTO 规格的公共约定。所有字段名为**冻结候选**，最终以版本化 OpenAPI 与标准错误协议为准。

#### 2.4.1 响应信封

```json
// 成功：{ "data": <资源或对象>, "meta": { ... } }
// 列表类 data 为 { items: [...] } 对象，meta 至少含 next_cursor（无下一页时为 null）
// 失败（RFC 7807 Problem Details）：
// { "type": "...", "title": "...", "status": 4xx|5xx, "detail": "可读摘要",
//   "code": "STABLE_CODE", "request_id": "...", "retryable": true|false }
```

- 前端只读 `data` / `meta`；分页仅从 `meta.next_cursor` 取下一页。
- 错误展示使用稳定错误码 + 可读摘要（title/detail）+ 请求标识；不得展示内部堆栈、Token、密钥或 Provider 原始异常。稳定错误码全集见后端方案 §2.6 统一错误码总表。

#### 2.4.2 公共枚举

| 枚举 | 取值 | 说明 |
|------|------|------|
| market | `US` / `KR` / `CN` | 接口定义的市场枚举，前端不允许扩展 |
| freshness_status | `FRESH` / `STALE` / `UNAVAILABLE` | 数据新鲜度（覆盖最近收盘日 / 落后但有快照 / 无可展示时序），语义见 3.1.3.4 |
| market_session_status | `OPEN` / `CLOSED` | 开闭市状态，与 freshness_status 正交；CLOSED 时附 market_closed_reason |
| task_status | `PENDING` / `QUEUED` / `RUNNING` / `RETRYING` / `SUCCEEDED` / `FAILED` / `CANCELLED` / `CANCEL_REQUESTED` | 任务正式状态，状态机见 3.5.3 |
| report_block | `market` / `sector` / `stock` / `decision` | 报告区块标识 |
| block_status | `AVAILABLE` / `UNAVAILABLE` / `NOT_REQUESTED` | 报告区块状态 |
| window_type | `pre_event_5d` / `event_day` / `post_event_5d` | 事件研究预测窗口 |
| task_type | `SINGLE_STOCK` / `MARKET_WIDE` | 任务类型（OpenAPI 枚举） |
| interval | `"1d"`（首期） | K 线周期，取值受资产 supported_intervals 约束 |

#### 2.4.3 幂等键

- 创建任务请求头携带 `Idempotency-Key`（UUID，前端生成），不放入请求 body。
- **同一表单会话（未修改任何输入）内**的重复提交/网络超时重试复用同一键，服务端返回同一任务，不产生重复任务。
- 用户修改任一输入后，前端重新生成新键（视为新意图）。

#### 2.4.4 Cursor 分页

- 追加下一页时保持服务端稳定排序；前端不拼接、不修改游标。
- `meta.next_cursor == null` 时不展示"加载更多"。
- 下一页加载失败时保留已成功加载的页，仅对失败页提供重试。

## 三、详细页面需求

### 3.1 大盘页面（/market）

#### 3.1.1 页面职责

大盘页在同一滚动页面按 **市场（宏观指数）→ 板块（热门概念）→ 信息（宏观信息）** 的固定顺序直接呈现后端准备好的市场读模型，不提供页内 Tab 或视图切换。三个区块独立加载和反馈，任一区块加载、空态或失败均不得阻塞其他区块的展示。页面不维护指数名单、不计算热点、不抓取新闻，也不把其他页面的数据作为大盘数据来源。

#### 3.1.2 页面级元素与交互

| UI 元素 | 说明 | 交互行为 | 操作后结果/边界处理 |
|---------|------|----------|---------------------|
| 页面标题-大盘 | 标识当前一级页面 | — | — |
| 市场区块标题 | 标识宏观指数区域 | — | 页面加载时直接展示在首个固定区块，不通过页内导航进入 |
| 板块区块标题 | 标识热门概念区域 | — | 页面加载时直接展示在市场区块之后，不通过页内导航进入 |
| 信息区块标题 | 标识宏观信息区域 | — | 页面加载时直接展示在板块区块之后，不通过页内导航进入 |

##### 3.1.3.4 新鲜度状态机（🟦【建议默认值】）

| 维度 | 状态 | 判定（服务端读模型） | 前端展示 |
|------|------|------------------|----------|
| freshness_status | FRESH | 读模型已覆盖该市场最近一个已收盘交易日 | 正常展示快照与更新时间 |
| freshness_status | STALE | 落后最近收盘日，但仍有最后成功快照 | 保留最近成功快照 + "数据可能延迟"标注 + 源更新时间 |
| freshness_status | UNAVAILABLE | 没有可展示时序 | 不可用状态；上游故障时按 503 可重试错误处理 |
| market_session_status | OPEN | 按市场时区与交易日历当前处于交易时段 | 正常展示 |
| market_session_status | CLOSED | 当前不在交易时段（未开盘/已收盘/休市日） | 展示最近闭市快照 + 闭市状态与休市原因（market_closed_reason） |

freshness_status 与 market_session_status 正交：休市日的收盘数据可以是 FRESH（已覆盖最近收盘日）。判定一律以服务端读模型为准；前端不得自行按时间推算新鲜度或开闭市。

### 3.3 AI 投研看板（/ai）

#### 3.3.1 页面职责与信息层级

**生成与渲染规则**：

1. **结论摘要/风险标记的生成时机**：任务成功时由后端**报告读模型**生成 conclusion_summary 与 risk_flag/risk_hint 并落库；看板接口只读不现场解析报告正文（保证看板接口性能与报告正文解耦）。

4. **看板不建立 SSE**：状态只来源于本摘要 API；任务详情页才订阅进度（与 3.3.2 一致）。

### 3.5 AI 任务详情与最新报告（/ai/tasks/:taskId）

#### 3.5.1 页面职责

任务详情是运行任务的唯一标准 URL，也是成功任务阅读最新结构化报告的唯一页面。无论用户由创建成功跳转、刷新页面、浏览器前进/后退，还是直接粘贴 URL，页面均先读取任务正式状态，再决定是否订阅进度或使用定时查询回退；仅当状态为 SUCCEEDED 时，在同页加载最新报告。首期不支持报告版本切换，也不提供独立报告路由。

#### 3.5.2 页面元素与交互

| UI 元素 | 说明 | 交互行为 | 操作后结果/边界处理 |
|---------|------|----------|---------------------|
| 任务标识 | 任务 ID、任务类型、目标标的（如有） | — | 用于定位当前任务；不展示请求幂等键、租约、内部路径或完整请求敏感信息 |

| 取消任务按钮 | 对尚未结束的任务发起协作式取消 | 点击 → 提交取消请求 | 点击后显示"取消请求中"；最终以服务端 CANCELLED 或其他正式状态为准；重复取消幂等显示当前状态 |

🟦 重连/回退参数（建议默认值）：SSE 重连采用 1s 起指数退避（1s/2s/4s/8s…，上限 30s），连续 5 次失败转 5s REST 定时查询；时间线最多保留 50 条事件（超出丢弃最早，不伪造"完整历史"）；任务达到终态或离开页面/切换任务时停止全部连接与计时。

#### 3.5.3 任务状态机与用户可见行为

🟦 状态迁移（建议默认值，作为任务正式状态契约冻结候选）：

```
            ┌───────── 可重试错误（attempt + 1）─────────┐
            ▼                                             │
PENDING → QUEUED → RUNNING ──┬── SUCCEEDED（成功，最新报告已保存）
                             ├── FAILED（不可重试错误或重试耗尽）
                             └── RETRYING ──(重新投递)──→ QUEUED
任意非终态 ── 用户取消/服务端收口 ──→ CANCEL_REQUESTED → CANCELLED
```

- 终态 = SUCCEEDED / FAILED / CANCELLED，不可再迁移；取消为协作式：不承诺立即停止，取消请求送达前任务可能已完成并收口为 SUCCEEDED/FAILED（存在竞争窗口），最终以服务端正式状态为准。
- attempt 在每次重新投递时 +1；SSE 事件携带 attempt_no，仅用于展示。

| 正式状态/事件 | 用户看到的含义 | 页面行为 |
|---------------|----------------|----------|
| PENDING | 请求已受理，等待确认投递 | 显示等待状态；任务仍可读取，非终态时进入进度观察 |
| QUEUED / queued | 当前 attempt 已进入执行队列 | 状态卡显示排队中，时间线追加排队节点 |
| RUNNING / started | Worker 已开始执行 | 状态卡显示运行中，时间线追加开始节点 |
| progress | 市场层、板块层、个股层等稳定阶段进展 | 时间线追加阶段消息；不解析日志文本伪造更细粒度步骤 |
| RETRYING | 当前 attempt 遇到可重试问题，下一 attempt 正在等待 | 状态卡显示重试中、当前 attempt 和下次时间；时间线不伪造"失败"或"重试"事件 |
| completed / SUCCEEDED | 分析成功，最新报告已保存 | 停止进度连接，刷新任务/报告数据，并在当前详情页加载最新报告 |
| failed / FAILED | 不可重试错误或重试耗尽，任务失败 | 停止进度连接，展示错误摘要和返回/重新发起分析入口 |
| cancelled / CANCELLED | 任务已取消 | 停止进度连接，展示取消结果；可返回投研看板重新发起分析或返回任务中心继续查找 |
| CANCEL_REQUESTED | 已提交取消请求，等待 Worker 或服务端收口 | 显示取消请求中；不能承诺立即停止正在进行的外部调用 |

#### 3.5.4 SSE 进度事件协议（🟦【建议默认值】）

订阅端点：`GET /api/v1/analysis-tasks/{taskId}/events?after=<streamId>`（SSE）。wire 格式为 SSE 标准 `id / event / data`：六种业务事件（queued / started / progress / completed / failed / cancelled）持久化到 Redis Stream 并携带 id；reset / heartbeat 为控制事件，无 id、不持久化。data 为 JSON payload，字段映射：

| payload 字段 | 类型 | 说明 | 与本页旧视图的对应 |
|------|------|------|--------------------|
| task_id | string | 任务 ID | — |
| attempt_no | int | 事件所属 attempt | attempt |
| occurred_at | datetime | 事件时间 | ts |
| schema_version | string | 字面量 "v1" | — |
| sequence | int? | progress 时严格递增的业务序号 | seq |
| phase | enum? | progress 时的稳定阶段：market / sector / stock / decision（另有 queue/finish 等图阶段以既有回调为准） | stage |
| message | string? | 阶段进度文案（仅展示服务端给出的合法文案） | message |
| worker_id | string? | started 时携带 | — |
| report_id / duration_ms | — | completed 时携带 | — |
| error_code / message | — | failed 时携带（不可含 retryable=true） | — |

控制事件：`heartbeat`（无 id，data 固定为 {connection_id, sent_at, schema_version}，服务端空闲保活约 30s 一条）；`reset`（无 id，data 固定为 {task_url, earliest_event_id, occurred_at, schema_version}，游标早于保留窗口时发送一次后关闭连接）。

处理规则：

- **去重与乱序**：仅接受 Stream ID 严格递增业务事件；旧事件不改变当前页面状态；重复事件丢弃。
- **合法性校验**：事件内 task_id 与 URL 不匹配、schema_version 不支持或结构不合法 → **立即停止该连接、不写入时间线/游标**，重新读取任务；任务仍未结束时转为 REST 回退。
- **reset**：收到 reset 后清空本地进度窗口，重新读取任务；若未结束则使用 REST 定时查询，不把残缺历史展示为完整记录。
- **heartbeat**：服务端约 30s 空闲保活；客户端超时判定（建议 45s 无任何事件）按断连处理进入重连/回退。
- **终态收口**：任务已终态但末事件缺失时以任务正式状态为准，不阻塞用户查看最终状态。

#### 3.5.5 异常与恢复规则

| 场景 | 处理要求 |
|------|----------|
| 刷新、直接访问或浏览器历史导航 | 以 URL 中 taskId 重新获取任务；非终态才订阅实时进度，不能依赖前页内存状态 |
| 任务不存在（404） | 显示专用资源不存在状态，提供返回 /ai 的入口；不得建立实时连接、无限重试或显示成系统崩溃 |
| 进度事件重复/乱序 | 去重并仅接收严格递增的业务事件；旧事件不改变当前页面状态 |
| 事件协议不合法、任务 ID 不匹配、版本不支持 | 立即停止该实时连接、不写入时间线/游标，重新读取任务；任务仍未结束时转为 REST 回退 |
| 事件保留窗口已过 | 收到 reset 后清空本地进度窗口，重新读取任务；若未结束则使用 REST 定时查询，不展示残缺历史为完整记录 |
| 网络连接连续失败 | 按受控退避重连，达到阈值后使用 5 秒 REST 查询；任务结束、切换任务或离开页面时停止所有连接和计时 |
| REST 定时查询单次失败 | 显示可重试反馈但保持后续固定间隔查询，不叠加并行请求 |
| 任务已终态但进度末事件缺失 | 以任务正式状态为准，不阻塞用户查看最终状态；服务端可补写规范终态事件 |

#### 3.5.6 最新报告区块状态与边界

| 区块状态/场景 | 页面展示与处理 |
|---------------|----------------|
| AVAILABLE | 渲染该区块的结构化内容、图表或卡片；用户可阅读、展开长文本、查看图表。 |

| window_type | enum | 否 | post_event_5d | pre_event_5d / event_day / post_event_5d |
| event_type | string? | 否 | — | 模板标签 |
| event_subtype | string? | 否 | — | 模板标签 |
| event_condition | string? | 否 | — | 模板标签 |
| save | bool | 否 | false | true 时预测落库供事后追踪，不改变返回 |
| event_id | int? | 否 | — | 关联事件 ID（save=true 时可选） |

**响应** `200`：

| 字段 | 类型 | 说明 |
|------|------|------|
| data.prediction.direction | enum | up / down / neutral（服务端判定，前端仅映射文案） |
| data.prediction.predicted_return | number? | 预测收益（CAR）；无样本时为 null |
| data.prediction.confidence | number | 0~1 置信度 |
| data.template_stats.sample_count / avg_car / win_rate | int / number? / number? | 模板匹配统计；无样本时 avg_car/win_rate 为 null |
| data.supplement_events | array | 相似历史事件：[{event_id, title, similarity, weight}]，模板/补充分开报告 |
| data.note | string? | 服务端说明（如"事件库暂无相似事件"），原样展示 |

**资产清单**（已确认新增）：`GET /api/v1/event-studies/assets` → items: [{ticker, name, market}]（首期为事件研究系统已初始化的 4 个 CN 指数：上证指数 000001.SH / 科创50 000688.SH / 科创100 000698.SH / 沪深300 000300.SH）。接口缺失时前端保留自由输入，不硬编码名单。

**错误映射**：`VALIDATION_ERROR`（422，窗口非法/文本超长，字段级提示）；`EVENT_STUDY_BUSY`（503，可重试，仅手动）；`EVENT_STUDY_TIMEOUT`（504，可重试，仅手动）；`EVENT_STUDY_INTERNAL`（500，不可重试，展示脱敏摘要）。

#### 3.6.4 预测异常处理

| 场景 | 页面行为 |
|------|----------|
| 表单校验失败 | 在对应字段显示提示，保留全部已输入内容，不发起请求 |
| 预测成功 | 保留表单输入，在结果区域展示最新一次结果 |
| 503 EVENT_STUDY_BUSY | 提示"事件研究请求繁忙，请稍后重试"，保留输入，仅允许用户手动重试，不自动重试 |
| 504 EVENT_STUDY_TIMEOUT | 提示本次等待超时并保留输入，允许用户手动重试；不能暗示后端计算一定已经停止 |
| 其他可重试错误 | 展示可读错误和重试入口，保留输入 |
| 不可重试错误 | 展示服务端错误摘要，保留输入以供用户修改；不自动连续提交 |
| 结果为空/样本不足 | 作为正常业务结果显示服务端说明（note）；不从前端生成预测结论 |

### 4.1 路由跳转矩阵

### 4.2 核心用户流程

**流程 A：从自选标的发起分析（全市场调研）**

```
自选页选择分组 → 选择标的 → 点击"AI 分析"
  → AI 投研看板打开创建任务面板（恒为全市场调研）
  → 确认请求交易日与层级（市场/板块/筛选固定，仓位可选）→ 提交分析 → 跳转任务详情
  → 查看排队/运行/阶段进度
  → 成功后在当前任务详情页阅读最新报告
```

关键约束：新建分析恒为全市场调研（无目标标的输入）；入口不会绕过表单校验或直接创建任务；用户仍需确认完整分析范围。

**流程 B：全市场分析与可重试过程**

```
AI 投研看板点击"新建分析"并选择"全市场分析"
  → 选择市场、板块、筛选条件及市场/板块/筛选层级
  → （如需仓位）同时选择筛选层级
  → 提交 → 任务详情显示 PENDING/QUEUED/RUNNING
  → 可重试异常时显示 RETRYING 和新的 attempt
  → 新 attempt 重新排队并继续进度
  → 成功后在当前任务详情页加载报告，或失败后查看错误摘要并返回 AI 投研看板重新创建任务
```

关键约束：可重试不是失败终态；用户不需要重新提交原任务，页面以任务详情的正式状态为准。

**流程 C：维护本地组合**

```
自选页 → 新建或选择组合 → 新增/修改持仓数量和平均成本
  → 保存并刷新服务端持仓
  → 发生 revision 冲突时重新读取最新持仓
  → 用户基于最新数据再次操作
```

关键约束：不做客户端静默合并、乐观排序或以 AI 建议覆盖人工持仓。

**流程 D：从宏观信息进入事件研究**

```
大盘-信息区块 → 浏览已审核宏观信息
  → 点击信息标题 → 跳转事件研究页面（🟦 按 Q-03 预填输入草稿）
  → 输入/确认预测参数 → 手动提交预测
  → 当前页展示方向、CAR、样本数和相似事件
```

关键约束：信息卡片不能直接把预测结果或报告文本当作宏观信息来源；预填仅为输入草稿，不自动提交。

**流程 E：处理待处理事项（失败任务与报告不可用区块）**

```
AI 投研看板-待我处理区
  → 失败事项 → 任务详情阅读错误摘要 → 返回看板新建分析（新任务，不重试原任务）
  → 报告不可用事项 → 任务详情定位对应报告区块 → 查看原因（可重试则手动重试报告读取）
     → 仍不可用 → 返回看板以包含该层级的新任务重新分析
```

关键约束：失败任务不提供"重试原任务"入口——系统级可重试由 RETRYING 自动处理；用户动作是创建新任务。

### 4.3 全局状态与持久化边界（🟦【建议默认值】）

| 类别 | 内容 | 持久化方式 |
|------|------|------------|
| 本机偏好 | 明/暗主题、侧栏折叠状态 | localStorage，跨会话保留 |
| 会话内筛选 | 大盘三区块筛选、自选当前分组/组合选择 | 路由切换保留（页面级状态），刷新后以 URL/默认值重建 |
| URL 承载 | create=1&ticker、status 筛选、event_id、from 来源页 | 深层链接可直接恢复对应视图 |
| 不持久化 | 创建面板表单、事件研究表单输入（未提交） | 离开页面即丢弃，不承诺跨路由草稿恢复（URL 预填参数除外） |

## 五、通用业务规则与边界条件

### 5.1 数据展示与协议规则

| 规则 | 需求 |
|------|------|
| 数据来源 | 前端只消费版本化 API DTO；不得直接调用 AKShare、Tushare、Python AI 图或读取日志文件 |
| 成功响应 | 所有业务成功响应按 {data, meta} 读取；分页仅从 meta.next_cursor 获取下一页游标 |
| 失败响应 | 使用包含稳定错误码、请求标识和是否可重试属性的标准错误信息；不得展示内部堆栈、Token、密钥或 Provider 原始异常 |
| 列表分页 | 追加下一页时保持服务端返回的稳定排序；不得以 offset、客户端时间或本地排序替代服务端游标 |
| 加载/空/错误 | 每一个独立数据区域都必须区分加载中、正常空态、可重试错误、不可重试错误和成功展示，不能将它们混为"暂无数据" |
| 敏感信息 | 页面、浏览器存储和 URL 中不得保存 API Key、Provider Token、密码、完整内部异常、租约或本地绝对路径 |
| 契约一致性 | 前端页面字段、枚举、分页和错误处理以版本化 OpenAPI/标准错误协议为准；三章 DTO 规格均为冻结候选，不手写后端领域 DTO |

### 5.2 市场数据边界

| 场景 | 处理 |
|------|------|
| 资产未启用 | 显示"该资产未启用"或不可用空态，不请求 K 线、不无限重试 |
| 上游行情不可用 | 显示可重试错误，允许用户手动重试；不使用静态数据冒充实时/正式数据 |
| 市场休市 | 显示最近成功快照、闭市状态和闭市原因，不视为系统错误 |
| 数据过期 | 允许展示最近成功快照，但必须明确标注可能延迟和源更新时间 |
| 无可展示时序 | 不绘制空壳或伪造图表，显示不可用状态 |
| 不支持的周期/范围 | 不允许选择不支持周期；范围非法/过大时提示用户调整，不能静默截断 |
| 无热点概念 | 显示正常空态，不作为错误，不以硬编码概念兜底 |
| 无已审核宏观信息 | 显示正常空态，不从预测或报告中拼装替代内容 |

### 5.3 自选和组合并发边界

| 场景 | 处理 |
|------|------|
| 同名分组/组合 | 保留输入并提示名称已存在 |
| 同分组重复标的 | 不插入本地乐观项，提示重复并保留输入 |
| 删除非空分组/组合 | 阻止删除，提示先清空标的/持仓或完成迁移 |
| 标的排序冲突 | 重新读取该分组标的，按服务端顺序渲染；用户可重新操作 |
| 持仓并发冲突 | 重新读取当前组合及持仓，避免本地静默覆盖 |
| 非法持仓 | 数量须大于 0，平均成本须大于等于 0；字段级提示并保留输入 |
| 资源已被删除 | 刷新相关父/子列表并退出已失效上下文；不显示系统崩溃 |

### 5.4 任务与报告边界

| 场景 | 处理 |
|------|------|
| 用户重复点击提交 | 提交中禁用重复操作；同一意图重试复用幂等键 |
| 单股/全市场参数不匹配 | 前端阻止提交并提示；服务端仍做最终校验 |
| 取消运行中任务 | 显示请求中，等待后端最终状态；不能承诺立即中断正在执行的外部调用 |
| 页面刷新或直接访问任务 | 通过 URL 恢复并读取任务正式状态，不依赖旧页面内存 |
| 实时进度断线 | 受控重连失败后改用 REST 定时查询，直至任务终态 |
| 任务失败 | 展示安全的错误摘要；提供返回 AI 投研看板打开创建任务面板重新创建任务，不将失败任务当报告成功 |
| 任务成功但报告区块不可用 | 根据 UNAVAILABLE 显示原因，不将报告整体判为空白或成功内容 |
| 报告未请求区块 | 显示 NOT_REQUESTED 说明；引导以包含该层级的新任务获取内容 |

### 5.5 事件研究边界

| 场景 | 处理 |
|------|------|
| 同步请求时长 | 前端设置请求超时（🟦 建议 45s，大于服务端 30s 超时以优先收到 504 EVENT_STUDY_TIMEOUT），超时按 EVENT_STUDY_TIMEOUT 呈现，不能暗示后端计算已停止 |
| 容量受限（繁忙） | 503 时提示稍后重试，仅用户手动重试，不自动重试、不自动排队 |
| 结果为空/样本不足 | 作为正常业务结果显示服务端说明，不生成前端结论 |
| 资产无历史影响数据 | 提交非目录资产时服务端返回无样本说明（note），前端正常呈现，不阻止提交 |
| 保存选项 | save=true 仅落库供追踪，不改变返回结构与页面展示 |
| 与 AI 任务的关系 | 事件研究不创建分析任务、不进入任务进度时间线；预测结果不伪装成 AI 报告 |

## 六、验收口径

### 6.1 功能验收场景

| 编号 | 验收场景 | 预期结果 |
|------|----------|----------|
| AC-01 | 进入大盘页 | 市场、板块、信息三个固定区块直接同时展示；市场区块指数按 US → KR → CN 分组，组内按服务端 display_order；不出现页内 Tab 或前端静态指数名单 |

## 七、已确认决策与待确认事项

### 7.1 已确认决策

1. 一级导航固定为 **大盘 / 自选 / AI**，不提供登录和账户相关页面。
2. 大盘页固定按 **市场（宏观指数）→ 板块（热门概念）→ 信息（宏观信息）** 的顺序直接展示三个区块，不提供页内视图切换。
3. 宏观资产按 **US → KR → CN** 分组，资产本身、组内顺序与支持周期都由后端资产目录决定。
4. 自选分组和本地组合是两个独立的业务对象；手工持仓不会被 AI 建议自动覆盖。
5. AI 一级入口 /ai 是"AI 投研看板"，按待处理、进行中、最近结论和新建分析组织；它不承担完整历史列表或运行记录功能。
6. 全量任务浏览收敛至 /ai/tasks；列表不接入 SSE，详细运行进度仅在任务详情页展示。
7. AI 任务详情 /ai/tasks/:taskId 是运行任务的标准可恢复地址；最终状态始终以任务 REST 数据为准，并在成功后同页展示最新报告。
8. 报告只读取最新版本，且各区块必须显式区分可用、不可用和未请求；首期不提供独立报告路由或版本切换。
9. 事件研究是选股/个股研究的辅助能力，采用用户手动提交的一次性同步预测；繁忙和超时仅允许用户手动重试。
