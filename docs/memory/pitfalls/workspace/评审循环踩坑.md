# 评审循环踩坑史（评审维度清单的来源）

> 一句话结论：评审多轮不收敛的根因是"初稿留白 + 评审维度缺失 + 修复残留"三类，已分别由前置自检、固定维度清单、同类表述同步三条机制封堵——机制见 CLAUDE.md「方案评审机制」。

## 纯 delta 循环 7 轮才收尾（2026-08-23）

- **根因**：初稿没有把声明级细节一次写全——每条数据流的接续（X 由谁产生、传给哪个参数、最终落到哪个输出）、每个匹配规则的落点（checkpoint dir 第几段对应哪个 expander 标签）、每个测试断言的可构造性（fixture 能否真的造出该场景，注意"恒空公式"这类永远测不到的死路径）都留了猜测空间，每轮 delta 补一点。
- **对策**：声明级细节进前置自检（维度 2/7），写不全不进评审。

## 修复残留 = 下一轮 findings 主要来源（2026-08-23 实测）

- 实测第 2 轮 2 条 findings 全是第 1 轮修复的残留——同一概念在代码草图/决策表/契约/测试清单多处出现，只改了发现处。
- **对策**：修复 findings 时必须同步所有同类表述；且修复不得引入新矛盾——改一个公式/口径时，先推演它与上游来源、下游消费的组合是否仍成立（如"以覆盖日期生成的窗口做差集恒为空"）。

## 元组形状改造必须枚举全量随迁点（2026-09-06，评审 2 轮才收齐）

- **根因**：方案描述"改私有方法返回元组/元素形状"时只写了调用点解包，漏了函数体内部随迁点：失败路径 return 的值个数、按 index 取元素的排序键（头部插字段导致索引整体移位）、函数自身 docstring 的形状描述。
- **后果**：漏任何一类都会让消费侧解包抛 ValueError 或排序静默错序。
- **对策**：评审维度 4「结构改造随迁」全量枚举。

## 方案"现状"描述必须代码事实核对（2026-09-10，市场层方案评审 3 轮才收净）

- **根因**：写方案时的现状/文件路径/既有行为描述凭印象，未 grep 核实——本轮反复发现"按需自主查询"实为固定自动调用（`_load_event_study_data`）、"缺连板梯队/炸板率"实际已有（`get_limit_up_ladder`）、"审核界面是 Streamlit"实已平台化（backend 防腐层）。
- **追加发现**：事件研究相关方案必须同时覆盖 AI 侧与平台侧两条链路（维度 9 的来源）；提示词规则的真实载体是 `AI/utils/prompts.py` 注册表而非 templates/md（md 只是 `{output_format}` 锚点）。
- **对策**：评审维度 1「现状代码事实」+ 维度 9「跨链路覆盖」。

## Code Review 第 2 轮才收净的两类缺陷（2026-09-12，市场层证据驱动改造）

1. **中文枚举子串解析的否定识别必须一次做对双向**——假否定（"非常/无非/未来"等含否定字的复合词被当否定 → 真 high 漏熔断）与漏否定（"并没有偏高"多字否定+填充字 → 反配误熔断）；正确姿势 = 复合词白名单 + 剥一个填充字 + 模式表（并不/没有/尚未…）+ 双重否定抵消，并固化 4 类回归用例（非常X / 并没有偏X / 并非不高 / 无非X）。
2. **共享一个 PG conn 的查询循环/码表探测，每个 except 分支必须 `conn.rollback()`**（自身包 try）——否则 autocommit=False 下事务中毒，后续语句全部 `InFailedSqlTransaction` 被吞成"接口不可用"，整条数据通道静默丢失。

- **对策**：Code Review 前主会话自查这两类高发缺陷（见 CLAUDE.md「Code Review 规则」）。

## 渲染语义边界必须以真实轴 extent 实测锚定（2026-09-14，画线模块评审 4 轮才收净）

- **表象**：§3.6 画线工具 y 裁剪的"夹取目标"连续三轮处方级残留——R1 无 y 裁剪（markLine `containData` 要求两点均在轴范围内，越界整条静默丢弃）→ R2 处方"±5% 缓冲区间"方向用反（缓冲向外扩，端点反而落 extent 外）→ R3 处方"无缓冲 [min(low), max(high)]"留空带（真实 extent 含 BOLL 上/下轨可超 high/low，空带 ~2% 价格，画线被压平渲染成错位线）→ R4 真实 extent（`getModel().getComponent('yAxis', 0).axis.scale.getExtent()`）一次到位。
- **根因**：① 用数据极值近似图表库的渲染语义边界（axis extent / containData / clip），而真实边界只能从库实例读；② 评审处方若含"或"选项（"真实 extent 或 X 近似"）未经逐选项实测就落方案，近似选项即下一轮残留。
- **正确姿势**：① 方案中任何"渲染边界/裁剪语义"必须写死读取路径（真实 extent）+ 实测锚定结论（含边界严格包含：恰等于边界出图、+1e-9 即整条丢弃）；② 评审处方落地后，处方涉及的新机制（读取时序、两路径衔接、测试 mock 面）同步进验证清单，否则机制无断言锚点。
- **对策**：评审维度 8 扩充"图表渲染语义边界（clip/containData/轴 extent 等）必须以真实轴 extent 实测锚定，禁止数据极值近似"（2026-09-14 起）。
