## 一、背景与动机

### 1.1、现状

事件研究已有审核界面，但它是独立 Streamlit 应用，不在平台（React 前端 + FastAPI 后端）内：

- **审核界面本体**：[AI/eventStudy/review/review_app.py](AI/eventStudy/review/review_app.py)——`streamlit run` 单独起进程，直连 PG + Redis，两个 Tab：①待审核事件（批量可编辑表格：类型/子类型/关键条件/重要性/操作=通过/忽略/跳过，默认值来自 AI 预填）；②影响结果确认（资产×窗口勾选落表）。
- **审核数据层**：[AI/eventStudy/review/review_dao.py](AI/eventStudy/review/review_dao.py)——同步、PG conn 注入式函数：`get_pending_events / get_pending_event / approve_event / ignore_event / get_impact_drafts / get_event_title / confirm_impacts`。草稿在 Redis（`events:pending:{draft_id}`、`event_impacts:draft:{event_id}`），审核终态写 PG（`events`、`event_impacts` 表），审核日志 LPUSH Redis `event_review_log`。
- **AI 预填**：[AI/eventStudy/review/ai_prelabel.py](AI/eventStudy/review/ai_prelabel.py)——`prelabel_events(drafts) -> int`，quick 模型分类写回草稿 `ai_suggestions`，幂等。
- **平台后端现状**：`backend/api/routers/event_studies.py` 只有 `POST /api/v1/event-studies/predictions`、`GET /api/v1/event-studies/assets` 两个端点；`backend/modules/event_study/` 只包装预测路径（`EventStudyAdapter` 在有界线程池调 AI 侧 predictor）。**全仓 grep 无任何审核端点**。
- **平台前端现状**：`frontend/src/modules/event-study/pages/` 只有预测页（AiEventStudyPage / PredictionForm / PredictionResultPanel），大盘页「宏观信息」区块只消费已审核数据。**无任何审核页面**。
- **可观测问题**：审核是事件研究流水线的必经环节（爬虫草稿 → 人工审核 → PG → 影响计算），但审核界面游离于平台之外——需单独起一个 Streamlit 进程、单独访问端口，且 Streamlit 版数值三列（预期/实际/前值）不可编辑（改数值要去 Adminer 手动改库）、operator 恒为 "admin"、批量提交无事务毒化防护。

### 1.2、目标

- 把审核界面的两个 Tab 集成进平台：FastAPI 新增审核 API + React 新增审核页面，`/ai/event-study/review` 可从 AI 工作台入口进入。
- **行为对齐 Streamlit 版**（见 3.1.1「行为对齐表」列出的 3 处有意偏差除外）。
- **AI 侧零改动**：review_dao / ai_prelabel / compute_all_windows / collector / daily_job 全部复用，`tests/event_study/test_review_regressions.py`、`test_ai_prelabel.py` 继续守护同一实现。
- 无新数据库表、无新迁移；无新第三方依赖。

## 二、架构设计

```
爬虫/daily_job（AI 侧，既有）
  │ 写 Redis 草稿 events:pending:{draft_id}（30 天 TTL）
  ▼
平台后端（新增）
  EventStudyReviewService（同步，经 analysis_services.run() 线程池执行）
    └─ EventStudyReviewAdapter（防腐层）→ 复用 AI 侧 review_dao / ai_prelabel /
       compute_all_windows（PG 连接走 AI 侧 get_connection()，Redis 走 AI 侧 config 全局单例）
  ▲
React 审核页 /ai/event-study/review
  Tab1 待审核事件（批量编辑 + 分块提交 + AI 预填循环）
  Tab2 影响结果确认（勾选 → 按事件分组确认落表）
  ▼
PG：events（approved/ignored）、event_impacts（人工确认的正式记录）
Redis：草稿删除、event_review_log 审核日志
```

### 2.1 数据模型设计

**不改变任何表结构与 Redis key 约定**（无迁移）。审核 API 读写全部沿用既有结构：

**Redis 待审草稿** `events:pending:{draft_id}`（String，JSON，TTL 30 天，`PENDING_DRAFT_TTL`）：

| 字段 | 类型 | 写入者 | 说明 |
|---|---|---|---|
| title | str | 爬虫 | 快讯标题，必填；写 PG 时 `draft.get("title", "")` |
| content | str | 爬虫 | 快讯正文，可空 |
| source_url | str | 爬虫 | 官方原文链接，审核时核对用 |
| announced_at | str | 爬虫 | ISO8601 字符串，统一转 +08:00，如 `"2026-08-01T09:00:00+08:00"` |
| importance_hint | int\|null | 爬虫 | 来源星级（财联社 A/B/C→5/4/3），多数为空，靠人工审核填 |
| source | str | 爬虫 | 来源名，如 `"金十数据"` |
| draft_id | int | 爬虫 | 如 `42`，`events:draft_seq` INCR 分配；读时从 key 后缀解析 |
| ai_suggestions | dict\|无 | ai_prelabel | 见下。**预填写回用 `r.set(...)` 不带 ex，会清除草稿既有 TTL（AI 侧既有行为，本次不改）** |

**ai_suggestions**（AI 预填写回草稿的字段）：`event_type`（7 类：宏观数据/央行/地缘/产业政策/公司/市场行情/其他）、`event_subtype`、`event_condition`（超预期/符合预期/低于预期/利好/利空/中性）、`importance`（int 1-5）、`expected_value` / `actual_value` / `previous_value`（float 或 null；原文未明确提数字一律 null）。

**Redis 影响草稿** `event_impacts:draft:{event_id}`（String，JSON，TTL 7 天，`IMPACT_DRAFT_TTL`）：

```json
{"event_id": 7, "t0": "2026-08-03", "computed_at": "2026-08-04T08:31:02.123456",
 "assets": {"000001.SH": {"pre_event_5d": {"window_days": 5, "cumulative_abnormal_return": 0.012345,
     "t_stat": 2.1534, "direction": 1, "is_contaminated": false, "error": null}, ...}}}
```

- 资产 = 4 个目标指数（000001.SH/000688.SH/000698.SH/000300.SH）；窗口 = `WINDOW_TYPES = ("pre_event_5d", "event_day", "post_event_5d")`；`error` 非 None 的窗口确认时跳过（daily_job 兜底重算）。

**PG 写入列**（表结构归 [AI/eventStudy/db/schema.sql](AI/eventStudy/db/schema.sql) 管，不新增列）：
- `events`（approve/ignore 各写一次）：`title, content, event_type, event_subtype, event_condition, announced_at, expected_value, actual_value, previous_value, importance, status, source_url`，`RETURNING event_id`；`status` 仅 `'approved'`（进入影响计算）或 `'ignored'`（仅供爬虫标题去重）；`trading_day`/`surprise` 由 compute_all_windows 补写，`embedding` 由 vectorizer 补写。
- `event_impacts`（confirm 写入）：`event_id, asset_id, window_type, window_days, cumulative_abnormal_return, t_stat, direction, is_contaminated`，`ON CONFLICT (event_id, asset_id, window_type) DO NOTHING`。

**审核日志** `event_review_log`（List，LPUSH JSON，无 TTL）：`{"event_ref": "42", "operator": "admin", "time": "2026-08-19T09:15:30.123456", "action": "approve|ignore|confirm_impacts", "changed_fields": {...}}`。

## 三、详细设计

### 3.1 后端审核 API

#### 3.1.1 模块设计

**已定决策（7 项）**：

1. **复用 review_dao 全部函数（零改动）**，平台侧只写防腐适配层。理由：行为平价（数值 0 合法性兜底、`ON CONFLICT ... DO NOTHING`、日志格式、草稿删除时机等微妙语义已由 `tests/event_study/test_review_regressions.py` 守护）；backend 依赖 AI 包是既有模式（EventStudyAdapter 先例）；草稿生产者用 AI 侧配置写 Redis，审核读同一配置保证「读到==写出」。
2. **批量接口内联 compute**：approve 成功即在同一 conn 上调 `compute_all_windows(conn, event_id)`；compute 失败仅记 `compute_status="failed"`，不失败该行（daily_job 步骤 6 兜底）。另设独立补算端点（见端点 4）覆盖即时失败不等到次日。
3. **AI 预填端点**：`POST /prelabel` 幂等，前端循环调用至 remaining=0。
4. **数值三列（预期/实际/前值）在 React 端可编辑**（后端 `_insert_event` 本就接受这三个字段），默认值取 `ai_suggestions`。**语义定死：清空 = 该字段不落值（PG NULL）**。已核实：爬虫 `_normalize` 从不写草稿顶层数值字段、`ai_prelabel` 只写 `ai_suggestions`——`_insert_event` 第 78-84 行的「草稿顶层回退」对真实草稿恒取到 None，故显式提交 null 的落库结果就是 NULL（与预期列现状一致）。UI caption 与 mappers 测试按此语义固化。
5. **Skip 保持纯 UI 概念**：不提交该行即可，后端不加 skip 端点。
6. **无迁移**：events/event_impacts 归 schema.sql 管（同库），日志在 Redis。`test_migrations.py` 两表集不相交断言零改动。
7. **operator 可选字段**：请求体 `operator?: str = "admin"` 透传 review_dao 写入日志（平台无认证，与现状一致）。

**端点清单**（router：`backend/api/routers/event_study_review.py`，`APIRouter(prefix="/api/v1/event-studies/review", tags=["event-studies"])`——同 tag 使 openapi-typescript-codegen 并入既有 `EventStudiesService`，前端测试只 mock 一个模块；响应统一 Envelope）：

| # | Method/Path | 请求体 | 响应 `Envelope[T]` | 说明 |
|---|---|---|---|---|

| 2 | `POST /prelabel` | `PrelabelRequest{limit: int = 50, 1..200}` | `PrelabelData{prelabeled: int, remaining: int}` | 幂等；LLM 不可用返回 prelabeled=0 不报错。口径（定死）：服务层先列草稿并**仅取无 `ai_suggestions` 的切片**取前 limit 条 → `adapter.prelabel(切片)` → `prelabeled`=返回值；`remaining`=**执行后**重新列草稿、仍无 `ai_suggestions` 的数量（保证前端循环收敛） |

`submit_batch` 流程（关键实现细节，写死）：
1. **整体预检**：`adapter.redis_available()` 为 False → 抛 `ReviewUpstreamUnavailableError`（整批 503，比逐行报错符合平台错误惯例）。
2. 开一个 conn 贯穿批次（`adapter.open_connection()`，finally close）。
3. 逐行 try/except（**行级失败不失败整批，兑现「部分成功仍 200」**）：
   - **review_fields 构造**：ReviewRowCommand → dict，**仅含非 None 键**（键缺失委托 review_dao 既有默认链：importance → `importance_hint` 或 3；数值键 → 落 NULL）。
   - approve：`adapter.approve(conn, draft_id, fields, operator)`；成功即 `adapter.compute_windows(conn, event_id)`（同 conn，Streamlit 先例）。compute 异常（任何类型）→ 行结果 `ok=True, compute_status="failed"` + `logger.warning`（daily_job 兜底）+ **`conn.rollback()`**（compute 可能留下 aborted 事务毒化后续行）；成功 → `compute_status="ok"`。
   - ignore：`adapter.ignore(conn, draft_id, operator)` → `compute_status="skipped"`。
   - **异常映射**：`ValueError`（草稿不存在/已过期）→ `ok=False, error_code="REVIEW_DRAFT_NOT_FOUND"`；**其余 Exception**（如脏草稿 announced_at 触发的 timestamptz DataError 等 DB 错误）→ `ok=False, error_code="REVIEW_ROW_FAILED"`（行级信息码，不抛 HTTP、不进 `_CODE_MAP`）；**任何失败路径统一 `conn.rollback()` 后继续下一行**（修复 Streamlit 版事务毒化后整批失败的隐患，store 包踩坑先例）。
4. 汇总 `ReviewBatchResult`。

`infrastructure/review_adapter.py`（防腐层，包 AI 侧函数；PG 连接用 `AI.eventStudy.db.connection.get_connection()`——EventStudyAdapter 同款先例；Redis 用 AI 侧 `config.get_redis_client()` 全局单例——**刻意与草稿生产者同配置**）：

```python
class EventStudyReviewAdapter:

    def redis_available(self) -> bool: ...    # review_dao.is_redis_available()
    def list_pending_events(self) -> list[dict]           # review_dao.get_pending_events()
    def approve(self, conn, draft_id, fields, operator) -> int   # review_dao.approve_event
    def ignore(self, conn, draft_id, operator) -> int            # review_dao.ignore_event
    def compute_windows(self, conn, event_id) -> None    # event_study.compute_all_windows
    def prelabel(self, drafts: list[dict]) -> int        # ai_prelabel.prelabel_events
    def list_impact_drafts(self) -> list[dict]           # review_dao.get_impact_drafts()
    def event_title(self, conn, event_id) -> str         # review_dao.get_event_title
```

**行为对齐表**（Streamlit 版 vs 平台版，逐条标注）：

| 行为 | Streamlit 版 | 平台版 | 备注 |
|---|---|---|---|
| Redis 不可用列草稿 | 空列表 + 页面横幅 | 503 `REVIEW_UPSTREAM_UNAVAILABLE` | 有意偏差：平台错误惯例；前端渲染错误横幅 |
| 批量提交事务 | 无 rollback 防护，一行失败可能毒化后续行 | 行级捕获 Exception + 失败路径统一 rollback 后继续；行级失败（含 DB 错误）映射 ok=false 不失败整批 | 有意改进（修隐患） |
| 数值三列 | 不可编辑，改值去 Adminer | 可编辑 Input，默认值取 ai_suggestions；清空 = 不落值（NULL） | 有意改进 |
| approve 后影响计算 | 同 conn 立即 compute，失败 st.warning | 同 conn 立即 compute，失败 `compute_status="failed"` | 对齐 |
| 二次确认 | 表格下方 checkbox | ConfirmDialog | 对齐（交互形式不同） |
| operator | 恒 "admin" | 默认 "admin"，请求体可覆盖 | 对齐 |

**接线与门禁**：
