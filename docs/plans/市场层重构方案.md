## 一、背景与动机

### 1.1 现状

- [市场层.md](../市场层.md) 规划了 `MacroMarketAnalyst → HistoricalCaseAnalyst` 两阶段串行结构，**但未实现**
- 当前整个系统只有一个单体 StateGraph，市场层、个股层、辩论、风控全混在一个图里
- 当前 `market_analyst.py` 本质是**个股技术面分析**（命名有歧义），依赖 ticker
- `tech_market_analyst.py` 覆盖科技/AI 产业链，属于板块+个股层

### 1.2 目标

**架构层面**：将市场层从单体图中拆出，做成**独立的编译子图**（LangGraph subgraph）。这是三层 Subgraph 架构的第一步：

```
顶层 Graph（个股维度）
├── Subgraph: 市场层（本期实现）   ← 独立编译，共享 state
├── Subgraph: 板块层（后续）       ← 预留占位
└── 个股层 + 辩论 + 风控（现有）    ← 保持现状
```

**市场层内部**：按地域维度组织——

- **Layer 0 — 国际新闻分析**：跨国宏观事件、地缘政治、全球流动性，不归任何单一国家
- **Layer 1 — 各国市场分析**：每个国家 = 新闻 + 技术两个 Analyst，"两面看同一个市场"

核心设计原则：**国家维度可扩展**——新增一个国家只需加两个文件 + 一行配置。

## 二、架构设计

### 2.1 整体结构

```
市场层
├── Layer 0: 国际新闻分析 (Global)
│   └── 跨国宏观事件 + 历史案例类比
│
└── Layer 1: 各国市场分析（可扩展）
    ├── 美国市场 (US)
    │   ├── 美国新闻分析 — 美国宏观数据、政策、财报季等
    │   └── 美国技术分析 — 标普500 / 纳指 / 道指
    ├── 韩国市场 (KR)
    │   ├── 韩国新闻分析 — 韩国政策、出口数据、三星/SK动态等
    │   └── 韩国技术分析 — KOSPI / KOSDAQ
    ├── 中国市场 (CN) ★ 主战场，分析最深
    │   ├── 中国新闻分析 — 资金日历 + 微观结构（IPO/解禁/交割日/两融）
    │   └── 中国技术分析 — 三大指数+科创50 / 涨跌家数 / 北向资金 / 风格因子
    └── [可扩展: JP(日本) / EU(欧洲) / IN(印度) ...]
```

### 2.2 图谱架构

**顶层图**（`setup.py` — 简化后）：

```
START
  → Market Layer (subgraph)    ← 一个节点，内部封装 7 个 Analyst
  → [现有个股层: Social → News → Fundamentals → Stock Tech]
  → Bull ↔ Bear Debate → Research Manager → Trader → Risk → END
```

> - 子图触发条件：`selected_analysts` 中包含 `"market"` 时运行（默认包含），不含时跳过。
>   旧 key `"tech"`（`tech_market_analyst`）被删除——若显式传入旧列表含 `"tech"`，setup.py 自动忽略该 key 并 warn
> - 个股层顺序保持现有：Social → News → Fundamentals → Stock Tech

**市场层子图内部**（`AI/marketAgents/market_layer_graph.py` — 独立编译）：

```
START
  → International News ←→ tools_intl_news  → Msg Clear
  → US News             ←→ tools_us_news    → Msg Clear
  → US Tech             ──→ Msg Clear         (直接边)
  → KR News             ←→ tools_kr_news    → Msg Clear
  → KR Tech             ──→ Msg Clear         (直接边)
  → CN News             ←→ tools_cn_news    → Msg Clear
  → CN Tech             ──→ Msg Clear         (直接边)
  → END
```

> - 子图与父图共享同一个 `AgentState`，子图写入市场层字段，个股层直接读取
> - 子图可独立编译、独立测试（只传 `trade_date` 即可跑）
> - 新增国家只改子图，顶层图无感知
> - 新闻类 Agent: 保留工具循环；技术类 Agent: 直接边

### 2.3 可扩展设计

新增一个国家的约定：

1. `AI/marketAgents/analysts/` 下加两个文件：`<country>_news_analyst.py` + `<country>_tech_analyst.py`
2. `agent_states.py` 加 4 个字段：`<country>_news_report`、`<country>_tech_report` + 2 个 count
3. `agent_utils.py` 的 Toolkit 中加该国专有工具
4. `market_layer_graph.py` 的 `COUNTRIES` 列表中加一行 `"<country>"`
5. 子图内部自动创建节点、ToolNode、路由、Msg Clear，顶层图完全不需要改动

### 2.4 子图实现要点

**新文件**：`AI/marketAgents/market_layer_graph.py`

```python
class MarketLayerGraph:
    """市场层子图，独立编译后被父图作为节点调用"""
    
    COUNTRIES = ["us", "kr", "cn"]  # 加国家只需改这一行
    
    def __init__(self, llm, toolkit, max_tool_calls=3):
        ...
    
    def build(self) -> CompiledGraph:
        """编译并返回市场层子图"""
        workflow = StateGraph(AgentState)
        # 遍历 COUNTRIES 自动创建节点、ToolNode、Msg Clear、边
        ...
        return workflow.compile()
```

**父图集成**（`setup.py` 简化后）：

```python
# 创建子图
market_subgraph = MarketLayerGraph(llm, toolkit).build()

# 父图中作为一个普通节点加入
workflow.add_node("Market Layer", market_subgraph)
workflow.add_edge(START, "Market Layer")
workflow.add_edge("Market Layer", "Social Analyst")  # 接到个股层第一个（现有个股层顺序：Social → News → Fundamentals → Stock Tech）
```

| 字段 | 类型 | 写入者 | 说明 |
|------|------|--------|------|
| `international_news_report` | `str` | Intl News Analyst | 跨国宏观事件 + 历史案例类比 |
| `us_news_report` | `str` | US News Analyst | 美国宏观数据、政策事件 |
| `us_tech_report` | `str` | US Tech Analyst | 标普500/纳指/道指技术面 |

| `*_tool_call_count` | `int` | 对应 Analyst | 各 1 个，共 7 个 |

## 三、各 Agent 详细设计

### 3.1 Layer 0 — 国际新闻分析师 (Global)

**文件**：`AI/marketAgents/analysts/international_news_analyst.py`
**输出字段**：`international_news_report`
**工具循环**：有（多轮获取不同类型数据）

#### 职责

扫描跨国/全球性宏观事件，不归任何单一国家。合并原设计中的"宏观事件驱动层 + 历史案例分析"。

#### 分析内容

- 地缘政治冲突、战乱、重大自然灾害、公共卫生事件
- 全球流动性/利率政策：美联储、欧央行、日央行货币政策基调
- 全球宏观经济数据：美国 CPI/非农、中国 PMI/社融
- 大宗商品/汇率联动：原油、黄金、美元指数
- 历史案例类比：逐事件检索相似历史案例
- 传导链条 + 资金虹吸提示
- 系统性风险评估

#### 工具

| 工具函数 | 用途 |
|----------|------|
| `get_global_macro_news(curr_date)` | 全球宏观财经新闻（AKShare 财联社电报，获取近期固定窗口，curr_date 用于日志/缓存 key） |
| `get_central_bank_calendar(curr_date)` | 主要央行利率决议日历 |
| `get_macro_indicators(curr_date)` | 关键宏观指标最新值 |
| `get_commodity_fx_overview(days=10)` | 大宗商品+汇率概览 |
| `get_event_calendar_history(events_desc)` | 历史案例检索（静态 JSON） |

- 上证综指、深证成指、创业板指、科创50
- 工具：扩展 `get_china_market_overview`（加入科创50 `000688.SH`）

**B. 市场宽度（情绪温度计）**
- 涨跌家数比、涨停/跌停家数统计

**C. 资金流向**
- 北向资金净流入（标注 2024-08-16 起不再披露盘中实时数据）
- 主力资金净流入

- 大盘 vs 小盘：上证50 vs 中证1000 相对强弱

- 实现：扩展 `get_china_market_overview` 到 7 个指数（加入上证50、中证1000、红利指数），LLM prompt 做定性对比

> **注意**：AI 产业链板块分析（`get_ai_industry_chain`、`get_tech_correlation_analysis`）不放在市场层，归属板块层（SectorAnalyst）——市场层只负责大盘环境，板块层负责行业/概念纵深。

## 六、market_layer_graph.py 可扩展设计（位于 `AI/marketAgents/`）

```python
class MarketLayerGraph:
    """市场层子图：独立编译后作为父图的一个节点"""
    
    # ★ 新增国家只需在这里加一行 ★
    COUNTRIES = ["us", "kr", "cn"]
    
    LABELS = {
        "intl_news": "International News",
        "us_news": "US News", "us_tech": "US Tech",
        "kr_news": "KR News", "kr_tech": "KR Tech",
        "cn_news": "CN News", "cn_tech": "CN Tech",
    }
    
    # 新闻类 = 工具循环，技术类 = 直接边
    LOOP_KEYS = {"intl_news", "us_news", "kr_news", "cn_news"}
    
    # 每个 key 对应的工具列表
    TOOL_MAP = {
        "intl_news": ["get_global_macro_news", "get_central_bank_calendar",
                       "get_macro_indicators", "get_commodity_fx_overview",
                       "get_event_calendar_history"],
        "us_news":    ["get_us_macro_news", "get_us_economic_calendar", "get_vix_index"],
        # 注：技术类 key (us_tech, kr_tech, cn_tech) 不在此列表——它们用直接边，
        # 工具调用在 Agent 节点内部通过 bind_tools + inline invoke 完成（参考现有 tech_market_analyst 模式）
        "us_news":    ["get_us_macro_news", "get_us_economic_calendar", "get_vix_index"],
        "kr_news":    ["get_kr_macro_news", "get_kr_export_data"],
        "cn_news":    ["get_ipo_calendar", "get_share_unlock_calendar",
                       "get_futures_expiry_calendar", "get_margin_trading_balance"],
    }
    
    def __init__(self, llm, toolkit, max_tool_calls=3):
        self.llm = llm
        self.toolkit = toolkit
        self.max_tool_calls = max_tool_calls
    
    def build(self) -> CompiledGraph:
        workflow = StateGraph(AgentState)
        
        all_keys = ["intl_news"] + [
            f"{c}_{t}" for c in self.COUNTRIES for t in ("news", "tech")
        ]
        
        for key in all_keys:
            label = self.LABELS[key]
            # 1. 创建 Analyst 节点
            factory = self._get_factory(key)
            workflow.add_node(f"{label} Analyst", factory(self.llm, self.toolkit))
            # 2. 创建 Msg Clear 节点
            workflow.add_node(f"Msg Clear {label}", create_msg_delete())
            # 3. 新闻类额外创建 ToolNode + 条件边
            if key in self.LOOP_KEYS:
                tools = [getattr(self.toolkit, t) for t in self.TOOL_MAP[key]]
                workflow.add_node(f"tools_{key}", ToolNode(tools))
                workflow.add_conditional_edges(
                    f"{label} Analyst",
                    self._make_router(key),
                    {f"tools_{key}": f"tools_{key}", f"Msg Clear {label}": f"Msg Clear {label}"}
                )
                workflow.add_edge(f"tools_{key}", f"{label} Analyst")
            else:
                # 技术类：直接边
                workflow.add_edge(f"{label} Analyst", f"Msg Clear {label}")
        
        # 串行连接所有节点
        workflow.add_edge(START, f"{self.LABELS[all_keys[0]]} Analyst")
        for i in range(len(all_keys) - 1):
            src = f"Msg Clear {self.LABELS[all_keys[i]]}"
            dst = f"{self.LABELS[all_keys[i+1]]} Analyst"
            workflow.add_edge(src, dst)
        workflow.add_edge(f"Msg Clear {self.LABELS[all_keys[-1]]}", END)
        
        return workflow.compile()
    
    # intl_news → international_news 的字段名前缀映射
    FIELD_PREFIX = {"intl_news": "international_news"}  # 其他国家 key 与字段前缀一致
    
    def _make_router(self, key: str):
        """为指定 key 生成条件路由函数（新闻类专用）"""
        prefix = self.FIELD_PREFIX.get(key, key)  # intl_news → international_news
        report_field = f"{prefix}_report"
        count_field = f"{prefix}_tool_call_count"
        label = self.LABELS[key]
        max_calls = self.max_tool_calls
        
        def router(state: AgentState) -> str:
            messages = state.get("messages", [])
            last_msg = messages[-1] if messages else None
            count = state.get(count_field, 0)
            report = state.get(report_field, "")
            
            if count >= max_calls:
                return f"Msg Clear {label}"
            if report and len(report) > 100:
                return f"Msg Clear {label}"
            if hasattr(last_msg, 'tool_calls') and last_msg.tool_calls:
                return f"tools_{key}"
            return f"Msg Clear {label}"
        
        return router
```
