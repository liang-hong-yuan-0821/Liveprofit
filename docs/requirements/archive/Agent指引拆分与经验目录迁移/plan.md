### 4.1 规则拆分

按源章节及规则段落建立迁移表，覆盖流程、验收、架构存储、任务文档、评审、量化、测试、经验使用、Provider、采集、Python配置、AI、前端、调度、Windows及市场命名。纯事实用现有 knowledge 收纳/引用；格式用模板收纳；一般规则与更新政策置开发流程。SQLAlchemy 锁后刷新和量化测试行像等不得丢失。代码验收保留测试组织的全部规则并指向 tests/README，细则作为统一规范而非改写执行入口。

根入口按受影响业务判断：API前端消费、市场schema的研究/执行消费方、量化研究/目标/账本/迁移/测试均须读取相关规范。所有命中的文件都读；经验按领域主题定位。关键门禁常驻摘要，细则不可放松摘要。规范内相对链接按新目录位置重新解析；旧 AGENTS/CLAUDE 章节指针在活跃入口中改为实际规范链接。

开发流程的通用约束对所有非 trivial 工作必读；依赖、环境和 Windows 脚本操作即使只有一行也须读取对应通用约束。任务生命周期章节仅在复杂任务时适用。

### 4.2 经验目录与引用

移动前验证两个绝对路径均属于工作区 docs 且目标不存在，移动后核对文件全集及规范化前后内容。替换 docs/memory、相对 memory 路径以及可访问经验链接；不批量改写历史方案的设计语义，不修改生成测试索引。原有破损链接作为基线登记，验收要求无新增断链，新增规范/任务/根入口无断链。历史 CLAUDE 叙述可保留，活跃规范与入口不得依赖不存在的文件。

### 4.3 并发内容与验收

先快照全部可能改动的文本和状态；每次写入比较当前内容与最后已知内容，有并发变化则停止该文件并合并。迁移基于工作树，不用 HEAD 覆盖；提交时对已有脏文件仅暂存本次路径/文本差异，经验文件迁移保持原有未提交差异在新位置。AGENTS 的新增规则在工作树规范中保留；HEAD 基线与工作树新增规则分别核验。索引初始无暂存条目；提交前再次检查范围，无非文档内容进入提交。

双版本明确构造：W 为原工作树执行本次迁移后的交付内容，S 为原 HEAD 执行同一迁移后的提交内容。新的 standards 同时从 W 与 HEAD 源指引各生成一份，S 写入索引，W 保留在文件系统；既有 tracked 经验以 HEAD 内容执行路径替换后进入 S，原有六份 untracked 经验只移动并继续 untracked。其余脏文档用 HEAD 施加本次相同路径/导航修改构造 S，不暂存原独立增量。通过精确路径暂存后以 Git blob 校准 S，核索引内容逐文件与 S 完全一致；W−S 的差异逐文件核对原工作树−HEAD 在路径/规则映射后仍保留。无关文件哈希保持不变。根入口与 S 规范不新增指向原未追踪经验的依赖，已有未提交文档对此类资料的引用在 W 中保留，分别报告工作树和提交快照有效性。

验证工具：Python 标准库读取文档/哈希/解析相对路径；Git 只读差异与精确暂存。无外部库/API、DB、Redis、LLM调用。软件/文档验收不宣称部署或新会话自动加载认证。回滚使用本次提交的反向变更；同时保全迁移后未提交差异，禁止直接覆盖脏工作树。

文件范围：新增上述七份规范及 standards/index；修改 AGENTS、docs/index、经验索引、相关模板/知识库/历史文档的路径引用；移动 docs/memory 全集；新建本任务八文件与附件。仓库应用逻辑不在范围内。
