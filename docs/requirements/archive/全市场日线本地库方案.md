## 一、背景与动机

### 1.1、现状

- 事件研究系统已有 `market_data` 表（`AI/eventStudy/db/schema.sql`），但**仅覆盖 4 个目标指数**（上证指数/科创50/科创100/沪深300）日线，NUMERIC 类型、PK `(asset_id, ts)`；消费方为事件研究（`event_study`、`market_context`）。
- 个股/ETF 日线目前**只走展示链路即时拉取**（`TushareProvider.get_stock_data` 等返回 Markdown str，每次分析现拉最近 N 天），无本地存储。
- 板块层/个股层分析反复经代理端点拉历史日线（sw_daily/dc_daily/index_daily 等），同一数据重复请求，且依赖代理在线可用性。
- 全市场级数据无落地：无法做"某日全市场横截面"查询（涨跌分布、选股），无本地回测数据基础。

### 1.2、目标

- 本地 PostgreSQL 落地**全市场 A 股 + 场内基金（ETF/LOF）近 10 年日线 + 复权因子 + 基本信息 + 概念成分映射**。
- 每日增量自动更新（并入 `daily_job`，覆盖 tushare 数据修正）。
- 提供标准查询 DAO：单标的区间序列、全市场横截面、前复权序列。
- 一次性回填脚本，可断点续跑。
- 现有 `market_data` 表及其消费方**零改动**。

```
    ▼
store 包（新建 AI/dataflows/store/）
    ├── backfill.py       历史回填（一次性，断点续跑）
    ├── incremental.py    每日增量（daily_job 步骤 2 调用）
    ├── stock_daily_dao.py  DAO（批量写入 / 查询 / 前复权）
    ├── db.py             连接 + init_store_schema()
    └── schema.sql        六张新表（public schema）
    ▼
PostgreSQL 16（liveprofit 库，与事件研究同库不同表）
```

### 2.1 数据模型设计

| 表 | 写入者 | 说明 |
|------|------|------|
| `stock_basic` | backfill / incremental | 股票基本信息（stock_basic 接口全量，含退市股，含 area 地域） |
| `fund_basic` | backfill / incremental | 场内基金基本信息（fund_basic market='E'，含费率/业绩基准） |
| `stock_daily` | backfill / incremental | 股票 + 场内基金日线**共用**（未复权原值） |
| `adj_factor` | backfill / incremental | 复权因子**共用**（股票 adj_factor + 基金 fund_adj） |
| `concept` | backfill / incremental | 概念列表（**多来源**：ths=同花顺 / dc=东方财富，~2000 行，含成分数/发布日期） |
| `concept_member` | backfill / incremental | 概念成分映射（**多来源**，逐概念拉取，~12 万行） |

**分类策略（决策 1）**：`stock_daily` / `adj_factor` **不冗余 asset_type 列**。理由：① 两表合计约 1400 万行，冗余列增加 ~150MB 且需与基本信息表双源同步；② 代码段天然不重叠（股票 60/68/00/30/8/4/920 前缀 vs 基金 5 前缀（沪）/15/16/18（深）），`is_fund_ts_code()` 前缀函数可判定；③ 查询分类统一走前缀函数判定（`market='stock'` = 非基金前缀），**不经基本信息表 JOIN/白名单过滤**——避免退市股、异常代码被白名单静默漏掉。注：该决策是对之前讨论"日线表加 asset_type 列"的修订。

**B 股边界（实测，2026-08-28）**：代理端点 `daily`/`stock_basic`/`adj_factor` **均不含 B 股**（900/200 前缀 0 行）。当日 daily 前 3 位代码实测分布：000/001/002/003/300/301/302/600/601/603/605/688/689/920，与"沪深 A 股 + 北交所"一致。结论：`is_fund_ts_code` 前缀规则无需处理 B 股；若未来端点口径变化引入 900/200，它们会被归入 stock 侧（存储无害），届时再评估。

```sql
-- 股票基本信息（实测全量 5551 行，含退市股）
CREATE TABLE IF NOT EXISTS stock_basic (
    ts_code      VARCHAR(16) PRIMARY KEY,   -- 证券代码（后缀 .SH=沪/.SZ=深/.BJ=北）：如 000001.SZ（平安银行）、
                                            -- 600000.SH（浦发银行）、920992.BJ（北交所）
    name         VARCHAR(32) NOT NULL,      -- 证券简称：如"平安银行"
    market       VARCHAR(16),               -- 上市板块（stock_basic 口径）：主板/创业板/科创板/北交所；
                                            -- 如 000001.SZ→主板、300xxx.SZ→创业板、688xxx.SH→科创板、920xxx.BJ→北交所
    exchange     VARCHAR(8),                -- 交易所：SSE=上海证券交易所（沪市）/ SZSE=深圳证券交易所（深市）/
                                            -- BSE=北京证券交易所（北交所）；与 market 是不同维度（板块层级 vs 交易所）
    industry     VARCHAR(32),               -- 所属行业（stock_basic 口径）：如 000001.SZ→"银行"
    area         VARCHAR(16),               -- 公司地域（stock_basic 原生字段）：如"深圳"/"北京"/"吉林"/"江苏"
    list_status  CHAR(1),                   -- 上市状态：'L'=上市 / 'D'=退市 / 'P'=暂停上市
    list_date    DATE,                      -- 上市日期：如 000001.SZ → 1991-04-03
    delist_date  DATE,                      -- 退市日期（仅退市股有值）：如 000418.SZ（小天鹅A，吸收合并退市）；
                                            -- 在上市股为 NULL
    updated_at   TIMESTAMPTZ NOT NULL DEFAULT now()  -- 行最后写入时间
);

-- 场内基金基本信息（~2900 行，ETF/LOF，fund_basic market='E' 全字段）
CREATE TABLE IF NOT EXISTS fund_basic (
    ts_code        VARCHAR(16) PRIMARY KEY, -- 基金代码：如 158013.SZ（易方达国证航天航空行业ETF）、
                                            -- 161725.SZ（招商中证白酒LOF）；本表恒为场内基金（market='E' 过滤）
    name           VARCHAR(64) NOT NULL,    -- 基金全称：如"易方达国证航天航空行业ETF"
    management     VARCHAR(64),             -- 基金管理人：如"易方达基金管理有限公司"
    custodian      VARCHAR(64),             -- 基金托管人：如"国泰海通证券股份有限公司"
    fund_type      VARCHAR(32),             -- 基金类型（fund_basic 口径）：如 '股票型'/'混合型'/'债券型'；
                                            -- 实测 158013.SZ = '股票型'
    invest_type    VARCHAR(32),             -- 投资类型（fund_basic 口径）：官方含指数型/股票型等；实测部分基金为空
                                            -- （NaN→NULL），原样保留
    type           VARCHAR(32),             -- 基金类型（fund_basic 口径，与 fund_type 语义重叠）：实测 '股票型'
    found_date     DATE,                    -- 基金成立日期：如 158013.SZ → 2026-08-26
    due_date       DATE,                    -- 基金到期日（封闭式/定期开放基金有值；普通开放式为 NULL）
    list_date      DATE,                    -- 场内上市日期（交易所挂牌日，fund_basic 口径）
    issue_date     DATE,                    -- 发行日期：如 158013.SZ → 2026-07-27
    delist_date    DATE,                    -- 场内退市日期（仅已摘牌基金有值；在册基金为 NULL）
    issue_amount   DOUBLE PRECISION,        -- 发行份额，单位：亿份
    m_fee          DOUBLE PRECISION,        -- 管理费率，单位 %/年：如 158013.SZ = 0.15
    c_fee          DOUBLE PRECISION,        -- 托管费率，单位 %/年：如 158013.SZ = 0.05
    duration_year  DOUBLE PRECISION,        -- 存续期（年），开放式基金多为 NULL
    p_value        DOUBLE PRECISION,        -- 面值（元）：实测恒 1.0
    min_amount     DOUBLE PRECISION,        -- 起购金额（fund_basic 口径）：如 158013.SZ = 0.1
    exp_return     DOUBLE PRECISION,        -- 预期年化收益（fund_basic 口径）：实测多数为 NULL
    benchmark      VARCHAR(128),            -- 业绩基准（跟踪指数描述）：如 158013.SZ =
                                            -- "国证航天航空行业指数收益率×100%"
    status         CHAR(1),                 -- 基金状态：'L'=上市 / 'I'=发行期 / 'D'=终止上市；如 158013.SZ = 'L'
    trustee        VARCHAR(64),             -- 受托人（fund_basic 口径）：实测多数为 NULL
    purc_startdate DATE,                    -- 申购起始日
    redm_startdate DATE,                    -- 赎回起始日
    market         CHAR(1),                 -- 交易场所：'E'=场内 / 'O'=场外；本表恒 'E'（按 market='E' 过滤拉取）
    updated_at     TIMESTAMPTZ NOT NULL DEFAULT now()  -- 行最后写入时间
);

-- 日线共用表（未复权原值；~1400 万行）
CREATE TABLE IF NOT EXISTS stock_daily (
    ts_code    VARCHAR(16) NOT NULL,        -- 证券代码（股票与场内基金共用）：如 000001.SZ（平安银行）、
                                            -- 158013.SZ（航天航空ETF）；分类靠前缀函数 is_fund_ts_code 判定（2.1 决策 1）
    trade_date DATE NOT NULL,               -- 交易日（自然日）；停牌日无行（整行缺失，不存 NULL 行），
                                            -- 查询方需自行 ffill/容忍缺口
    open       DOUBLE PRECISION,            -- 开盘价（元，未复权）：如 920992.BJ@2026-08-28 → 11.31
    high       DOUBLE PRECISION,            -- 最高价（元，未复权）：11.49
    low        DOUBLE PRECISION,            -- 最低价（元，未复权）：11.26
    close      DOUBLE PRECISION NOT NULL,   -- 收盘价（元，未复权）：11.41；NOT NULL——写入清洗时
                                            -- close 为 NaN 的行显式 drop（3.3.1）
    pre_close  DOUBLE PRECISION,            -- 前收盘价（元）：11.37（新上市首日为 NULL）
    change     DOUBLE PRECISION,            -- 涨跌额（元）= close - pre_close：0.04
    pct_chg    DOUBLE PRECISION,            -- 涨跌幅（%）= change / pre_close × 100：0.3518
    vol        DOUBLE PRECISION,            -- 成交量，单位：手（1 手 = 100 股/份）：5670.63
    amount     DOUBLE PRECISION,            -- 成交额，单位：千元：6450.05523（约 645 万元）
    PRIMARY KEY (ts_code, trade_date)       -- 含日期列，未来可切 TimescaleDB/分区
);
CREATE INDEX IF NOT EXISTS idx_stock_daily_trade_date ON stock_daily (trade_date, ts_code);
-- 反向索引：某日全市场横截面查询（get_cross_section）

-- 复权因子共用表（~1400 万行）
CREATE TABLE IF NOT EXISTS adj_factor (
    ts_code    VARCHAR(16) NOT NULL,        -- 证券代码（股票 adj_factor 接口 + 基金 fund_adj 接口共用）：
                                            -- 如 000001.SZ / 160505.SZ
    trade_date DATE NOT NULL,               -- 交易日；因子行数 ≥ 当日日线行数属预期（停牌标的仍更新因子，3.4.3）
    adj_factor DOUBLE PRECISION NOT NULL,   -- 复权因子（原值）：无除权除息 = 1.0；如 160505.SZ@2026-08-28 = 11.1326；
                                            -- 前复权公式 qfq_x = x × factor_t / factor_latest（3.3.1 get_qfq_daily）
    PRIMARY KEY (ts_code, trade_date)
);

-- 概念列表（多来源，~2000 行；决策 8/9）
-- 概念与成分拆两张表（决策 8）：概念元数据（成分数/发布日期）不冗余到成分行，
-- 概念改名/下线只 UPDATE 1 行；概念列表与成分变动独立刷新
CREATE TABLE IF NOT EXISTS concept (
    source       VARCHAR(8) NOT NULL,       -- ths=同花顺 / dc=东方财富（决策 9 多来源解耦）
    concept_code VARCHAR(32) NOT NULL,      -- 883300.TI（ths）/ BK1753.DC（dc）
    name         VARCHAR(64) NOT NULL,      -- 概念名（如"激光雷达"/"光刻胶"）
    count        INTEGER,                   -- 成分数（来源口径快照）：如 883300.TI"沪深300样本股" = 300、
                                            -- 864008.TI"激光雷达" = 1；与 concept_member 实际行数存在滞后偏差属预期
    exchange     VARCHAR(8),                -- 概念指数市场归属（ths_index 口径）：实测恒为 'A'（= 全部 A 股市场）；
                                            -- dc 来源无此口径，存 NULL
    list_date    DATE,                      -- 概念指数发布日期（ths_index 口径）：如 883300.TI"沪深300样本股" = 2010-04-13；
                                            -- dc 来源无此口径，存 NULL
    type         VARCHAR(8),                -- 板块指数类型（ths_index 口径）：'N'=概念指数（本表 V1 恒为 N——
                                            -- 拉取时即按 type='N' 过滤）；同花顺另含 'I'=行业指数、'S'=特色指数，
                                            -- 保留此列以备未来扩展类型；dc 来源无此口径，存 NULL
    updated_at   TIMESTAMPTZ NOT NULL DEFAULT now(),
    PRIMARY KEY (source, concept_code)
);

-- 概念成分映射（多来源，逐概念拉取，~12 万行）
CREATE TABLE IF NOT EXISTS concept_member (
    source       VARCHAR(8) NOT NULL,       -- 概念来源：ths=同花顺 / dc=东方财富（与 concept.source 对应）
    concept_code VARCHAR(32) NOT NULL,      -- 概念代码：如 883300.TI（ths）/ BK1753.DC（dc 光刻胶）
    ts_code      VARCHAR(16) NOT NULL,      -- 成分股票代码：如 301630.SZ（光刻胶成分"同宇新材"）
    PRIMARY KEY (source, concept_code, ts_code)
    -- 不存成分股名（决策 12）：概念来源名称与 stock_basic.name 存在改名不同步的漂移风险，
    -- 展示/对账一律 ts_code JOIN stock_basic 取权威名称
);
CREATE INDEX IF NOT EXISTS idx_concept_member_ts ON concept_member (ts_code);
-- 反查索引：某股票属于哪些概念（get_stock_concepts）
```

**类型决策（决策 2）**：行情列全部 `DOUBLE PRECISION`（对比现有 market_data 的 NUMERIC）。理由：日线 OHLC 精度需求 ≤ 4 位小数，double 15 位有效数字绰绰有余；1400 万行规模下 NUMERIC 变长存储比 double 大 ~2.5 倍且聚合更慢。`market_data`（指数）**不迁移**——保持既有 NUMERIC 与消费方稳定（向后兼容）。

**分区决策（决策 3）**：V1 不分区。1400 万行单表 PG 16 完全可承受（表 ~1.6GB + 索引 ~1.5GB），分区增加运维复杂度；PK 已含 `trade_date`，未来切 TimescaleDB hypertable 或 RANGE 分区无阻塞。

**schema 归属**：新表建在 `liveprofit` 库 public schema，与事件研究同库。表名与现有表（assets/events/market_data/…）无冲突。

### 3.2 Provider 层扩展（TushareProvider）

#### 3.2.1 模块设计

按 Data Provider 接口约定，**先在 `BaseStockDataProvider` 加 6 个方法**，默认返回 `None`（结构化返回接口例外，规则 8），仅在 `TushareProvider` 覆写（AKShare 不覆写——Tushare 接口可完全覆盖，强制规则 2）：

```python
# base_provider.py 新增（默认返回 None）
def get_full_market_daily_df(self, trade_date: str, market: str = "stock"):
    """单交易日全市场日线（结构化 DataFrame）。
    market: "stock"=股票 daily 接口 / "fund"=场内基金 fund_daily 接口。
    trade_date: YYYYMMDD。不支持或失败返回 None。"""

def get_full_market_factor_df(self, trade_date: str, market: str = "stock"):
    """单交易日全市场复权因子（adj_factor / fund_adj）。同上。"""

def get_stock_basic_df(self):
    """股票基本信息全量（含退市，含 area 地域）。返回 None 表示不支持/失败。"""

def get_fund_basic_df(self):
    """场内基金基本信息全量（fund_basic market='E'）。返回 None 表示不支持/失败。"""

def get_concept_list_df(self, source: str = "ths"):
    """概念列表（多来源）。source: "ths"=同花顺 / "dc"=东方财富。返回 None 表示不支持/失败。"""

def get_concept_members_df(self, concept_code: str, source: str = "ths", trade_date: str = None):
    """单个概念的全部成分（按概念代码过滤，多来源）。trade_date 仅 dc 来源需要（快照式，
    调用方传最近交易日）；ths 来源忽略该参数。返回 None 表示不支持/失败。"""
```

`TushareProvider` 覆写要点：

- 经 `self._api_call(...)` 调用（自动获得超时保护与端点子日志，复用现有机制）；未连接返回 None。
- `get_full_market_daily_df`：按 market 选 `self.api.daily` / `self.api.fund_daily`，**只传 `trade_date` 参数**（禁止区间查询，原因见 3.2.2）。
- **列序归一**：实测 `fund_daily` 列序为 `ts_code,trade_date,pre_close,open,high,low,close,change,pct_chg,vol,amount`，`daily` 为 `ts_code,trade_date,open,high,low,close,pre_close,…`——返回前统一按标准列序 `[ts_code, trade_date, open, high, low, close, pre_close, change, pct_chg, vol, amount]` 重排（缺失列置 NaN），消费方不感知差异。
- `get_full_market_factor_df`：`adj_factor` / `fund_adj`，标准列 `[ts_code, trade_date, adj_factor]`。
- `get_stock_basic_df`：`stock_basic` 不传 list_status（全量含 D/P），字段 `ts_code,name,market,exchange,industry,area,list_status,list_date,delist_date`（area 为原生字段，实测可用）。
- `get_fund_basic_df`：`fund_basic(market='E')` 全字段透传。
- `get_concept_list_df(source)`：`ths` → `ths_index(type='N')`，标准列 `[ts_code, name, count, exchange, list_date, type]`；`dc` → `dc_index(trade_date=<最近交易日>, idx_type='概念板块')`，标准列取 `[ts_code, name]` 并归一为 `[ts_code, name, count, exchange, list_date, type]`（dc 缺的列置 None）。未知 source 返回 None。
- `get_concept_members_df(concept_code, source, trade_date)`：

### 3.4 历史回填脚本（backfill.py）

#### 3.4.1 模块设计

```
python -m AI.dataflows.store.backfill [--start 2016-01-01] [--end 2026-08-28]
```

流程：

1. **Provider 获取**：直接实例化 `TushareProvider`（`from AI.dataflows.providers.tushare_provider import TushareProvider`），**不经 `get_provider()`**——store 数据只可能来自 tushare 代理端点，与 `LIVEPROFIT_DATA_SOURCE` 无关（否则 akshare 环境下 4 方法全返回 None，约 2600 交易日 × 3 重试空跑 9~10 小时）。
2. `init_store_schema()` → `upsert_stock_basic` + `upsert_fund_basic`（各 1 请求，覆盖退市股与历史基金）→ `collect_concepts(conn)`（概念体系双来源：ths 899 概念 + dc 1031 概念，逐概念拉成分 ≈ 2000 请求 ≈ 35 分钟；**失败域分层**：单概念失败仅跳过该概念、单来源失败不阻断另一来源、概念体系整体失败不阻断日线回填）。
3. 交易日历：复用 `TushareProvider.get_trade_cal(start, end)`（现有方法，已支持 CN）。
4. 逐交易日（升序）：拉 4 接口（daily/adj_factor/fund_daily/fund_adj）→ **完整性校验**（见下）→ 当日 4 接口全部成功后内存合并（stock 与 fund 的日线/因子各自 concat）→ `bulk_upsert_daily(update=False)` + `bulk_upsert_factor(update=False)` → 单日提交（`conn.commit()`）。
5. **失败处理（接口失败与写入失败同一路径）**：当日任一接口失败、完整性校验失败、或 bulk_upsert/commit 抛异常（连接抖动、约束违例等）→ 当日整体不写库（保证库内无"半截日"）→ 记错误日志并**重试 3 次（间隔 5s）后跳过该日**，写入失败清单 `logs/stock_backfill_failures.json`，继续下一日；脚本结束时汇总失败日期列表。
6. **完整性校验（截断检测，评审新增）**：单日返回行数 **≥ 6000 → 视为截断**，自动降级为分批补拉（stock_basic/fund_basic 全量代码列表、**每批 100 个**逗号分隔 + trade_date 逐批查询后 concat，该方式实测可用，见 3.2.2）；另有软性 sanity 检查：日线行数与"当日应上市数"（由 stock_basic 的 list_date/delist_date 重建）偏差超过 ±5% 时记 warning（不阻断，覆盖新股扩容初期 stock_basic 未及时更新的情况）。
7. **断点续跑**：以 PG 内 `max(trade_date)` 为天然断点（完整日才入库，无需独立 checkpoint 文件）——重启脚本自动从最大日期次一日继续；进度日志写 `logs/stock_backfill.log`。
8. 请求间隔 0.2s（实测无强限频，保守余量）。

**失败清单与 --retry-missing 语义**：失败清单为 JSON 数组 `["YYYYMMDD", ...]`，由回填脚本以 temp+rename 原子写更新（沿用项目惯例）。`--retry-missing` 模式：**忽略 max(trade_date) 断点**，仅按清单日期逐日执行"4 接口拉取 + 完整性校验 + DO NOTHING upsert"（这些日此前未入库，DO NOTHING 与回填语义一致），成功则从清单移除；该模式与断点续跑互不干扰（两者写入同一主键空间，幂等）。

## 四、已确认决策 / 待确认问题

**已确认决策**：

1. 范围：全市场 A 股 + 场内基金（ETF/LOF）一起做（用户拍板 2026-08-30）。
2. 复权：存未复权原值 + 复权因子两表，用时现算前复权（用户拍板）。
3. 历史深度：近 10 年（2016-01-01 起）（用户拍板）。
4. 表组织：基本信息拆 stock_basic / fund_basic 两张（ETF 费率 m_fee/c_fee、托管人、业绩基准等基金特有字段独立承载）；日线/因子表共用不拆（列结构一致、代码段不重叠）（用户拍板）。
5. 日线表不冗余 asset_type（本文修订，见 2.1 决策 1）。
6. 现有 market_data 表不迁移不优化（NUMERIC 保持），零向后兼容风险。
7. 行情列用 DOUBLE PRECISION、日期用 DATE、V1 不分区（决策 2/3）。
8. 概念拆两张表（`concept` 概念元数据 + `concept_member` 成分映射）：数据源天然两层、概念改名只改 1 行、更新语义独立（用户拍板 2026-08-30）。
9. **概念多来源解耦**（用户拍板 2026-08-30）：`source` 列区分来源，V1 实现 ths=同花顺 + dc=东方财富 两个来源；表结构与采集循环按来源参数化，新增来源只加 Provider 分支不改表。官方 concept/concept_detail 在代理端点不存在（实测），不入来源。
10. 概念体系周刷（每周一随增量执行，refresh_concepts 参数可手动触发）；股票/基金基本信息仍每日刷新。
11. 来源参数硬约束（实测）：ths 用 `ths_member(ts_code=概念代码)`（`code=` 参数被代理忽略）；dc 用 `dc_member(ts_code=板块代码, trade_date=最近交易日)` 组合过滤（仅 ts_code 返回跨 5 日快照、全量拉截断 8000 行，均实测）。
12. **外部优化建议评估结论（2026-08-30 用户提供清单，逐条评估后拍板）**：
    - ❌ vol/amount 改 BIGINT：**实测否决**——daily 当日 5547 行中 vol 带小数 4371 行、amount 5543 行；fund_daily 同理。小数部分实测为 0.00~0.99 均匀分布的 100 种取值（= 股数÷100 的真实零股数据，非浮点噪声）；且 522 行（9.4%）连两位小数都不是，×100 也无法整数化；BIGINT 与 double 同为 8 字节无存储收益。保持 DOUBLE PRECISION。
    - ⏸ adj_factor 反向索引 (trade_date, ts_code)：暂缓——当前无全市场因子横截面消费方，~300MB 索引白养；未来有需求时 `CREATE INDEX CONCURRENTLY` 后补即可。
    - ❌ RANGE 按年分区：维持决策 3 不分区——横截面单日查询命中 (trade_date, ts_code) 反向索引，按年分区对它无 pruning 收益；删旧数据需求 V1 不存在；PK 含 trade_date 未来切 TimescaleDB 无阻塞。
    - ❌ 删除 change/pct_chg 列：保留原始值入库（数据仓库惯例）；不一致风险由增量 DO UPDATE 全列覆盖机制解决；pct_chg 为高频筛选条件，删除后每次现算且生成列无法完全复刻 tushare 舍入口径。
    - ✅ **删除 concept_member.con_name**：已落实——概念来源名称与 stock_basic.name 存在改名不同步的漂移风险，展示/对账一律 ts_code JOIN stock_basic 取权威名称。
    - ❌ stock_basic 建 industry/area 索引：仅 5550 行小表，全表扫描毫秒级；索引反而加重每日 upsert 维护。
