## 一、背景与动机

### 1.1 现状

当前项目没有独立前端工程，现有 AI 能力通过 main.py 命令行入口运行。

AI/graph/trading_graph.py 已能通过 progress_callback 输出市场层、板块层、个股层进度；前端只消费后端标准 REST/SSE 契约，不读取日志或 Python 内部状态。

后端平台将提供任务、报告、市场读模型、事件研究、自选分组和组合的版本化 API。

首期为 loopback local-only 单人应用：无登录、账号、权限、远程访问和管理后台。

### 1.2 目标

建设以 大盘 / 自选 / AI 为一级导航的 React 投研工作台，使用户能够：

- 在大盘页连续阅读全球指数、热门概念和已审核宏观信息；
- 在自选页维护关注标的及手工组合，并从标的上下文发起分析；
- 在 AI 投研看板发起分析、处理待办、查看进行中任务和最近结论；
- 在任务中心追溯全部任务，在详情页恢复运行进度并阅读最新报告；
- 在事件研究页对新事件进行一次性同步影响预测。

页面功能、元素、交互、边界和跳转均以《Liveprofit 产品需求分析》为产品基线；本方案仅定义前端页面实现、数据消费与技术约束。

## 二、架构设计

### 2.1 技术选型

| 层 | 选型 | 设计约束 |
|----|------|----------|
| 框架 | React 19 + TypeScript + Vite | SPA，不承担 SEO；路由页面为业务代码默认归属 |
| 路由 | React Router | 使用 /market、/watchlist、/ai、/ai/tasks、/ai/tasks/:taskId、/ai/event-study |
| 远端状态 | TanStack Query | REST 数据、分页、失效和轮询均进入 Query；不复制到 Zustand |
| 本地共享状态 | Zustand | 仅存被至少两个独立组件消费的跨页面 UI 偏好 |
| UI | shadcn/ui + Radix UI + Tailwind CSS | 深色专业投研终端；组件源码由项目维护 |
| 图表 | Apache ECharts + echarts-for-react | 图表只接收前端 ViewModel，不接收 API DTO |
| 流式进度 | 原生 EventSource | 仅任务详情页使用；手动重连和 REST 回退 |
| 测试 | Vitest + React Testing Library + Playwright | 覆盖纯逻辑、页面状态与本地端到端任务闭环 |

### 2.2 工程边界与目录

```
frontend/src/
├── app/                         # Router、Provider、错误边界、应用壳
├── api/
│   ├── client.ts                 # base URL、timeout、envelope/Problem Details 适配
│   ├── generated/                # OpenAPI 唯一领域 DTO、枚举和 client
│   └── queryKeys.ts              # Query Key 工厂
├── modules/                      # 业务模块：页面、私有 Query/Mutation、Mapper、局部组件
│   ├── analysis/                 # /ai、/ai/tasks、/ai/tasks/:taskId 三个工作区
│   │                             # 任务详情页同置 useTaskEvents 与 taskEventProtocol
│   ├── market/                   # /market 大盘阅读工作区：市场/板块/信息三区块
│   ├── watchlist/                # /watchlist 自选工作区；内部 watchlists / portfolios 两个聚合 UI
│   └── event-study/              # /ai/event-study 同步预测工具
├── routes/                       # 仅 URL → Module Page 的薄装配、懒加载和 errorElement
├── shared/                       # 跨业务通用 layout、feedback、纯 ViewModel charts
└── stores/uiPreferenceStore.ts   # 主题、侧栏折叠；不预建 features/
```

页面私有的组件、Query、Mutation、Hook 和 DTO→ViewModel Mapper 必须与所属 modules/<domain>/pages/ 同置；routes/ 不得承载业务逻辑。

modules/analysis 的三条路由页可以复用稳定的任务状态展示、任务链接和轻量 Mapper，但不得抽取全能任务 feature；看板聚合、列表分页、详情 SSE、创建表单与报告布局仍各自页面私有。

shared/ 只放跨业务通用展示能力。shared/charts/ 只接受 ViewModel，不能识别市场代码、OHLC 字段或报告 DTO；完整业务能力在至少两个模块实际复用前不创建共享 feature。

uiPreferenceStore 仅含 themeMode 和 sidebarCollapsed：前者由 ThemeToggle、AppProviders 消费，后者由 AppShell、SidebarNav 消费。任务流、表单、筛选、报告展开状态和 API 数据必须留在页面/Hook/Query。

### 2.3 路由与页面边界

| 路由 | 页面 | 数据职责 | 禁止承担的职责 |
|------|------|----------|----------------|
| /market | 大盘 | 市场、板块、信息三个读模型区块 | 本地计算热点、维护指数名单、抓取新闻 |
| /watchlist | 自选 | 分组/标的、组合/持仓 CRUD | 自动应用 AI 建议、跨分组移动 |
| /ai | AI 投研看板 | 待处理、进行中、最近结论、新建分析 | 全量任务分页、运行日志、SSE |
| /ai/tasks | AI 任务中心 | 全量任务摘要、服务端状态筛选、Cursor 分页 | 创建表单状态、SSE、报告正文 |
| /ai/tasks/:taskId | 任务详情与最新报告 | 任务 REST 状态、有限进度窗口、最新报告 | 任务历史版本、独立报告路由 |
| /ai/event-study | 事件研究 | 单次同步预测表单和结果 | 创建分析任务、异步任务历史 |

根路由由 AppErrorBoundary 捕获渲染异常；各一级页及任务详情配置 RouteErrorBoundary。资源 404 必须显示 NotFoundState 并提供上级入口，不能建立 SSE、无限重试或显示为系统崩溃。

### 2.4 契约、分页和状态规则

backend/openapi/openapi.v1.json 是领域 DTO、枚举、错误码的唯一来源（契约已按后端方案 §2.6.1~§2.6.5 冻结），前端使用 openapi-typescript-codegen@0.29.0 生成 frontend/src/api/generated/；禁止页面手写同名领域类型。

所有成功响应（含 DELETE，固定 200 + data={deleted, resource_id}）均由 api/client.ts 解包为 { data, meta }；所有 Cursor 翻页只读取 meta.next_cursor，禁止 offset、本地拼接 cursor 或对已加载页假装全量筛选。

ApiError 必须保留稳定 code、request_id 和 retryable；页面不可展示堆栈、Token、密钥、绝对路径、租约或 Provider 原始异常。

独立数据区必须分别展示 loading、正常 empty、retryable error、non-retryable error 和 success；一个区块失败不得阻塞同页其他区块。

创建和写操作从 response envelope 的 data 读取结果；同一创建意图重试复用 Idempotency-Key，任何输入变更都必须生成新的 key。

### 2.5 SSE 与任务恢复规则

AiTaskDetailPage 先 GET /api/v1/analysis-tasks/{taskId}；仅 REST Task 为非终态、且 TaskDTO.events_url 严格等于 canonical /api/v1/analysis-tasks/{taskId}/events 时，才启动 useTaskEvents，否则视为 API 协议错误仅进入 REST 轮询。刷新、直接访问、前进/后退均重复该过程。

useTaskEvents 是唯一可创建和关闭 EventSource 的 Hook，首期只被任务详情使用；事件窗口、lastEventId、连接状态、重连次数均是 Hook State，不创建全局 taskStreamStore。时间线最多保留 50 条业务事件（前端策略，超出丢弃最早），不伪装完整历史。

只注册 queued、started、progress、completed、failed、cancelled、reset、heartbeat 八种命名事件。任何帧先通过 parseTaskEvent() 的严格运行时校验，才可影响状态。

业务事件必须有 Redis Stream ID、匹配 task_id、正整数 attempt_no、RFC 3339 occurred_at 和 schema_version: 'v1'；reset、heartbeat 为无 ID 控制事件（data 分别固定为 {task_url, earliest_event_id, occurred_at, schema_version} 与 {connection_id, sent_at, schema_version}），均不能进入时间线或推进游标。游标优先级为 Last-Event-ID > after > 0-0。

Redis Stream ID 以两个 BigInt 数字段比较，只接收严格递增事件。畸形 JSON、未知字段、版本不匹配、任务不匹配、非法控制帧和旧事件均不可写入时间线。

每次 onerror 立即关闭连接，并按 1s/2s/4s/8s…（上限 30s）指数退避手动重建；心跳超时按 45s 无任何事件判定断连；连续五次失败、合法 reset 或协议错误后切换为每 5 秒 REST 轮询，直到正式终态（对齐 API 契约）。

completed、failed、cancelled 才关闭流并失效 Task/Report Query。RETRYING 仅由 Task REST DTO 的状态、attempt_no 和 next_retry_at 表达，不能由 SSE 时间线推断。

### 2.6 三方依赖能力评估

| 依赖 | 能力确认 | 风险与降级 |
|------|----------|------------|
| React Router | 嵌套路由、参数、search params、errorElement | 可满足 canonical task URL；资源不存在时转 NotFoundState |
| TanStack Query | 条件 Query、Mutation、分页、失效、refetchInterval | SSE 只触发精准失效，不作为正式状态来源 |
| Zustand | 持久化非敏感 UI 偏好 | 不满足“至少两独立消费者”的状态必须下沉 |
| EventSource | 命名 SSE 事件、close() | 不支持自定义 header；单人同源场景可用，失败时受控 REST 回退 |
| shadcn/ui / Radix | Dialog、Sheet、Form、Table、Skeleton、无障碍基础 | 可满足表单、反馈和投研密集布局；需保留键盘和焦点回归测试 |
| ECharts | candlestick、line、bar、响应式 resize | 只接收 ViewModel；空数据不渲染伪图表 |
| react-hook-form + Zod | 表单状态、字段校验和错误展示 | 只做前置校验，后端仍是最终校验方 |

## 三、详细设计

本章以前端业务 Modules 与 API 消费层作为唯一详细设计轴线：业务 Module 负责页面、复用能力、ViewModel 与局部状态；app/api/shared 是基础设施，routes 只负责 URL 薄装配；API 消费层负责 generated Client、Query/Mutation 与 DTO 边界；SSE 协议解析与 useTaskEvents 同置于 analysis 模块任务详情工作区。页面不得直接发起 fetch、重定义领域 DTO 或跨越模块深层导入私有实现。

### 3.1 Modules 详细设计

| Module | 所有权与职责 | 本地状态 / ViewModel | API 消费边界 |
|--------|--------------|----------------------|--------------|
| app / api / shared | 基础设施：Router、Provider、错误边界、应用壳、generated Client 和纯展示组件 | uiPreferenceStore 仅含主题和侧栏折叠 | 不承载业务 Query、Mutation、领域状态或领域 DTO 的二次定义 |
| modules/analysis | 任务与最新报告的三个路由工作区：看板、任务中心、任务详情；后端 analysis 是业务真相 | 看板表单、列表筛选与详情 SSE 分别页面私有；REST Query 是正式状态 | 看板只消费聚合 DTO；列表只消费 TaskListItemDTO；详情独占 Task/Report Query 与 EventSource |
| modules/market | /market 的市场、板块、信息三固定区块 | 各 Panel 的筛选和加载状态；DTO→图表 ViewModel | 资产、Bars、热点 Query；只读消费 event_study 的宏观信息投影，不维护静态资产或热点名单 |
| modules/watchlist | /watchlist 内的自选分组/标的与组合/持仓工作区；前端也保留两套独立资源状态 | 当前资源选择、编辑草稿和弹窗均为页面局部状态；watchlists / portfolios 不共享 Query、Mutation、revision | Watchlist / Portfolio Query、Mutation；冲突后精准失效；不得自动应用 AI 建议 |
| modules/event-study | 一次性事件预测表单与结果 | 表单和 mutation 状态 | 仅消费事件预测 DTO（及可用时的资产清单）；不创建任务流 Store |

#### 3.1.1 market 模块（/market）

##### 3.1.1.1 页面职责与布局

MarketOverviewPage 在一个连续滚动页按 市场（宏观指数）→ 板块（热门概念）→ 信息（宏观信息） 固定顺序组合 MarketIndicesPanel、HotConceptsPanel、MacroInformationPanel。不得提供页内 Tab、marketActiveView、本地指数名单或页面间数据拼接。

三个 Panel 是独立 Query 边界：页面装载后并行读取，各自维护筛选、加载、空态和错误态；一个 Panel 失败不能影响另外两个 Panel 的内容和操作。

##### 3.1.1.2 市场区块（宏观指数）

| UI/组件 | 数据与实现 | 交互与边界 |
|---------|------------|------------|
| MarketIndicesPanel | 先请求 GET /api/v1/market-assets?enabled=true，仅对 availability_status=AVAILABLE 的资产请求 bars（GET /api/v1/market-data/indices/{symbol}/bars?market=&interval=&from=&to=，market/interval/from/to 均必填，from ≤ to） | 固定以 US → KR → CN 分组；组内仅按服务端 display_order 排序，不补充前端资产 |
| IndexCandlestickSection | 显示名称、市场、币种、时区、as_of、来源、源更新时间、新鲜度与 K 线 | 周期选择仅渲染 supported_intervals；修改周期或日期范围重新请求 bars |
| 日期范围控件 | 使用页面局部 state 组织 from/to | 开始日期晚于结束日期、范围超过服务端限制时显示字段错误，不静默截断 |
| CandlestickChart | Mapper 将 bars 转为 CandlestickChartViewModel | 无 bars 不绘制空壳图；图表只负责数据点交互 |
| 数据状态提示 | 消费 freshness_status（FRESH/STALE/UNAVAILABLE）、market_session_status（OPEN/CLOSED）与 market_closed_reason | STALE 展示最近快照及延迟标识；CLOSED 展示最近闭市快照及闭市原因（休市是 200 正常响应）；ASSET_DISABLED 不重试；MARKET_DATA_UPSTREAM_UNAVAILABLE 可手动重试 |

##### 3.1.1.3 板块区块（热门概念）

| UI/组件 | 数据与实现 | 交互与边界 |
|---------|------------|------------|
| HotConceptsPanel | GET /api/v1/market-data/concepts/hot?market=&as_of=&interval=&from=&to=&cursor=&limit=（market/interval/from/to/limit 必填，as_of 可选） | 市场、周期、日期范围均为页面局部状态；仅允许 API 枚举 |
| ConceptCandlestickGrid | 每个卡片展示 concept_name、concept_code、rank、hotness_reason、period_return、更新时间和 K 线 | 前端不计算排名、热度或趋势；卡片 K 线仍通过 Mapper 转 ViewModel |
| 加载更多 | 使用 meta.next_cursor 请求下一页并追加 | 无 cursor 时隐藏；下一页失败保留既有成功卡片 |
| 快照状态 | 消费 freshness_status（FRESH/STALE/UNAVAILABLE）与 result_status（OK/NO_HOT_CONCEPTS） | NO_HOT_CONCEPTS/空列表是正常空态；STALE 可展示旧快照并标注；上游失败不使用静态概念兜底 |

##### 3.1.1.4 信息区块（宏观信息）

| UI/组件 | 数据与实现 | 交互与边界 |
|---------|------------|------------|
| MacroInformationPanel | GET /api/v1/macro-information?cursor=&limit=&market=&topic= | 市场、主题筛选是此 Panel 私有状态；按服务端 Cursor 顺序消费 |
| MacroInformationCard | 只展示已审核投影的标题、摘要、发生时间、市场/地区、主题、来源、关联资产和研究状态 | 长文本通过通用阅读控件折叠/展开，不修改原文 |
| 卡片标题 | 页面跳转 /ai/event-study?event_id=<id> | 按后端方案 §5.1：无 prefill 接口，用卡片已渲染字段预填输入草稿，绝不自动执行预测 |
| 加载更多/空态 | 读取 meta.next_cursor | 无审核信息显示正常空态，不从新闻、AI 报告或预测结果回填 |

##### 3.1.1.5 页面 Query、文件与验证

| 文件 | 职责 |
|------|------|
| modules/market/pages/MarketOverviewPage.tsx | 固定组合三个 Panel，不持有视图切换状态 |
| modules/market/pages/MarketIndicesPanel.tsx | 资产目录分组、指数区块与 bars 查询协调 |

#### 3.1.2 watchlist 模块（/watchlist）

##### 3.1.2.1 页面职责与布局

WatchlistPage 同页分为两个独立业务区：自选分组与标的、手工组合与持仓。二者的选择、弹窗和编辑草稿均为页面局部状态；两套资源各自分页、Mutation 和错误恢复。AI 报告中的 final_position_plan 不得自动写入、合并或覆盖手工持仓。

##### 3.1.2.2 自选分组与标的区

| UI/组件 | 数据与实现 | 交互与边界 |
|---------|------------|------------|
| WatchlistGroupList | GET /api/v1/watchlists?cursor=&limit=，服务端顺序 updated_at DESC, id DESC | 选择分组后读取其 items；资源 404 时刷新列表并清除失效选择 |
| 新建/改名分组表单 | POST /api/v1/watchlists、PATCH /api/v1/watchlists/{watchlistId}（name + expected_version） | 名称冲突保留输入并显示 WATCHLIST_NAME_CONFLICT；版本冲突重新读取资源 |
| 删除分组 | DELETE /api/v1/watchlists/{watchlistId}?expected_version= | WATCHLIST_NOT_EMPTY 时阻止删除并提示先处理标的；成功后清除当前分组上下文 |
| WatchlistItemList | GET /api/v1/watchlists/{watchlistId}/items?cursor=&limit=，按 display_order ASC, id ASC | 空分组为正常空态；子资源读写只在已选择有效分组后启用 |
| 新增/排序/删除标的 | POST /api/v1/watchlists/{watchlistId}/items（携带 expected_watchlist_revision）、PUT /api/v1/watchlists/{watchlistId}/items/order（expected_watchlist_revision + items 完整有序列表整体重排）、DELETE /api/v1/watchlists/{watchlistId}/items/{itemId}?expected_watchlist_revision= | 重复标的不可乐观插入；排序 409（WATCHLIST_ITEM_ORDER_CONFLICT）后重新读取 items 列表再整表重排提交；404 也失效父/子 Query |
| 标的 AI 分析入口 | navigate('/ai?create=1&ticker=<ticker>') | 只预填 ticker，不自动创建任务；用户仍需确认其余分析参数 |

##### 3.1.2.3 组合与持仓区

| UI/组件 | 数据与实现 | 交互与边界 |
|---------|------------|------------|
| PortfolioList | GET /api/v1/portfolios?cursor=&limit=，顺序 updated_at DESC, id DESC | 选择组合后读取 positions；失效资源时刷新并清除选择 |

#### 3.1.5 analysis 模块：任务详情工作区（/ai/tasks/:taskId）

##### 3.1.5.1 页面职责与加载顺序

AiTaskDetailPage 是运行中任务唯一 canonical URL，也是成功任务阅读最新结构化报告的唯一页面。页面严格按以下顺序工作：

### 3.2 API 消费详细设计

前端 API 层仅由 api/generated/、api/client.ts、api/queryKeys.ts 组成。生成 Client 是领域 DTO 与 REST 操作的唯一来源；client.ts 统一处理 base URL、超时、成功 envelope 解包和 RFC 7807 → ApiError 映射；各 Module 只能封装其页面专属 Query/Mutation 和 DTO→ViewModel mapper。SSE 协议解析与 useTaskEvents 同置于 analysis 模块任务详情工作区，不属于共享 API 层。

#### 3.2.1 Module 到 API Contract 映射

| 前端 Module | generated REST / SSE 操作 | Query / Mutation 规则 | 响应与异常处理 |
|-------------|---------------------------|----------------------|----------------|
| market | GET /api/v1/market-assets、GET /api/v1/market-data/indices/{symbol}/bars、GET /api/v1/market-data/concepts/hot、GET /api/v1/macro-information | 三个固定区块独立 Query；Cursor 只从 meta.next_cursor 读取 | 前三个接口属于后端 market_data；宏观信息仅只读消费后端 event_study 投影。根据 DTO 状态或 Problem Details 降级，禁止本地静态回填 |
| watchlist | watchlists 与 portfolios REST 全集（/api/v1/watchlists/*、/api/v1/portfolios/*） | 写入成功、409 或资源 404 后精准失效各自父/子 Query；自选与组合不共享 Query、Mutation、revision，不做乐观排序/删除 | expected_version/expected_watchlist_revision/expected_portfolio_revision 冲突重新读取；422 INVALID_POSITION 映射字段错误；DELETE 也返回 200 envelope |
| analysis / dashboard | GET /api/v1/analysis-dashboard、POST /api/v1/analysis-tasks | 看板三个区块独立 Query；每个新建意图生成 UUID Idempotency-Key | 只消费聚合 DTO；创建从 envelope data.task_id 读取 ID 跳转详情（events_url/report_url 为服务端派生的相对 URL） |

#### 3.2.2 SSE Client 与运行时协议边界

useTaskEvents 是唯一 EventSource 生命周期所有者，首期只允许 AiTaskDetailPage 调用。它必须使用 addEventListener 注册 queued、started、progress、completed、failed、cancelled、reset、heartbeat 八个命名事件，并先调用同置于 task-detail 的 strict parseTaskEvent(eventName, data, lastEventId, expectedTaskId)，再更新页面局部状态。六类业务帧使用 Redis Stream ID 的 BigInt 数值分段比较去重并严格推进游标；reset/heartbeat 无 ID、不得写入时间线或游标。协议错误、5 次退避失败或合法 reset 必须关闭流并改为每 5 秒 Task REST 轮询，直到终态。

> SSE 载荷字段口径（Redis Stream ID 分段比较 / 递增序号）与 attempt_no/attempt 字段名均以后端方案 §2.6 冻结契约为准：正文统一使用 attempt_no，产品基线 3.5.4 的 seq/attempt 候选不再单独实现。

#### 3.2.3 契约生成与消费门禁

后端执行 python -m backend.scripts.export_openapi --output backend/openapi/openapi.v1.json 后，前端唯一生成命令为 pnpm --dir frontend generate:api（package.json 脚本即 pnpm --dir frontend exec openapi --input ../backend/openapi/openapi.v1.json --output src/api/generated --client fetch）。OpenAPI、生成物、后端 contract test 与前端 typecheck 任一存在 diff/失败均阻断合并。完整 envelope、Problem Details、分页、Task/Report/SSE、市场与自选/组合字段以后端方案 §2.6.1~§2.6.5 为唯一冻结规范；本节只规定前端消费位置、缓存、失效和失败降级，不复制或二次定义字段。

## 五、已确认决策与待确认问题

### 5.1 已确认决策

1. 一级导航固定为 大盘 / 自选 / AI；首期无登录、账户、权限及管理后台。
2. 大盘页固定展示市场、板块、信息三个连续区块；市场按 US → KR → CN，不使用页内 Tab。
3. /ai 是 AI 投研看板，/ai/tasks 是全量任务中心，/ai/tasks/:taskId 是运行任务的可恢复标准地址和最新报告阅读页；模块内部职责与 API 消费边界以本方案第 3 章为准。
4. 任务正式状态以 REST 为准；SSE 只改善进度体验，且只在任务详情页存在。
5. 前端模块与路由同名对齐：market（/market）、watchlist（/watchlist）、analysis（/ai、/ai/tasks、/ai/tasks/:taskId）、event-study（/ai/event-study）；SSE 协议解析与 useTaskEvents 随任务详情工作区同置；app/api/shared/routes 不承载业务逻辑。
6. OpenAPI v1 契约已冻结（后端方案 §2.6.1~§2.6.5）：本方案所有端点、DTO、枚举引用以冻结契约为准，与产品基线候选不一致处以冻结契约为准。
7. routes/ 仅作薄装配；完整业务能力留在所属 modules/，只有至少两个业务模块实际复用时才评估共享 feature。Store 只保留满足至少两个独立消费者条件的跨页面 UI 偏好。
8. 手工组合与 AI 仓位建议完全隔离；事件研究是单次同步预测，不是分析任务。

## 六、与后端方案的契约与部署边界

后端负责任务状态机、交易日校正、报告 DTO、Redis Stream、市场读模型、错误分类；前端仅做前置校验、请求触发和展示。

前端只调用版本化 /api/v1 DTO；不得直接调用 AKShare、Tushare、Python Agent、数据库、日志或读取任何 Provider/LLM 密钥。

开发期 Vite 代理 /api；本地部署由 Nginx 同源反代 API 和 SSE。SSE location 必须关闭 buffering/cache/gzip，设置 X-Accel-Buffering: no，并使用大于 heartbeat 的 75 秒读写超时。

Compose 内服务可监听 0.0.0.0 供容器网络调用，但宿主仅映射 127.0.0.1:${FRONTEND_HOST_PORT}:80；API、数据库、Redis、Mongo 和 Worker 不发布宿主端口。

任何 LAN/公网访问都必须通过独立认证、TLS、CORS、审计、CSRF、权限与安全头方案重新设计，不能由本方案默认开启。
