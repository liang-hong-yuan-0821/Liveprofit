## 一、背景与动机

### 1.1 现状与目标

**当前范围**

- 已具备独立 LangGraph 子图，覆盖国际事件识别/影响分析、中国资金日历和中国技术环境判定；实际仅运行中国市场主链路，US/KR Agent 保留代码但未启用。

- 当前主链路为：`START → International Event Extraction → International News → CN News → CN Tech → END`。

- 现有下游依赖 `international_event_report`、`international_news_report`、`market_event_calendar`、`market_regime` 和 `risk_gate` 等字段；本次改造遵循“数据先聚合、规则先计算，LLM 仅负责解释与条件化判断”的原则。

| 维度 | 现状 | 问题 | 目标 |

|---|---|---|---|

| 技术特征 | 指数展示接口仅保留最后 5 行。 | 无法计算 MA60/120/250、长期趋势和相对强弱（如 120 日窗口仅 5 行输出，MA250 需 250 条样本）。 | 特征层预计算完整窗口的均线、收益、斜率和相对强弱；样本不足时明确输出“信息不足”。 |

| 情绪与资金 | 宽度、北向/主力资金和两融数据主要以单日快照提供。 | 无法识别情绪周期及连续资金趋势（如仅单日宽度快照，无法判断情绪是升温还是退潮）。 | 提供 5/20 日宽度、高标情绪和资金变化特征，全部结论可回溯至实际数据。 |

| 长线环境 | 当前缺少估值、无风险利率和流动性输入。 | 在核心证据缺失时，仍无法可靠支撑配置或等待窗口判断（如长线结论无估值分位/10Y/流动性输入，只能靠模型常识）。 | 接入可验证的估值与流动性特征；核心输入缺失时禁止给出长线方向结论。 |

| 国际风险 | 未接入 DXY、美债、VIX、信用利差等风险定价序列。 | 国际风险结论主要依赖文本解释，缺少可量化、可复核的定价证据（如判断“避险升温”时无 VIX/DXY 序列佐证）。 | 基于结构化风险价格、事件事实和历史统计共同输出 `global_risk_assessment`。 |

| 数据时点 | 新闻和部分 AKShare 快照使用“当前最新数据”。 | 数据未严格截止至 `trade_date`，历史回放可能混入未来信息（如历史任务把当日盘后快讯当作当日盘前输入）。 | 所有输入携带实际数据日期并过滤未来数据；不支持历史回放的数据明确降级。 |

| 结构化与风控 | 关键结论以自由文本输出，`risk_gate` 通过正则解析中文标签。 | 风控决策依赖不稳定的文本格式，证据、置信度和失效条件不可被机器可靠消费（如 `derive_risk_gate` 正则匹配失败时 fail-open 落 `normal`）。 | 统一输出证据、置信度、确认/失效条件和数据质量字段；`risk_gate` 仅消费结构化状态。 |

| 事件研究路由 | 国际影响节点固定自动调用 `_load_event_study_data` 整合历史案例（ToolNode 已休眠），且事件没有层级与目标标识。 | 检索参数固定、结果不稳定，无法确定性地向市场、板块或个股层路由（如事件无作用域字段，行业政策无法路由到对应板块）。 | 已审核事件补充 `market`/`sector`/`stock` 作用域及目标对象；各信息 Agent 仅预取本层事件，并以前置证据注入 Prompt。 |

| 跨层协作 | 上层报告与事件原文可能混用，技术分析存在接收事件数据的路径。 | 层间职责与上下文边界不清，技术结论可能受事件文本直接干扰（如技术 Prompt 可能注入新闻原文，把消息面当技术面）。 | 市场 → 板块 → 个股单向继承结论；不重复注入上层事件原文；所有技术 Agent 与事件/信息报告隔离。 |

| 海外节点与兼容 | US/KR 数据能力不足，既有下游仍依赖旧文本字段。 | 启用海外节点会产生未经数据时点验证的结论；直接切换字段会破坏存量调用（如 US/KR 占位接口输出混入无时点结论；下游已正则解析 `market_regime`）。 | US/KR 保持停用直至数据能力与时点验证达标；保留现有拓扑、全文 `report` 字段和单票模式；`market_regime`/`market_event_calendar` 原地升级为结构化 dict，消费方同变更内同步改造。 |

### 1.2 非目标

- 不修改市场 → 板块 → 个股的总体拓扑，不引入新的 LLM 编排框架；

- 不将板块轮动、行业选择、个股买卖点职责挪入市场层；

- 不在首期将所有未审核的实时新闻自动写入事件研究正式库；实时候选与已审核历史样本严格分离；

- 不承诺使用免费数据源覆盖所有海外市场数据；

- 不把 LLM 输出直接作为交易指令，所有结论仍标注“基于公开数据的方向性判断，不构成投资建议”。

## 三、事件作用域、目标对象与历史样本路由

### 详细设计

> 模块总览（每一行对应下方一个设计模块小节）：

| 维度 | 问题 | 方案概览 |

|---|---|---|

| 数据模型 | 事件库没有作用层级与目标对象，无法确定性路由到市场/板块/个股（如 `events` 表无 `event_scope`/`affected_scope_refs` 列，同名事件无法区分作用于大盘还是某行业） | 新增 `event_scope`/`affected_scope_refs` 正交路由字段；AI 预填建议值 + 审核确认入库，读写层归一化 |

| 审核、查询与预取 | 审核入口缺作用域提交点；检索无路由与时点过滤，可能混入未来样本（如 approve 仅落 `review_fields` 既有字段、无作用域；查询无 `as_of`，历史任务会读到 `announced_at > trade_date` 的事件） | 两条审核链路 AI 回填 + 服务端校验（格式/存在性/组合）；按路由 + `as_of` 查询并建立 JSONB/B-tree 索引 |

| 分层消费与隔离 | 事件无法按层确定性注入；技术分析受事件文本直接干扰（如技术分析存在接收事件数据的路径，上层报告与事件原文可能混用） | 三层各预取本层作用域事件；技术 Agent 不读取任何事件或信息研究报告 |

| 板块/个股事件生产与消费 | 板块/个股层事件条目结构、消费与降级未定义（如 `sector_news_analyst.py:31` 已消费 `get_industry_policy_news` 政策新闻流，与新历史样本预取的关系未定义） | 三字段同构矩阵；与政策新闻流并存分工；单票模式不加打名单接口；原文不跨层透传 |

#### 数据模型

`event_type`、`event_subtype`、`event_condition`继续作为事件性质和历史模板标签；新增正交路由字段，禁止以 `importance` 或自由文本推断层级。

| 字段 | PostgreSQL 类型 | 写入者 | 约束/示例 | 说明 |

|---|---|---|---|---|

| `event_scope` | `VARCHAR(16)` | AI 预标注（建议值）+ 审核人确认 | `market` / `sector` / `stock`，非空 | 最细作用层级；单事件只属一层 |

| `affected_scope_refs` | `JSONB` | AI 预标注（建议值）+ 审核人确认 | `[]`、`["SW:801080"]`、`["stock:600519.SH"]` | 层内目标对象；市场事件固定空数组 |

| `event_scope` | 目标约束 | 路由 |

|---|---|---|

| `market` | 必须 `[]` | 仅市场信息研究 Agent |

| `sector` | 至少一个行业/概念稳定引用 | 仅命中目标的板块信息研究 Agent |

| `stock` | 至少一个统一市场后缀股票代码 | 仅命中目标的个股信息研究 Agent |

行业使用既定申万/东财代码，概念使用 `CONCEPT:<稳定代码>`（如 `CONCEPT:BK1753.DC`，**写入即归一化为稳定代码**，source 锁定东财 dc 代码——已确认决策：行业申万代码、概念东财 dc），股票使用统一市场后缀代码；展示名只能由映射表解析。物理列首期允许 `NULL`，读写层归一化为 `market` + `[]`；未经审核确认回标的旧事件不得路由到板块或个股（旧事件批量 AI 回标本期不做，已确认）。

#### 审核、查询与预取

作用域与目标由 **AI 自动填写**：`ai_prelabel.py` 扩产 `event_scope`、`affected_scope_refs` 建议值写入草稿 `ai_suggestions`（与既有 `ai_suggestions` 预填模式一致，表单默认链 suggestions ?? importance_hint ?? 3），审核表单回填为默认值（标注“AI 预填，请确认”），人工可改。审核通过时以表单提交值入库；服务端校验作用域、引用格式、引用**存在性**（对照集合与事件研究**同库**：liveprofit 库 public schema 的 store 表 `stock_basic`/`concept`（source 锁定东财 dc，已确认），复用同一 `pg_dsn()` 连接；行业集合为静态码表或 provider 快照落库，步骤 3 前置）及作用域—目标组合，校验失败不得入正式库。校验失败 = 行级失败：草稿保留、表单可修正后重提（含回退 `market` 重提路径）；校验失败抛**独立异常**（非草稿不存在语义）→ review_adapter 翻译 → review_service 映射 `REVIEW_ROW_FAILED`，不得映射为 `REVIEW_DRAFT_NOT_FOUND`。校验落点分工 = AI 侧 `review_dao` 共享校验 + 平台 `review_service` 提交前前置校验（同一规则，双保险）。AI 预填不可用/解析失败时表单默认 `market`，下层作用域无目标仍阻止通过。`ignored` 事件保存默认值但不参与检索。校验覆盖两条审核链路：AI 侧 Streamlit（`review_app.py` + `review_dao.py`）与平台侧（backend `EventStudyReviewService` → 防腐层 `review_adapter` → `review_dao`），平台侧 schema/表单/服务校验同步改造（见文件变更），任一路径不得绕过作用域校验。改造需评估与“平台集成 AI 侧零改动”约定（见 done/事件研究审核界面平台集成方案）的边界：`review_dao` 行为变化由既有 `tests/event_study/test_review_regressions.py` 与新增契约测试共同守护。

#### 分层消费与隔离

1. 市场：`international_event_extraction` 只处理 `market` 事件和实时市场候选。

2. 板块：`sector_news_analyst` 只预取命中扫描范围的 `sector` 事件；市场报告仅作背景分段。

3. 个股：`news_analyst` 只预取命中 `company_of_interest` 的 `stock` 事件；市场、板块报告仅作背景分段。

4. 技术 Agent 不读取任何事件或信息研究报告（板块技术对板块新闻主线的技术面确认边界：可消费主线结构化摘要做技术确认、禁止事件/CAR/原文注入，已确认决策）。

5. 同层资产覆盖缺失时返回 `historical_impact = null` 和原因，不跨层借用沪深 300 CAR。

#### 板块/个股事件生产与消费

`international_events`、`sector_events`、`stock_events` 三字段同构（至少包含：`event_id`、`event_scope`、`affected_scope_refs`、分类、`event_time`、事实、`historical_impact`（可为 null + 原因）、`confidence`、来源、`data_quality`；市场层条目另含 `market_confirmation`、`history_match_status`，见第五章），仅作用域与目标不同；每层最多注入 5 条，State 仅保留实际引用摘要。

| 字段 | 写入者 | 消费方 | 注入点 | 降级 |
|---|---|---|---|---|
| `international_events` | `international_event_extraction` | `international_news_analyst`（事件类证据）；下游信息研究背景 | 国际影响 Prompt 注入 | `no_sample`/`api_unavailable` 时 `historical_impact=null` 并附原因，不升级门控 |
| `sector_events` | `sector_news_analyst` | 板块层内部分析；个股层背景摘要 | 板块新闻 Prompt 注入（`sector_event_prefetch` 结果） | 同上；无命中事件时为空列表 |
| `stock_events` | `news_analyst`（个股） | 个股层内部分析 | 个股新闻 Prompt 注入（`stock_event_prefetch` 结果） | 同上；无命中事件时为空列表 |

- 与既有 `get_industry_policy_news` **并存分工**：前者是当期产业政策新闻事实流（近 7 日 PG approved + Redis pending 合并，`event_type='产业政策' OR importance≥4`，见 done/板块层轮动战术与政策事件流方案），后者是作用域路由的事件研究历史样本统计。`sector_news_analyst` Prompt 中两者分块注入，历史统计不得引用政策新闻流文本冒充 CAR 证据。

## 十二、公共设计与实施

### 公共 State 与风险门控

| 字段 | 类型 | 写入者 | 说明 |

|---|---|---|---|

| `international_events` | `list[dict]` | 国际事件提取 | 市场事件、事实、目标、引用的历史统计与局限 |

| `sector_events` | `list[dict]` | 板块信息研究 | 命中板块事件、目标和统计 |

| `stock_events` | `list[dict]` | 个股信息研究 | 命中股票事件、目标和统计 |

| `global_risk_assessment` | `dict` | 国际影响 | 风险偏好、系统风险、传导、风险价格证据 |

| `market_event_calendar` | `dict` | 中国新闻 | 三级别资金日历与压力来源（str → dict 原地替换） |

| `market_regime` | `dict` | 中国技术 | 只含技术、宽度、资金、估值、流动性（str → dict 原地替换）。最小 schema：`short_term`/`wave`/`long_term` 各含 `level`（短线段枚举 适合/谨慎/回避/信息不足、波段段 进攻/平衡/防御/信息不足、长线段 配置窗口/等待窗口/信息不足）与证据/确认/失效/置信度；另含 `style`、`sentiment_cycle` 固定枚举与 `data_quality` 子字段（键名与第八章 Prompt 输出模板一致） |

| `market_data_quality` | `dict` | 图启动初始化（`build_data_quality_summary`） | 截至日期、缺失项、降级级别；各节点只读，节点级缺失内嵌于各结构化输出的 `data_quality` 子字段 |

| `risk_gate` | `str` | `derive_risk_gate` 纯代码节点（原地替换正则派生实现） | `normal/caution/block` |

除 `market_data_quality`、`risk_gate` 为纯代码确定性产出外，其余结构化字段（`international_events`、`sector_events`、`stock_events`、`global_risk_assessment`、`market_event_calendar`、`market_regime`）均由各 LLM Agent 在运行时**自动填写**，人工不参与；其内容受各章 Prompt 规则与结构化输出格式约束。

数据质量包含 `analysis_date`、各输入实际日期、`missing_inputs`、`degradation_level` 和 `future_data_detected`。

`risk_gate` 不再正则解析 Markdown，由 `derive_risk_gate` 按以下有序规则表**短路判定**（逐条命中即返回，不进入后续规则；枚举与现状一致，仓位管理零改动）：

| 序 | 条件 | 结果 |
|---|---|---|
| 1 | `global_risk_assessment.systemic_risk = high` 且 `confidence >= 中` 且核心质量非不足 | `block` |
| 2 | `market_regime` 短线 = 回避 且核心质量非不足 | `block` |
| 3 | 核心质量不足（判据见下） | `caution`（全局上限：质量不足最高 `caution`，不得 `block`） |
| 4 | `systemic_risk = medium` 或 短线 = 谨慎 或 波段 = 防御 | `caution` |
| 5 | 其余 | `normal` |

核心输入清单：`global_risk_assessment` 的风险价格证据（第六章特征组表中阶段 = 3 的组）与 `market_regime` 短线判据组（宽度趋势 + 成交额/高标情绪）。核心质量不足判据 = 以下任一，且**节点级子字段优先于启动快照**（运行中途暴露的缺失以子字段为准）：(a) `market_data_quality`（启动快照）中对应核心输入实际日期缺失或 `degradation_level = insufficient`；(b) `global_risk_assessment`/`market_regime` 的 `data_quality` 子字段出现同类状态（Provider 中途返回 `None` 属此列）；(c) 门控对 `global_risk_assessment` 或 `market_regime` 结构解析失败（含必需枚举字段缺失/不可解析）；(d) 输出级不足枚举：`systemic_risk = insufficient` 或短线 = 信息不足（等价要求：节点输出为不足枚举时，其 `data_quality` 子字段必须标注 `insufficient`，否则视为违约写实现错误）。预取历史参考的 `no_sample`/`api_unavailable` 不构成核心质量不足，不升级门控；CAR 仅作条件化参考、不作为门控输入（已确认决策）。关键数据不足由当前 fail-open 改为 `caution`（已确认决策：fail-open → caution）。

字段枚举（与各章 Prompt 输出模板一致，门控为精确匹配）：`systemic_risk ∈ {high, medium, low, insufficient}`（规则 1/4 均以 `systemic_risk` 字面量匹配）；`confidence ∈ {high, medium, low}`，“不低于中” = high/medium，缺失或解析失败视为不满足规则 1（不得 `block`）；`market_regime` 短线 ∈ {适合, 谨慎, 回避, 信息不足}、波段 ∈ {进攻, 平衡, 防御, 信息不足}（对齐第八章结论候选）。

### Provider 接口约束

### 已确认决策

#### 已确认

- 保持独立 LangGraph 子图和当前中国主链路。

- 事件研究按同层 Prompt 前置证据融合，不新增图节点；技术 Agent 不调用也不读取事件。

- 路由字段采用 `event_scope`、`affected_scope_refs`；旧性质标签保留。

- **直接替换、不并存**：`market_regime`/`market_event_calendar` 原地改类型（str → dict）、`derive_risk_gate` 原地重写为有序规则表，同一变更内同步改造全部消费方；不设运行期回退开关。新结构化字段直接用语义名（`international_events`/`sector_events`/`stock_events`/`global_risk_assessment`/`market_data_quality`），不用 `_v2` 后缀。

- 作用域与目标由 AI 预标注自动生成建议值、审核人确认（或修改）后入库——与既有 `ai_suggestions` 预填模式一致（表单默认链 suggestions ?? importance_hint ?? 3），AI 不可用时人工照旧填写。

- 报告单向继承，禁止上层原始事件重复注入下层。

- Provider 遵循基类优先、优先 Tushare 覆写（AKShare 仅补缺）契约；特征接口为结构化例外组（基类默认 `None`）。

- 核心数据 `insufficient` 时风险门控改为 `caution`（fail-open → caution）：第十二章规则 3 保留，`test_risk_gate.py` 断言按新语义。

- 估值分位 POC 失败时接受长线固定“信息不足”（保留“只给技术趋势”降级）。

- 数据源按 Tushare 代理 POC 实测结论立项，接受对应降级路径（长线“信息不足”、国际风险用可得子集）。

- 不要求任意历史 `trade_date` 严格回放；有历史能力的数据严格截止 `trade_date`、无历史能力显式降级，回放能力渐进扩大。

- 保持 `COUNTRIES = ["cn"]`，US/KR 继续停用。

- 阈值首期常量集中在 `market_features.py` 顶部并单测覆盖，回测定值后只改常量；确认频繁调参需求后再配置化。

- CAR 纯条件化参考，不单独升级 `risk_gate`。

- 板块目标引用：行业用申万代码、概念锁定东财 dc 代码（`CONCEPT:BK1753.DC` 形态）。

- 旧事件批量 AI 回标本期不做：迁移只归一 `market`；回标等三级路由验证有效后再评估。

- 接受板块/个股历史样本覆盖不足的渐进上线（首期给事件事实与“覆盖不足”标记，历史统计渐进补齐）。

- 板块技术可消费板块新闻主线的结构化摘要做技术确认，仍禁止事件/CAR/新闻原文注入；实现时同步修订板块层.md。
