2. **R1-02 / major / 维度 2、3、9 / §4.1.1 L178、182，§4.3.1 L252、255、259，§4.4.1 L298**：停牌豁免需要 PG 重建，但未定义 `market.trade_status_daily` 写入和消费。现有 `collect_stock_quant_day` 与 qfq 因子门控绑定，不能直接复用；须独立 helper、可信完整字段、保护旧状态及量化字段，测试 Redis 清空后重建。
3. **R1-03 / major / 维度 4、6、9 / §4.2.1 L224–228、§4.3.1 L256**：公共锁漏了维护文档直接调用 `backfill_index_history`；旧采集吞 DB/rollback 异常继续拉源；锁不能等 daily_job 后续 AI 阶段才释放。须完整入口 wrapper/unlocked 清单、断连 fatal error、finally 解锁及直接入口测试。
4. **R1-04 / major / 维度 6 / §4.2.1 L218、§4.6.1 L356**：QUEUED 每 60 秒补发会在离线一天产生约 1440 条重复消息；与离线保留一份状态冲突。须存活/忙闲门控、退避上限、多 Dispatcher CAS，以及一小时离线/90 分钟忙碌消息数上界测试。
5. **R1-05 / major / 维度 6、9 / §4.3.1 L259、§4.5.1 L321、325**：个股 bars GET 在 bfq 不齐时调用上游；定时及每 10 秒失效可放大源请求，绕过采集锁/冷却。须自动 refetch 只读，或为按需因子设独立并发/冷却并定义锁边界；测试缺 bfq 且源失败时调用上界。
6. **R1-06 / major / 维度 1、5、9 / §4.4.1 L300**：“窗口不足仍 NO_HOT_CONCEPTS”与 `_compute_sector_heat` 三段降级及单行契约测试冲突。应保留三段 heat_v1，新增当日有效行筛选；若改算法则需要正式版本与双链路迁移。
7. **R1-07 / major / 维度 7 / §4.6.3 L370–372**：market_data integration 与 API contract 的逐例清理都漏现有 `market.trade_status_daily`，新增停牌测试会串数据。须两处 fixture 清理及“上一例已停牌、下一例未知”的反向测试。
8. **R1-08 / major / 维度 7 / §4.6.3 L370–372**：只清业务前缀无法清 Dramatiq namespace；`configure_broker` 有 `_configured` 单例，第二次不同 URL 不会切库；contract fixture 实际 flushdb，与文档叙述不符。须隔离 Broker namespace/进程、定向清理与连接断言，不能依赖重复 configure 切库。

11. **R1-11 / minor（影响实施一致性）/ 维度 3、10 / §4.1.1 L184–187、§4.3.1 L255、§4.4.1 L285–290、298**：目标日 11 个代码和窗口 33 个 code/date 的计数不清，成员重复及每概念100截断口径未定。分别定义目标日/窗口恒等式、停牌分母、工作单元及截断前成员关系计数。
