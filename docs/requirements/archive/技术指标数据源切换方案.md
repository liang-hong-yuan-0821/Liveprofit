## 一、背景与动机

| 维度 | 现状 | 问题 | 目标 |
|------|------|------|------|
| 整体 | 大盘页指数 K 线指标（MA5/10/20/60 + BOLL(20,2)）由 [indicators.py../../../backend/modules/market_data/application/indicators.py) 纯 Python 自算；AI 个股技术指标由 [stockstats.py../../../AI/dataflows/technical/stockstats.py) 用 stockstats 库自算 15 项指标 | 用户拍板"不要自算了"（2026-09-12）：指标一律改用 Tushare 因子端点获取，删除本地计算链 | 大盘页指标与 AI 个股指标全部来自 Tushare 因子端点，仓库中不再存在技术指标计算代码 |
| 指数因子来源 | `stk_factor_pro` 官方文档标注"股票代码"，代理端点实测三个指数代码（000001.SH/399001.SZ/399006.SZ）短区间与 2020 年以来长区间均 0 行、全市场单日拉取 5549 行全为个股——**指数因子另有专用端点 `idx_factor_pro`**，实测三指数均正常返回 | 大盘页 K 线是指数，必须走 `idx_factor_pro`（`stk_factor_pro` 覆盖不到指数） | 指数因子经 `idx_factor_pro` 获取，与现有指数日线同源对齐 |
| 个股因子来源 | [stockstats.py../../../AI/dataflows/technical/stockstats.py) 的 `get_stock_stats` 对每个指标都执行一次 `get_china_stock_data`（拉 365 天日线文本 → 逐行 split 解析 → stockstats 计算），`get_indicators_report` 循环 15 个指标 = **15 次行情拉取 + 15 次解析 + 15 次计算**；`stk_factor`（旧端点）实测因子列全为 None（代理已降级） | 个股因子应走 `stk_factor_pro`（实测 600000.SH 返回 9 行、MA/BOLL/MACD/KDJ/RSI 字段齐全），一次调用拿全部因子 | AI 个股技术指标报告一次 API 调用生成，删除 stockstats 计算链 |

## 二、架构设计

数据流（改造后）：

```
                    ┌────────────────────────── market_ingest（run.sh start_all 时执行，幂等可重复）──────────────────────────┐
                    │   index_daily ──→ market_bars_daily（存量，不动）                                                        │
                    │   idx_factor_pro ──→ market_index_factors（新表，全历史回填 + 日增量）                                   │
                    └──────────────────────────────────────────────────────────────────────────────────────────────────────┘
GET /market-data/indices/{symbol}/bars
        │ MarketDataService.get_bars：直接读 [from, to] 区间 bars + factors（不再补窗口、不再自算）
        │                              → 按 trading_date 对齐组装 indicators（ma/boll/macd）
        ▼
BarsData.indicators（契约形状不变，新增 macd；bars 空时 null）
        ▼
前端 CandlestickChart（MA/BOLL 主图不变；macd 存在时渲染副图）

AI 个股侧：agent_utils.get_stockstats_indicators_report（LLM tool，签名不变）
        │ StockstatsUtils.get_indicators_report（重写实现）
        │   TushareProvider.get_stock_factor_df（stk_factor_pro，一次调用）
        ▼
技术指标报告文本（14 项 API 口径因子，原 15 项中 4 项替换、1 项删除，见 3.4）
```

### 2.1 数据模型设计

新表 `market_index_factors`（新迁移 **0005**——`0004_agent_prompt_overrides.py` 已占用 0004 且业务库 `alembic_version` 实测为 `'0004'`；与 `market_bars_daily` 同库同 schema）：

| 字段 | 类型 | 写入者 | 说明 |
|------|------|--------|------|
| id | UUID PK | ORM 默认 | 主键（`default=uuid.uuid4`，同 MarketAsset 模式） |
| asset_id | UUID FK→market_assets | ingestion | 资产外键；示例：上证综指资产行的 UUID |
| trading_date | DATE | ingestion | 交易日；示例：`2026-09-11` |
| ma_bfq_5 / ma_bfq_10 / ma_bfq_20 / ma_bfq_60 | NUMERIC(18,6) | ingestion | 简单移动平均（不复权），N=5/10/20/60；示例：3929.45422 / 3942.70473 / 3934.80384 / 3941.71923（000001.SH @ 2026-09-11 实测） |
| boll_mid_bfq / boll_upper_bfq / boll_lower_bfq | NUMERIC(18,6) | ingestion | 布林带中/上/下轨（N=20, P=2，不复权）；示例：3934.804 / 4001.526 / 3868.082（同上实测） |
| macd_dif_bfq / macd_dea_bfq / macd_bfq | NUMERIC(18,6) | ingestion | MACD DIF/DEA/柱（SHORT=12, LONG=26, M=9，不复权）；示例：1.796 / 5.413 / -7.233（同上实测；上游 macd_bfq ≈ 2×(DIF−DEA)，精度为上游口径） |
| source_updated_at | TIMESTAMPTZ | ingestion | 入库采集时间（与 market_bars_daily 同模式，区分数据时点） |

- 约束：`UNIQUE(asset_id, trading_date)`（与 bars 表同模式）。
- 全量因子字段约 100 个（薛斯通道/梅斯线等），本方案只建**契约消费的 10 列**——存全量 JSONB 会把永不用到的字段写进读模型；未来新增指标（如 KDJ 副图）按需加列迁移。
- 本表只存不复权（`_bfq`）变体：指数无复权概念，且实测 idx_factor_pro 的 close 与 index_daily 完全一致（3888.1106 == 3888.1106），因子与 bars 可直接按 trading_date 对齐。
