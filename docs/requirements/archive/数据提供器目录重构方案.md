## 一、背景与动机

### 1.1、现状

Liveprofit 数据提供器层当前为**扁平目录**（`AI/dataflows/providers/`）：

```
providers/
├── __init__.py              # 仅 docstring，无导出
├── base_provider.py         # BaseStockDataProvider 接口契约基类
├── akshare_provider.py      # AKShareProvider（约 2037 行）
├── tushare_provider.py      # TushareProvider（约 2209 行）
├── daily_matrix_utils.py    # 板块逐日矩阵纯函数（仅两 provider 使用）
└── limit_ladder_utils.py    # 连板梯队纯函数（仅 tushare provider 使用）
```

参考项目 TradingAgents-CN 将中国市场提供器组织为**子包 + 无后缀命名**：

```
providers/china/
├── __init__.py
├── akshare.py
├── tushare.py
├── baostock.py
└── fundamentals_snapshot.py
providers/base_provider.py   # 基类留在 providers 层（跨市场契约）
```

Liveprofit 侧引用旧模块名的位置已全部盘点（见 3.2–3.4）：**代码 5 个文件**（interface.py、store/backfill.py、eventStudy/collectors 2 个、sectorAgents/charts.py）、**测试/脚本 9 个文件**、**主干文档 3 个**（CLAUDE.md、市场层.md、板块层.md）；另有 docs/done/ 归档 11 个按约定保留不动。

### 1.2、目标

- 目录层级与模块命名对齐参考结构：`AI/dataflows/providers/cn/{tushare,akshare,daily_matrix_utils,limit_ladder_utils}.py`
- **纯结构调整**：类名（`TushareProvider`/`AKShareProvider`）、接口契约（str-Markdown，CLAUDE.md 强制规则）、功能代码零变更（唯一例外：`base_provider` 相对导入上移一层）
- 全量更新 3.2–3.4 表内全部引用（10 处代码 import + 9 个测试/脚本文件 + 3 个主干文档），**不留旧名 shim**（用户已拍板）

## 二、架构设计

### 目标结构

```
AI/dataflows/providers/
├── __init__.py               # docstring 更新为新布局说明（无导出，与现状一致）
├── base_provider.py          # 不动：跨市场接口契约基类（对齐参考：基类在 providers 层）
└── cn/                       # 新建子包（用户指定名 cn，非参考的 china；与 Liveprofit market="CN" 命名一致）
    ├── __init__.py           # 新建，仅 docstring
    ├── tushare.py            # ← tushare_provider.py
    ├── akshare.py            # ← akshare_provider.py
    ├── daily_matrix_utils.py # ← 移入（纯函数，无相对导入，零改动）
    └── limit_ladder_utils.py # ← 移入（同上）
```

**布局决策**（评审可质疑）：

1. **`base_provider.py` 留在 `providers/` 层**：它是跨数据源/跨市场的接口契约，参考实现同样将 base 置于 china/ 之上；其自身引用点零改动。
2. **两个 utils 随 provider 一起移入 `cn/`**：二者仅被 cn 包内的 provider 使用（daily_matrix_utils 被两 provider 共用），且无任何相对导入 → 移动后包内相对导入 `from . import daily_matrix_utils` / `from .limit_ladder_utils import ...` **字面不变**。若留在 providers/ 层，则 provider 需改用 `from .. import ...`，把 CN 专属代码拆散在两个层级。
3. **`cn/__init__.py` 为空壳（仅 docstring）**：用户未采纳参考的 `*_AVAILABLE` 导出模式；导入统一走 `AI.dataflows.providers.cn.<模块>`。
4. **docs/done/ 归档文档不更新**：done/ 是历史决策记录（CLAUDE.md 约定"历史参考，不删除"），其中引用的旧路径保留原样。

### 数据模型设计

不适用——无共享状态、无跨模块接口变更。
