# 关键决策记录

按时间**倒序**追加。每条四要素：背景 → 选项 → 拍板结论 → 理由。

## 2026-09-14 templates 放全量模板

- **背景**：任务文件夹 8 文件骨架需要模板支撑；templates/ 原只有 plan/tasks 两模板。
- **选项**：① 只给必建文件（README/plan/tasks）配模板；② 8 文件全配模板。
- **结论**：② 8 文件全配模板（用户拍板）。
- **理由**：骨架全建（attachments 按需），模板也要齐全，新建任务文件夹时一次复制到位。

## 2026-09-14 骨架全建（8 文件）

- **背景**：此前方案建议"README+plan 必建、其余按需"；用户随后在方案树中改为全建。
- **选项**：① 按需建（轻任务不造空壳）；② 8 文件全建（attachments 按需）。
- **结论**：② 全建（用户拍板）。
- **理由**：8 文件各司其职、结构统一；轻任务容忍空壳。

## 2026-09-14 tasks.md（原 execution 更名）

- **背景**：任务清单载体——旧制度是 docs/tasks/<方案名>.md 平铺清单；骨架初稿用 execution.md。
- **选项**：① 顶层 docs/tasks/ 目录；② 任务文件夹内 tasks.md（与 plan.md 同级，原 execution 更名）。
- **结论**：②（用户拍板）。
- **理由**：任务资料聚拢在任务文件夹；CLAUDE.md Tasks 约定内容迁入 tasks.md，随文件夹归档保留。

## 2026-09-14 桶名 requirements/ 与 knowledge/

- **背景**：任务桶曾名 workflow/、tasks/，均被用户否定。
- **结论**：任务桶 = requirements/；知识桶 = knowledge/（用户拍板）。
- **理由**：requirements 贴合"任务"语义且不与骨架文件 tasks.md 冲突；knowledge 对应"知识沉淀"。

## 2026-09-14 评审触发规则

- **背景**：本方案因结构 3 次调整反复触发全量评审，走了 6 轮，节奏拖慢。
- **结论**：初版方案自动评审；之后任何修订只有用户说"走评审"才评审（已写入 CLAUDE.md）。
- **理由**：结构性修订风险由方案自带验证步骤兜底，不靠反复开轮。

## 2026-09-13/14 三桶结构

- **背景**：docs/ 一级文档平铺，过程文档与知识文档混排；用户要求分桶。
- **结论**：requirements/（任务）+ knowledge/（知识）+ memory/（经验）三桶，index.md 总导航。
- **理由**：任务过程、领域知识、经验教训三种内容生命周期不同，分桶后各守各的写入规则（见 CLAUDE.md「knowledge/ 刻意使用」）。
