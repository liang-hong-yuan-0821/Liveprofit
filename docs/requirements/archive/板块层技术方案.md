## 一、背景与动机

### 1.1 现状

- [板块层.md](../../knowledge/ai/板块层.md) 已规划了 `SectorAnalyst`（板块分析师）的定位，但**未实现**
- 原 `tech_market_analyst.py` 已删除，其 AI 产业链工具（`get_ai_industry_chain`、`get_tech_correlation_analysis`）保留在 Toolkit 中，归属板块层
- 当前已有概念板块数据能力：`get_concept_board()` / `get_all_concept_boards()`，覆盖 9 个 AI 产业链概念板块
- 市场层已实现并产出 7 份宏观报告（含 `cn_tech_report` 中的市场风格/环境判断）

### 1.2 数据基础：行业板块指数 K 线

板块层分析的主体是**申万行业板块指数**。每个申万行业（如汽车、医药、食品饮料……）都有一条板块指数，它是该行业所有成分股的综合价格曲线，有完整的 OHLCV 日线数据。

```
数据来源：ak.stock_board_industry_hist_em(symbol="汽车行业", period="daily")
返回字段：日期、开盘、收盘、最高、最低、成交量、成交额、涨跌幅
```

板块层的技术分析就是对这些**行业板块指数 K 线**做指标计算（均线、RSI、MACD、量价关系），与个股技术分析的方法论一致，只是分析对象从"个股K线"变成了"行业板块指数K线"。

### 1.3 目标

**填补三层金字塔的第二层空白**：在市场层（宏观环境）与个股层（单票分析）之间，加入**全市场行业/概念板块的横向对比分析**，形成完整的"市场 → 板块 → 个股"自顶向下分析链路。

板块层核心回答三个问题：
1. **哪些板块在走强？** — 申万行业涨跌排名 + 概念板块热度
2. **资金在往哪流？** — 行业板块资金流向 + 主力资金偏好
3. **当前市场在交易什么逻辑？** — 板块轮动主线识别 + 风格因子验证

## 二、架构设计

### 2.1 整体结构

板块层作为**独立编译的 LangGraph 子图**（`AI/sectorAgents/sector_layer_graph.py`），位于市场层之后、个股层之前：

```
顶层 Graph（个股维度）
├── Subgraph: 市场层（已实现 ✅）
├── Subgraph: 板块层（本期实现）    ← 独立编译，共享 state
│   ├── 板块新闻分析 (Sector News)  — 行业排名 + 资金流向 + 板块轮动
│   └── 板块技术分析 (Sector Tech)  — 全行业技术扫描 + AI专题深挖 + 风格验证
└── 个股层 + 辩论 + 风控
```

### 2.2 板块层子图内部

```
START
  → Sector News Analyst  ←→ tools_sector_news  → Msg Clear
  → Sector Tech Analyst  ──→ Msg Clear           (直接边)
  → END
```

> - 新闻类 Agent 保留工具循环（多轮获取不同类型的板块数据）
> - 技术类 Agent 用直接边（一次性拉取数据后分析输出）
> - 子图与父图共享同一个 `AgentState`，子图写入板块层字段，个股层直接读取

### 2.3 与市场层的关系

板块层**依赖**市场层的以下产出作为输入上下文：

| 市场层字段 | 板块层用途 |
|-----------|-----------|
| `cn_tech_report` | 大盘环境基调（牛/熊/震荡）、风格因子（大小盘、成长/价值） |
| `cn_news_report` | 资金日历事件（IPO/解禁/交割日→对板块资金面的影响） |
| `international_news_report` | 全球宏观风险偏好（影响板块选择：进攻 vs 防御） |

板块层 Agent 的 prompt 中注入市场层上下文摘要，使板块判断有"大盘环境"这个锚。

### 2.4 上游数据注入

板块层从 State 中读取市场层字段的方式与个股层一致——通过 `state.get("field_name", "")` 安全读取。在板块层子图入口处，组装市场层上下文的摘要版本：

```python
def _build_sector_context(state) -> str:
    """组装市场层中与板块分析相关的上下文摘要"""
    parts = []
    cn_tech = state.get("cn_tech_report", "")
    cn_news = state.get("cn_news_report", "")
    intl_news = state.get("international_news_report", "")
    
    if cn_tech and len(cn_tech) > 20:
        parts.append(f"## 大盘环境\n{cn_tech[:800]}...")  # 截断，只取摘要
    if cn_news and len(cn_news) > 20:
        parts.append(f"## 资金日历\n{cn_news[:500]}...")
    if intl_news and len(intl_news) > 20:
        parts.append(f"## 国际宏观\n{intl_news[:500]}...")
    
    return "\n\n".join(parts) if parts else "（市场层数据不可用）"
```

### 2.5 图谱集成

**父图（setup.py）集成**：

```python
# 创建板块层子图
sector_subgraph = SectorLayerGraph(llm, toolkit).build()

# 父图中插入到市场层之后、个股层之前
workflow.add_node("Sector Layer", sector_subgraph)
workflow.add_edge("Market Layer", "Sector Layer")
workflow.add_edge("Sector Layer", "Stock Tech Analyst")  # 接个股层第一个
```

**触发条件**：`selected_analysts` 中包含 `"sector"` 时运行。默认 `selected_analysts` 增加 `"sector"`。

### 2.6 可扩展设计

板块层子图采用与市场层一致的 `SectorLayerGraph` 类设计：

```python
class SectorLayerGraph:
    """板块层子图编译器"""

    ANALYSTS = ["sector_news", "sector_tech"]

    LABELS = {
        "sector_news": "Sector News",
        "sector_tech": "Sector Tech",
    }

    LOOP_KEYS = {"sector_news"}  # 新闻类有工具循环

    FACTORY_MAP = {
        "sector_news": create_sector_news_analyst,
        "sector_tech": create_sector_tech_analyst,
    }

    def __init__(self, llm, toolkit, max_tool_calls=3): ...

    def build(self) -> CompiledGraph:
        """编译并返回板块层子图"""
        workflow = StateGraph(AgentState)

        for key in self.ANALYSTS:
            label = self.LABELS[key]
            factory = self.FACTORY_MAP[key]

            workflow.add_node(f"{label} Analyst", factory(self.llm, self.toolkit))
            workflow.add_node(f"Msg Clear {label}", create_msg_delete())

            if key in self.LOOP_KEYS:
                tools = self._get_tools(key)
                if tools:
                    workflow.add_node(f"tools_{key}", ToolNode(tools))
                    workflow.add_conditional_edges(
                        f"{label} Analyst",
                        self._make_router(key),
                        {
                            f"tools_{key}": f"tools_{key}",
                            f"Msg Clear {label}": f"Msg Clear {label}",
                        },
                    )
                    workflow.add_edge(f"tools_{key}", f"{label} Analyst")
                else:
                    workflow.add_edge(f"{label} Analyst", f"Msg Clear {label}")
            else:
                workflow.add_edge(f"{label} Analyst", f"Msg Clear {label}")

        # 串行连接
        workflow.add_edge(START, f"{self.LABELS[self.ANALYSTS[0]]} Analyst")
        for i in range(len(self.ANALYSTS) - 1):
            src = f"Msg Clear {self.LABELS[self.ANALYSTS[i]]}"
            dst = f"{self.LABELS[self.ANALYSTS[i + 1]]} Analyst"
            workflow.add_edge(src, dst)
        workflow.add_edge(f"Msg Clear {self.LABELS[self.ANALYSTS[-1]]}", END)

        return workflow.compile()
```

> 板块层初期只有 2 个 Agent。如果未来需要扩展（如增加"板块轮动深度分析"Agent），只需在 `ANALYSTS` 中加 key + 写一个 Analyst 文件。

## 三、各 Agent 详细设计

### 3.1 板块新闻分析 (Sector News Analyst)

**文件**：`AI/sectorAgents/analysts/sector_news_analyst.py`
**输出字段**：`sector_news_report`
**工具循环**：有（多轮获取行业排名、资金流向、概念热度）

#### 职责

从"信息面 + 资金面"两个维度，扫描 A 股全量申万行业板块（约 30 个一级行业 + 100+ 二级行业）和概念板块的状态，不限于特定行业：

#### 分析内容

| 维度 | 内容 |
|------|------|
| **行业涨跌排名** | 申万一级行业近 N 日涨跌幅排序，识别领涨/领跌行业；二级行业做细分验证 |
| **资金流向** | 行业板块的主力资金净流入/流出排名，判断资金进攻方向 |
| **概念热度** | 热门概念板块的涨幅、成交额变化、持续性判断 |
| **政策/事件驱动** | 近期重大产业政策（如 AI、新能源、消费刺激）对相关板块的催化 |
| **板块轮动判断** | 是否有持续主线？还是快速轮动（无主线）？轮动方向是什么？ |
| **风格验证** | 结合市场层的风格因子判断（大小盘、成长/价值），验证板块层面的风格一致性 |

#### 工具

| 工具函数 | 用途 | 状态 |
|----------|------|:---:|
| `get_industry_sector_performance(days=10)` | 申万一级+二级行业涨跌排名 | **新增** |
| `get_sector_fund_flow(days=5)` | 行业板块主力资金净流向 | **实现**（已确认 `ak.stock_sector_fund_flow_rank()` 签名正确） |
| `get_concept_board_heat(days=10)` | 热门概念板块热度排名（涨幅+成交额综合） | **新增** |
| `get_industry_policy_news(curr_date)` | 近期产业政策/重大行业新闻 | **占位** |

#### Prompt 要点

- 明确告知 Agent 其角色是"板块维度的信息面分析"，不是个股分析
- 要求输出板块轮动主线判断（有主线/快速轮动/无方向），并给出置信度
- 结合市场层的大盘环境上下文（牛/熊/震荡、风格因子）给出板块层面的验证意见
- 数据不可用的工具如实标注，靠 LLM 训练知识做方向性补充

### 3.2 板块技术分析 (Sector Tech Analyst)

**文件**：`AI/sectorAgents/analysts/sector_tech_analyst.py`
**输出字段**：`sector_tech_report`
**工具循环**：无（直接边，一次性拉取数据后分析）

#### 职责

逐行业做技术面体检，输出全行业技术状态全景图。分析对象是**行业板块指数的日K线**（`ak.stock_board_industry_hist_em()` 返回的 OHLCV 数据），覆盖 A 股所有申万一级行业（汽车、医药、食品饮料、电力设备、电子、银行……约 30 个行业），对每条行业 K 线做均线/趋势/量价分析，判断各行业当前所处的技术阶段（趋势/震荡/反转），并结合市场层风格因子做交叉验证。

#### 分析内容

| 维度 | 内容 |
|------|------|
| **全行业技术扫描** | 逐行业（申万一级）做均线/趋势/量价分析，输出行业技术状态矩阵（强势/中性/弱势） |
| **行业相对强度 (alpha)** | 各行业相对大盘的超额收益排名，区分"真强势"（alpha 持续为正）和"补涨"（短期反弹） |
| **板块轮动技术验证** | 用技术指标验证板块新闻分析中识别的"主线"——领涨行业是否技术上健康（趋势不背离、量价配合） |
| **风格因子技术验证** | 用大小盘指数比值、成长/价值指数比值的趋势，验证市场层的风格判断 |
| **行业技术风险扫描** | 领涨行业是否出现高位放量滞涨/顶背离/M型头等需要警惕的信号；超跌行业是否出现底部放量企稳 |
| **AI/科技产业链专题** | 对科技相关行业做产业链级别的上下游轮动分析（存储芯片→半导体→光模块→AI服务器→算力→AI应用），判断当前热点位于产业链哪个环节，是否存在传导断裂或过热 |
| **全球科技映射** | 美股科技→韩股科技→A股科技板块的传导有效性判断（同步/背离/独立行情） |

#### 工具

| 工具函数 | 用途 | 状态 |
|----------|------|:---:|
| `get_industry_sector_performance(days=20)` | 全行业（申万一级+二级）近 N 日涨跌幅 + 均线数据，供技术形态判断 | **新增**（复用 §3.1 工具，调大 days，附加均线字段） |
| `get_sector_technical_screening(days=60)` | 逐行业批量计算技术指标（均线排列、RSI、MACD、量比），输出行业技术状态矩阵 | **新增** |
| `get_sector_relative_strength(days=20)` | 各行业相对大盘的 alpha 排名 | **新增** |
| `get_ai_industry_chain(days=10)` | AI 产业链各细分板块数据（专题深挖用） | **已有**（从旧 tech_market_analyst 继承） |
| `get_tech_correlation_analysis(days=10)` | 全球科技指数相关性 + 趋势预测（专题深挖用） | **已有**（从旧 tech_market_analyst 继承） |

> **工具使用策略**：Agent 先调用 `get_industry_sector_performance` + `get_sector_technical_screening` + `get_sector_relative_strength` 做全行业粗筛，然后对科技相关行业用 `get_ai_industry_chain` + `get_tech_correlation_analysis` 做专题深挖。

#### Prompt 要点

- 明确告知 Agent 其角色是"全行业板块技术面体检"，不是只分析 AI/科技
- 输出结构：全行业技术状态总览 → 重点行业（领涨/领跌/异动）深度分析 → AI/科技专题 → 风险提示
- 对板块新闻分析的结论做技术面交叉验证（如新闻说"汽车板块强势"，技术面确认量价是否健康、是否有背离）
- 结合市场层 `cn_tech_report` 的风格因子判断，验证板块层面是否存在风格背离（如市场层判断"大盘价值占优"，但板块层发现小盘成长板块也在放量走强——可能是风格切换前兆）

### 9.3 AKShare — 端点验证明细

#### `ak.stock_board_industry_name_em()` — 行业板块列表

- **功能**：获取东方财富行业板块名称列表
- **返回字段**：板块名称、板块代码、涨跌幅等
- **验证状态**：✅ AKShare 标准接口，广泛使用

#### `ak.stock_board_industry_hist_em()` — 行业板块历史行情

- **功能**：获取指定行业板块的历史日线数据
- **参数**：`symbol`（板块名称，如"半导体"）、`period`（"daily"）
- **返回字段**：日期、开盘、收盘、最高、最低、成交量、成交额、涨跌幅
- **验证状态**：✅ 与现有 `stock_board_concept_hist_em()` 同族接口

#### `ak.stock_sector_fund_flow_rank()` — 行业资金流向 ⚠️

- **功能**：获取行业资金流向排名
- **风险**：此端点在不同 AKShare 版本中的参数签名可能不同（`indicator` 和 `sector_type` 参数名需确认）。如不可用，降级方案：通过概念板块的成交额变化（量价配合）做资金流向的**代理判断**（放量上涨=资金流入，放量下跌=资金流出）。
- **降级策略**：若端点不可用，`get_sector_fund_flow` 返回"数据不可用：行业资金流向接口暂不可用，请通过板块涨跌幅和成交额变化自行判断资金方向"，Agent 靠 LLM 逻辑推断

#### `ak.stock_board_concept_name_em()` — 概念板块列表

- **功能**：获取东方财富概念板块名称列表
- **验证状态**：✅ 与现有概念板块接口同族，补充板块热度排序所需的全量列表
