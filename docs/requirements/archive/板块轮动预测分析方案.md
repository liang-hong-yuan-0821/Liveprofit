## 一、背景与动机

### 1.1 现状缺口

板块层已实现 `sector_news_analyst`（行业+概念横向对比）和 `sector_tech_analyst`（行业技术扫描），但两者对"板块热度/涨跌排名"的处理方式都是**单一区间快照**：

- `get_concept_board_heat(days=10)` 只计算"近 10 日累计涨跌幅 + 成交额变化"的**一次性综合排序**，返回一张静态 TOP30/TOP10 表
- `get_industry_sector_performance(days)` 同理，只有区间累计涨跌幅排名

这类"区间累计快照"能回答"过去 N 天谁涨得最多"，但**回答不了**：

- 这些热门板块是**连续多天**保持强势，还是**只有某一天爆发**（脉冲）？
- 昨天的 TOP 榜单，今天是否还在（动量延续），还是已经跌出（退潮）？
- 有没有**新出现**在榜单里的板块（新热点冒头信号）？
- 板块的赚钱效应到底有多强——**涨停家数**多不多？**连板高度**打到几板了？这是题材强度和情绪温度最直接的量化指标，单纯看涨跌幅排名看不出"是普涨还是有龙头打板"

而这些恰恰是"板块轮动规律"和"游资/情绪面强度"的核心信息，无法从现有的单一区间涨跌幅快照中还原。

### 1.2 目标

新增一个专门的"板块轮动预测分析师"节点，基于**逐日**的题材板块热度排名 + 涨停家数 + 连板高度数据，实现：

1. 拉取过去 5 个交易日，**每天单独**的题材板块热度排名（含涨停家数、连板家数、连板高度）
2. 汇总成"逐日轮动矩阵"，识别每个板块的上榜规律：连续上榜（强势主线）/ 新晋上榜（新热点）/ 掉出榜单（退潮）
3. 结合**涨停家数**（赚钱效应广度）和**连板高度**（情绪强度/龙头地位）做强度分级，区分"普涨式轮动"和"有龙头带动的真主线"
4. 输出对**明日**最可能上涨题材板块的预测结论（TOP3-5 + 置信度 + 逻辑链 + 风险提示）

### 1.3 范围界定（已与用户确认）

| 决策点 | 结论 |
|--------|------|
| 排名口径 | **逐日排名**（非区间累计） |
| 分析对象 | **题材/概念板块**，额外叠加**涨停家数 + 所属板块连板数**两个强度指标 |
| 落地形式 | **新增独立分析师节点**"板块轮动预测分析师"，串联在 `sector_news`/`sector_tech` 之后，产出独立报告字段 |
| **数据源**（关键变更） | **完全改用 Tushare 打板专题数据**（`limit_cpt_list` 最强板块统计接口），不再新增 AKShare 逐日遍历函数 |

### 1.4 数据源选型变更说明

原计划通过遍历 AKShare 概念板块列表 + 逐板块拉取K线，本地计算"逐日涨跌幅排名"，再另外新增"涨停股池 + 个股所属概念反查"来拼出涨停家数/连板数，实现链路长、计算量大（需要对数百个板块做个股级别的归属匹配）。

调研发现 **Tushare 官方"打板专题数据"下有现成接口 `limit_cpt_list`（最强板块统计）**，专为"板块轮动/资金动向分析"设计，**单次调用单个交易日即可直接拿到该板块当天的完整战斗力画像**。

#### 已确认字段（来源：Tushare 官方文档 doc_id=357）

| 字段 | 类型 | 含义 |
|------|------|------|
| `ts_code` | str | 板块代码（同花顺 THS 题材板块体系，`.TI` 后缀） |
| `name` | str | 板块名称 |
| `trade_date` | str | 交易日 |
| `up_nums` | int | 当日涨停家数 |
| `cons_nums` | int | 当日连板家数（板块内处于连续涨停状态的个股数量） |
| `up_stat` | str | 连板高度（如"9天7板"，表示该板块最强龙头股的连板战绩） |
| `days` | int | 该板块上榜天数（题材热度持续天数，官方口径，可能远超观察窗口） |
| `pct_chg` | float | 板块涨跌幅（%） |
| `rank` | **str** | 板块热点排名（官方综合排名，当日）⚠️ **注意：类型为 str，排序前必须 `pd.to_numeric()` 转换** |

> ⚠️ **`rank` 类型陷阱**：Tushare 官方文档标注 `rank` 为 `str` 类型。实际数据如 `"1"`, `"2"`, ..., `"10"`——直接 `sort_values("rank")` 会触发字典序排序（`"9"` > `"10"`），导致排名混乱。**所有使用 `rank` 做排序/比较的代码必须先 `pd.to_numeric(df['rank'], errors='coerce')` 显式转换。**

无需自建"个股 → 概念反查 → 聚合统计"的复杂链路，逐日循环调用该接口（每天一次请求）即可直接构造"逐日轮动矩阵"，同时天然自带涨停家数和连板高度两个强度指标，**完全覆盖本次新增需求**。

> **数据体系差异提示**：`limit_cpt_list` 用的是**同花顺（THS）题材板块分类**，与 `sector_news_analyst`/`sector_tech_analyst` 现有使用的**东方财富（EM/DC）概念板块体系**是两套独立分类（板块数量、名称、颗粒度均不同）。已与用户确认：**板块轮动预测分析师完全独立使用 THS 体系**，不强行与 EM 体系做板块名称对齐。详见 §二.5 跨体系引用策略。

#### Tushare 实现

```python
def get_concept_rotation_ranking(self, days: int = 5, top_n: int = 10) -> str:
    """
    获取近 N 个交易日题材板块轮动矩阵（Tushare 打板专题数据）。

    实现方式：逐日调用 limit_cpt_list(trade_date=<单日>)，汇总成包含逐日 TOP N 榜单、
    上榜统计、轮动分类标注、强度分级的完整 Markdown 表格。

    Args:
        days: 观察窗口（交易日数），默认 5
        top_n: 每日榜单取前 N 名，默认 10
    """
    if not self.connected:
        return "Tushare 未连接。"

    from AI.dataflows.utils.trading_calendar import get_last_trading_days

    # 使用交易日历工具获取近 N 个交易日日期列表（从晚到早）
    trade_dates = get_last_trading_days(n=days)
    if not trade_dates:
        return "交易日历不可用，无法获取轮动矩阵。"

    collected = []  # [(trade_date_str, DataFrame), ...] 按时间从早到晚

    for d in sorted(trade_dates):  # 排序为从早到晚
        try:
            df = self.api.limit_cpt_list(trade_date=d)
            if df is not None and not df.empty:
                # ⚠️ rank 字段为 str 类型，显式转数值
                df['rank_num'] = pd.to_numeric(df['rank'], errors='coerce')
                # 按 rank_num 升序排列（rank=1 是最强），同 rank 按 up_nums 降序兜底
                df = df.sort_values(['rank_num', 'up_nums'], ascending=[True, False])
                collected.append((d, df))
        except Exception:
            pass

    if not collected:
        return "近 {} 个交易日无打板专题数据。".format(days)

    # collected 已按日期从早到晚排列（trade_dates 已 sorted）
    ...
```

> **实现细节说明**：
> - `collected` 不再需要 `reverse()`——`trade_dates` 已经通过 `sorted()` 确保从早到晚，`collected` 直接按此顺序追加
> - 不再使用 `max_probe` 逐日回退机制（该逻辑迁移到 `trading_calendar` 中）
> - `limit_cpt_list` 对非交易日返回空 DataFrame（不抛异常），交易日历已前置过滤，无需额外判断

#### 数据汇总逻辑

1. **逐日 TOP 榜单**：每一天的 DataFrame 已按 `rank_num` 升序排列，直接取前 `top_n`

2. **上榜统计**：遍历 `days` 天的 TOP 榜单，按板块名称聚合统计：
   - 上榜次数、首次上榜日期、最近上榜日期、最后一天是否仍在榜
   - 连板高度峰值（`up_stat` 解析出连板数）在观察期内的变化趋势（走扩 / 走弱）
   - 涨停家数（`up_nums`）在观察期内的变化趋势（走扩 / 走弱）

3. **排名趋势扫描（TOP N 之外）**：对未进入每日 TOP N 的板块，追踪其 `rank_num` 变化趋势：
   - 若某板块 `rank_num` 在观察期内持续下降（排名持续上升），标记为**"蓄势上升"**——这是最强的轮动前兆信号之一，即使它尚未进入 TOP N
   - 输出中单独列出"TOP N 外蓄势上升板块"（最多 5 个）

4. **轮动分类标注**（纯规则计算，不依赖 LLM）：

   | 分类 | 判定条件 | 含义 |
   |------|----------|------|
   | **持续主线** | 上榜次数 ≥ 3 **且** 最后一天在榜 | 连续多天保持强势的板块 |
   | **新晋异动** | 仅最后 1-2 天上榜（此前未上榜） | 新热点冒头 |
   | **退潮** | 曾上榜但最后一天不在榜 | 热度下降 |
   | **蓄势上升** | 未进入 TOP N 但 `rank_num` 持续下降 | 边缘板块正在爬升，轮动前兆 |
   | **波动** | 其余 | 无稳定规律 |

5. **强度分级**（基于涨停家数 + 连板高度的**当日分位数**，非绝对阈值）：

   改用**当日横截面分位数**替代绝对数值，使强度分级随市场冷暖自适应：

   - 对当日所有上榜板块，计算 `up_nums` 的 P30 和 P70 分位数、解析后的连板高度值的 P50 分位数
   - **涨停家数高** = `up_nums ≥ P70`（当日涨停家数排前 30%）
   - **涨停家数中** = `P30 ≤ up_nums < P70`
   - **涨停家数低** = `up_nums < P30`
   - **连板高度高** = 解析后的连板数 ≥ P50（当日连板高度中位数以上）

   | 分级 | 条件 | 含义 |
   |------|------|------|
   | **强势主线** | 涨停家数高 **且** 连板高度高 | 广度+高度共振，最强信号 |
   | **普涨式轮动** | 涨停家数高 **但** 连板高度低 | 赚钱效应广但缺龙头 |
   | **龙头独立行情** | 涨停家数低 **但** 连板高度高 | 个股极致但板块参与度低，退潮时高位股风险大 |
   | **边缘题材** | 涨停家数低 **且** 连板高度低 | 关注度不足 |

   > **设计理由**：绝对阈值（涨停 ≥ 5 / 连板 ≥ 3 / 连板 ≥ 5）在冰点行情（日成交 5000 亿以下）和过热行情（日成交 1.5 万亿以上）下丧失区分度。分位数方案随当日截面自动调整——熊市中 P70 可能只有 3 家涨停，牛市中 P70 可能是 15 家涨停——始终保持相对排序的区分能力。分位数阈值（P30/P50/P70）为初值，后续可通过回测调参。

#### 连板高度解析（`up_stat` 字段）

`up_stat` 是板块内最强龙头的连板战绩，格式如 `"9天7板"`。解析规则：

```python
import re

def parse_up_stat(up_stat: str) -> dict:
    """解析 up_stat 字段，返回 {days_on_board, consecutive_boards}。
    若解析失败或为空，返回 {"days_on_board": 0, "consecutive_boards": 0}。
    """
    if not up_stat or not isinstance(up_stat, str):
        return {"days_on_board": 0, "consecutive_boards": 0}

    # 模式1："9天7板" → days_on_board=9, consecutive_boards=7
    m = re.match(r'(\d+)天(\d+)板', up_stat.strip())
    if m:
        return {"days_on_board": int(m.group(1)), "consecutive_boards": int(m.group(2))}

    # 模式2："首板" → days_on_board=1, consecutive_boards=1
    if '首板' in up_stat:
        return {"days_on_board": 1, "consecutive_boards": 1}

    # 模式3："N连板" → days_on_board=N, consecutive_boards=N
    m = re.match(r'(\d+)连板', up_stat.strip())
    if m:
        n = int(m.group(1))
        return {"days_on_board": n, "consecutive_boards": n}

    # 兜底：尝试提取所有数字
    nums = re.findall(r'\d+', up_stat)
    if len(nums) >= 2:
        return {"days_on_board": int(nums[0]), "consecutive_boards": int(nums[1])}
    if len(nums) == 1:
        return {"days_on_board": int(nums[0]), "consecutive_boards": int(nums[0])}

    return {"days_on_board": 0, "consecutive_boards": 0}
```

> **强度分级用 `consecutive_boards`**（连板数），`days_on_board` 仅作参考展示。

### 2.2 interface.py 薄封装

def get_concept_rotation_ranking(days: int = 5, top_n: int = 10) -> str:
    """
    获取近N个交易日题材板块轮动矩阵（Tushare 打板专题数据）。

基于逐日的题材板块热度排名 + 涨停家数 + 连板高度数据，
识别强势主线、新晋热点和退潮板块，给出对明日的板块轮动预测。

分析日期：{current_date}

背景上下文（来自板块新闻+技术分析）：
{sector_context}

### 题材板块逐日轮动矩阵
{rotation_matrix}

## 分析框架

### 第一步：主线识别
- 哪些板块连续多天上榜（持续主线）？
- 它们的涨停家数在走扩还是走弱？
- 连板高度在上升还是下降？
- 主线板块之间是否存在产业链关联（如 AI 的上中下游联动）？

### 第二步：新热点评估
- 有没有新晋上榜的板块（新晋异动）？
- 新热点的涨停家数和连板高度是否有扩散效应（从单个龙头扩散到多只跟风）？
- TOP N 之外有没有蓄势上升的板块（排名持续爬升）？

### 第三步：退潮风险
- 哪些板块掉出榜单（退潮）？
- 掉出榜单的板块此前是"龙头独立行情"还是"普涨式轮动"？
  - 龙头独立行情退潮：高位股补跌风险极大，需重点警示
  - 普涨式轮动退潮：可能只是暂时回调，关注是否重新上榜

### 第四步：强度验证
- 强势主线板块的强度是否可持续？（涨停家数≥当日P70 + 连板≥P50）
- 有没有"涨停家数高但连板高度低"的伪主线（普涨无龙头，难以持续）？

## 预测输出要求

基于以上四步分析，输出明日最可能上涨的 3-5 个题材板块，每个预测必须包含：
- 板块名称（THS 题材分类）
- 预测逻辑链（基于逐日矩阵的具体证据，不是泛泛而谈）
- 置信度（高/中/低 + 一句话依据）
- 风险提示（可能推翻预测的因素）

### 置信度参考标准
- **高**：持续主线 + 涨停家数走扩 + 连板高度上升 + 强度分级为"强势主线"
- **中**：新晋异动 + 涨停家数≥当日中位数 + 强度分级为"普涨式轮动"或"龙头独立行情"
- **低**：波动板块 / 仅靠蓄势上升信号 / 数据天数不足

### 风险提示清单（必须逐一检查）
- [ ] 大盘环境是否支持题材炒作？（参考市场层 macro 环境）
- [ ] 主线板块是否已到加速末期？（连板高度极高 + 涨停家数开始下降 = 见顶信号）
- [ ] 新晋异动是否有龙头带动？（缺龙头的新热点容易一日游）
- [ ] 退潮板块中的"龙头独立行情"类型是否有高位补跌风险？
- [ ] 是否存在板块间资金跷跷板效应？（A 板块强 → B 板块被抽血）

## 跨分类体系注意事项

⚠️ **重要**：本节数据来源为同花顺（THS）题材板块分类，
与板块新闻/技术分析报告使用的东方财富（EM）概念板块是**两套独立的分类体系**。
板块名称、数量、颗粒度均不同。

规则：
1. 板块轮动预测**独立使用 THS 分类**输出，不做跨体系名称对齐
2. 在解读"背景上下文"中的 EM 板块结论时，仅做**方向性参考**（如"科技方向整体偏强"），
   **不要**尝试将 EM 板块名称和 THS 板块名称做一一对应
3. 如果需要对同一方向做交叉验证（如 EM 的"ChatGPT概念"和 THS 的"ChatGPT"），
   在输出中**同时注明两个分类体系的名称**，并标注"跨体系比对，内涵可能不完全一致"
4. 禁止自行推断"EM 的 X = THS 的 Y"——这会引入不可靠的对应关系

请使用中文，结论前置。
```

### 3.2 输出 Schema（结构化提取）

LLM 自由文本输出后，通过 `_extract_rotation_prediction()` 提取结构化结论块，格式参照 `sector_news_analyst.py` 的 `## 〇` 模式：

```python
def _extract_rotation_prediction(report: str) -> str:
    """从完整报告中提取轮动预测速览结构化文本"""
    if not report or len(report) < 50:
        return report or ""

    import re
    # 尝试提取 ``` 代码块内容
    code_block = re.search(r'```\s*\n(.*?)\n```', report, re.DOTALL)
    if code_block:
        return code_block.group(1).strip()[:1200]

    # 尝试提取 ## 〇 段落
    section = re.search(
        r'##\s*〇[、，\s]*轮动预测速览.*?\n(.*?)(?=\n##\s|\Z)',
        report, re.DOTALL
    )
    if section:
        return section.group(1).strip()[:1200]

    # 兜底：返回报告前 1200 字
    return report[:1200]
```

LLM 被要求在输出的 `## 〇` 部分填入结构化短名单：

```
预测日期: YYYY-MM-DD
明日主线预测: <板块名> | 置信度:<高/中/低> | 逻辑:<一句话>
明日新晋热点预测: <板块名> | 置信度:<高/中/低> | 逻辑:<一句话>
退潮预警: <板块名> | 原因:<一句话> | 风险等级:<高/中/低>
蓄势关注: <板块名> | 排名变化趋势 | 关注逻辑:<一句话>
大盘适配度: <有利/中性/不利> | <一句话理由>
```
