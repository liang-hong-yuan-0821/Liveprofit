目标：持续新闻研判入库；每天09:00盘前、21:00晚间自动更新新闻与市场分析，每天21:00开始运行全部启用量化策略；页面可分别手动分析新闻和运行量化。事件研究直接按每日已知事件及仍有效历史事件生成并展示当版1/5/20交易日预测，不要求用户自行输入事件。结合历史事件和现有 agent 生成下一交易日、未来一周与一个月的方向判断及事件落地/兑现跟踪；量化页展示策略候选股票和近期事件权重。

方案已经用户确认并进入实施。新闻/量化批次、人工 API、日报界面、事件版本浏览和兑现快照已完成代码实现。工作区存在其他任务的大量并行改动；每日投研逐项核查相关文件并在其上安全集成，不回退其他任务内容。

相关方案：[市场数据自动补齐](../../市场数据自动补齐/plan.md)、[量化策略与实操层](../../量化策略与实操层/plan.md)。前者仍为方案，不能当成已上线依赖。

存储推荐：新增 news（来源原文版本）和 event_assessment（正式判断版本），复用任务、报告、信号与订单；不以表数作为优化目标。assessment 不再混放执行控制和模型逐轮发言，固定模型向量为只填充一次的派生字段，首期采用同库事务。比较与字段见 plan.md 2.1、4.1。

用户已认可该存储设计，并明确每日还需未来一周/一个月方向与利好、利空落地后的反应。日报现已实现 1/5/20 交易日期限方向与股票/指数价格兑现快照；历史板块成分和行情缺失会显示数据不足。

用户新明确时间：每天09:00和21:00各出一版新闻/市场判断，量化每天21:00开始运行，页面有两个独立手动按钮。整点新闻版展示新闻截止、实际完成、待处理数与来源覆盖；迟到新闻不会倒灌旧版，partial 状态保持明确。量化21:00是起跑时间，不是完成承诺。

事件研究页面现有“事件文本＋目标资产＋窗口”预测表单已从主流程移除，现按批次浏览系统生成的事件预测；旧自由文本预测 API 保留兼容，争议和更正仍走人工审核页。

量化当前已接入全量已发布策略扫描、事件权重排序及前十候选个股深研。若21:00扫描因新闻积压标为 partial，后续完整新闻批次清空积压后会自动创建幂等刷新批次，复用原策略扫描分数并更新事件权重与候选排序。按 2026-09-23 实施期范围澄清，一期交付候选排名与事件权重，不生成组合仓位或建议订单；组合级规划留待单独绑定组合后设计。日报会明确显示该范围，避免把候选排名误读成仓位建议。
