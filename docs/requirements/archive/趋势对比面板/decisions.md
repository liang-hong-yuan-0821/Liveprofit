## 2026-09-19 板口径改为官方指数（修订"全板等权自算"）

- **背景**：R1 全量评审 M1 实测发现，原"全板等权曲线"的归板依据 `market.stock_info.market` **只同步在册股票**——`instrument_daily` 中出现过的 5818 个股票代码里，**约 250 个已退市代码**不在 `stock_info`/`instrument` 中（约 4.3%；精确计数依赖分类口径，复算落在 251–258 不等），且该偏差各板幅度不一致（退市股集中主板，退市整理期普遍 -80~95%）→ 三条线的历史段都偏高且偏高幅度不同，"哪个板更强"的结论可能失真。同轮 M6 另实测首日过滤仍有 20 行极端涨跌幅（601091.SH +177.74%、000670.SZ +488.44%）漏过。用户提出"直接用 tushare index_daily 拿官方指数写库"的方向后，实测核查：我国官方指数体系**不存在"主板指数"**（2026-09-19 实测 `index_basic`：SSE 208 个、CSI 8961 个指数中含"主板"命中 0 个；仅深交所 395001.SZ「主板A股」且只覆盖深市一半）；但 **上证综指（000001.SH）/创业板指（399006.SZ）/科创50（000688.SH）三者均已在库且每日增量**（实测 8729/3961/1630 行，起点 1990-12-19/2010-06-01/2019-12-31）
- **选项**：① 现有官方指数零采集（上证综指/创业板指/科创50，均在库）；② 补采两个全样本指数（深主板A股 395001.SZ + 创业板综 399102.SZ），但沪市主板缺位、科创板仍只有样本指数；③ 自编等权保留原设计 + 改代码前缀归板（退市股纳入）
- **结论**：① 现有官方指数零采集。板 Tab 三条线 = 上证综指 / 创业板指 / 科创50；plan 4.1/m6/m9 等自编聚合相关内容全部移出，M1/M6 随之消解；口径差异（上证综指 2020-07-22 修订后含科创板、创业板指 100 只样本、科创50 50 只样本）在图注与 DTO 注释如实写明
- **理由**：数据真实可复现、零采集改动、无自维护分类规则、无幸存者偏差、无极端值过滤问题；实现面从"自编指数"收窄为"读已在库的指数行"，与市值分层 Tab 完全同构

## 2026-09-19 归一基点 = 共同首日=100

- **背景**：R1 M2 实测发现"区间起点=100"在「全部」区间下各序列基点落在不同日期——市值分层组各层起点 2005-01-04（沪深300）/2007-01-04（中证500）/2005-01-04（中证1000）/2014-01-02（中证2000），板组 1990-12-19/2010-06-01/2019-12-31——四条线 0 点不重合，横向对比失真（对比面板的核心价值受损）
- **选项**：① 各序列共同首日=100（所有序列都有数据的第一个交易日为基点日，各自该日 close 记 100，基点日之前的点丢弃）；② 保留"各自首点=100"并在图注/图例写明"各自起点"
- **结论**：① 共同首日=100。算法见 plan 4.4.1；已知代价：「全部」区间下市值分层组从 2014-01-02 起（丢沪深300/中证1000 的 2005–2013 段）、板组从 2019-12-31 起（丢上证综指 1990–2019 段）
- **理由**：同起点是"跨序列对比"的前提，丢掉历史段换取可比性是值得的取舍；方案内 UI 不标注"基点日"以外的复杂口径，展示逻辑最简

## 2026-09-19 砍掉行业 Tab（范围缩为两 Tab）

- **背景**：方案初版三 Tab（市值分层 / 板 / 行业）。行业 Tab 是全方案唯一需要新数据底座的部分：库内无行业日线表（`market.sector_daily` 只覆盖同花顺概念 dc 源），需新增 `market.industry_daily` 表 + 31 行业 sw_daily 全历史回填（~10 万行）+ 每日增量 + Provider 接口 + 前端热力图组件，占 8 个任务中的 3 个（T2/T3/T4）与全部数据模型变更；市值分层 Tab（读已有 instrument_daily）与板 Tab（现场聚合）无需新表
- **选项**：① 维持三 Tab（新表 + 采集 + Provider + 热力图全做）；② 行业数据实时拉不落库（每次 31 请求、依赖外部端点、无"全部"区间历史）；③ 行业 Tab 暂缓（本次只交付两 Tab）；④ 行业 Tab 永久删除
- **结论**：③ 暂缓——本任务只交付市值分层 + 板两 Tab，行业相关的表/采集/Provider/热力图组件（原 T2/T3/T4）整体移出范围；原任务的行业结论留档于 [plan.md](plan.md) 五、已确认决策 4（含 sw_daily 端点实测数据与被移出的设计要点，恢复时无需重测）
- **理由**：砍掉后方案无数据模型变更（无新表、不改 Provider），交付面明显收窄；两 Tab 的数据已在库（instrument_daily 指数行 + 全市场个股日线），风险与工作量集中在两端点 + 一个折线组件；行业底座属"新增一个数据域"，值得单独立项而非搭在这个面板里
