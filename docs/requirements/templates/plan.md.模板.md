## 四、已确认决策 / 待确认问题（按需：存在已确认项或待决策阻塞项时必需）

- 待确认问题：逐条列出仍阻塞实施的开放问题。**每条必须写具体并附背景、目标与推荐（2026-09-11 起）**：问题句带代码事实（文件/函数/字段现状）；背景 = 现状事实 + 该决策影响哪些实现点（不决策会卡住什么）；目标 = 各选项对应的实现形态或期望结果；推荐 = 默认选项 + 理由（用户可按推荐直接拍板，不另起调研）。例：

  ```
  1. **核心数据 `insufficient` 时，风险门控从 fail-open 的 `normal` 改为 `caution`？**
     - 背景：现状 `derive_risk_gate` 空串/解析失败一律返回 `normal`（fail-open"宁漏勿错"）；本方案有序规则表已按"质量不足 → `caution`"设计，与现状语义相反。
     - 目标：定死数据故障时风控的默认姿态——选 caution = 规则 3 保留；选 normal = 规则 3 删除。
     - 推荐：改 `caution`。结构化后"解析失败"与"无风险"已可区分，故障日拦一半比静默放行安全。
  ```
