目标：市场概览自动发现已到发布时间的行情缺口，后端按数据组补齐、去重与有限重试，页面保留旧数据并在入库后刷新。

**2026-09-24 目标日故障处置结果**：完整 `stock_basic` 目录（5907 条）仍无 3 个 DC 板块成分代码，说明板块分类可先于上市事实发布；个股覆盖目标现仅取股票主目录，目录内未知生命周期仍 fail-closed。旧停牌请求误用 `suspend_date`，代理忽略筛选并返回 5000 条截断历史；改为按官方 `trade_date` 及返回的 `trade_date/suspend_type` 验证，只将 S 计作停牌。板块代理 `dc_daily` 独缺 BK0165.DC 的 9 月 23 日，东财原始 K 线有完整 OHLC，已接入单板块目标日兜底。真实 API 在 API、Dispatcher、市场 Worker 重启后验证：**个股 5556 行行情 + 12 条停牌 = 5568/5568，板块 1031/1031，两组 FRESH**。`HISTORY_GAP` 只表示较早历史时段另有缺口，不否定当前目标日覆盖；详见 [日志](log.md) 和 [待验证项](issues.md)。

用户已授权实施 10 项任务。日期策略、覆盖读模型、Redis 准入、定向采集、刷新 API、前端自动检查与提示、后台专用 Worker 已实现；容器部署验收与最终归档仍待完成。Docker Hub 已用公开缓存绕过，Worker 镜像构建与隔离 Redis 心跳验证通过；Docker Desktop 已恢复，但 37.47 GB 的动态 VHDX 尚未压缩，D 盘当前仅余 1.54 GB。压缩需要管理员权限，未改动数据卷。回归测试使用隔离库和假源；本轮生产仅定向同步目录、补采缺失的个股日线与停牌事实、BK0165.DC 的目标日日线，未运行迁移。

此前的目录、出站权限与目标日缺口排查过程保留在 [工作日志](log.md)；上方是本轮验证后的最新结果。

设计覆盖中美韩指数、中国指数因子、dc 板块及成分股依赖日线。新增独立采集 Worker，调度仍由现有 Dispatcher 承担。

按业务语义评估后，本任务不新增 PostgreSQL 表：行情与可信停牌事实写入现有表；可重建的任务状态、冷却和预算使用 Redis，并复用 Dramatiq 队列。采集互斥使用 PG session advisory lock。Redis 状态丢失可重新检查补采，但不能恢复全部历史尝试次数。
