# 问题与解决

> **更新**：2026-09-19，问题已归入 [统一方案](plan.md)。以下区分文档已合并和仍需决策/实现的事项，不沿用旧文稿的评审通过状态。

## 1. 脚本感知生命周期、SELL_PARTIAL 与平台规则仲裁（已决定，待实现）

- **表象**：现行七键支持 SELL_PARTIAL 和自由文本 reason；七套参考规则默认仅返回 BUY/SELL_ALL/HOLD，状态机另算目标仓位。
- **根因**：尚未确定脚本可以读取哪些只读状态，以及脚本与平台同时给出减仓/退出意图时的优先级。部分卖出本身不等于不幂等；必须由平台固定意图基数、版本并处理未完成订单。
- **解决**：保留七键和 SELL_PARTIAL；V1 不向脚本注入生命周期事实。平台把脚本卖出和生命周期规则统一为绝对目标股数，同日取最低目标、清仓优先，按状态版本和未完成订单差额去重。reason 保持展示文本，模板使用固定码，自定义脚本平台码固定为 `CUSTOM_SIGNAL`；幂等不得依赖自由文本。

## 2. 成本止损归属与真实成交来源（已决定，待实现）

- **表象**：旧稿脚本条件引用初始成交价 P，但 context 仅有 shares/average_cost/market_value；布林/圆弧止损也不一定等于 P×(1-p)。
- **根因**：真实成交、已接受初始止损和脚本输入尚未连通。
- **解决**：成本止损确定归 `PositionLifecycleManager`：只使用确认成交和订单冻结的规范化初始止损，脚本只提供技术结构信号。禁止用 average_cost、信号价或当前滚动行情重建初始止损。

## 3. 行情实时扫描与持仓日事实（已合并设计，待实现）

- **表象**：原文要求全市场 task-scoped 行情冻结，冲突于用户“不回测、只按条件选股”的已确认范围。
- **根因**：旧模板稿未同步执行期读行情的决策；状态机同日重复处理仍需要稳定事实。
- **解决**：plan.md §2.6 保留实时扫描，仅持仓推进保存逐日决策依据和版本，不重建全市场快照表。同日事实重用、缺失日补齐顺序、存储字段和保留周期需在实施合同中细化。

## 4. 自定义代码与生命周期规则绑定（已决定，待实现）

- **表象**：用户可以修改参考代码，template_id 不再能证明代码仍满足该模板的确认/弱化条件。
- **根因**：模板来源与实际策略定义不是同一概念。
- **解决**：生命周期规则以独立不可变 `lifecycle_policy_version_id` 绑定策略发布版本。用户修改参考源码后，template_id 只保留来源审计，不能自动套用模板生命周期；未显式选择并通过字段兼容校验时，仅允许基础信号模式，不启用阶段加减仓。

## 5. 十项因子与输入门控（已纳入，待实现/验收）

- **表象**：七套规则需要 MA60、布林、MACD 等字段，超出初始三项因子合同。
- **根因**：数据库列、采集覆盖、context 投影和 AST 允许字段需同步。
- **解决**：统一字段清单及真实读取集合校验，固定整数下标；前五日量为 -6 至 -2，不开放 slice。MA5 临界价实际读取 close[-5]/close[-20]。C1 的全市场 250 日十项因子 100% 覆盖 POC 保留为部署门禁，尚未执行。

## 6. 价格双口径与 isfinite（已纳入，待实现）

2026-09-19 更新：isfinite 的非数值/bool 判定已修复并通过真实子进程单测；价格双口径尚未实施。

- **表象**：现行信号价格与订单规范化价格需要分别审计。
- **根因**：规范化不能覆盖原始七键结果，低价股取整后可能不满足风险收益关系。
- **解决**：保留 entry_price/stop_loss/take_profit；增加 order_entry_price/order_stop_price/order_take_price，按 Decimal/tick 规范化后复核，失败保留 BUY 并拒单。isfinite 对非 int/float 或 bool 返回 False，不抛异常。代码尚未在本轮修改。

## 7. 生命周期事务、成交回写及跨日去重（待细化）

- **表象**：(position_id, trade_date, target_shares, reason_code) 只能限制同日重复；昨天未成交、今天同一目标仍可能重复下单。
- **根因**：必须同时建模活跃意图、执行中订单、剩余预留数量、部分成交和持仓周期。
- **解决**：plan.md §2.6 补入锁、版本、活跃意图复用及扣除未完成订单数量的规则。成交/意图/逐日事实的物理表名、FK、接口、撤销与对账路径仍需细化；生成退出意图不等于真实清仓，成交完成才关闭周期。

## 8. 移动止损启用参数（待配置）

- **表象**：文稿定义 b/a/d，但未给出本项目经验证参数。
- **根因**：项目没有回测能力，本轮也不引入回测引擎。
- **解决**：不填推荐默认值；用户显式配置并满足 0<b≤a、0<d<1 后启用，成交时冻结。未配置时移动止损不启用，已有初始止损与结构保护继续有效。

## 9. 真实环境验收（待完成）

- **表象**：行业 POC、全市场因子 POC、完整栈策略发布→扫描→报告流程尚需真实环境验收；生命周期新增成交确认与加减仓流程尚未实现。
- **根因**：原 8/8 基础任务完成记录不能覆盖本次新增范围。
- **解决**：保留原行业覆盖口径“有归属活跃股票数/全部活跃股票数≥95%”；新增状态机 fixture 覆盖部分成交、跨日未成交、退出、日线缺失、同日重跑。以上通过前不将统一任务标为已完成。

## 10. 行情与因子按日期对齐（代码缺陷，P0）

- **表象**：现行 Loader 的 factor map 以 `trade_date` 为键，但读取时可能拿整条日线记录查询，导致 MA/RSI 全部静默变为 null；现有全流程测试策略只读取 close，因此全绿也无法发现。
- **根因**：缺少 `MarketContextBatchLoader` 专门单测，日期键类型和非空值没有直接断言。
- **解决**：实现 C9；只按 `(ts_code, trade_date)` 等值对齐。新增不同日期不同值、错位、全空和最新日缺失 fixture，直接断言每项指标与 bar 日期对应。修复并通过前不得做模板 POC。

## 11. 全历史批量读取（性能风险，P0）

- **表象**：200 票分批不等于有界读取；现行查询可能先返回每票全部历史，再在 Python 截取最近窗口。
- **根因**：SQL 没有逐票 top-N 限制；既有 6,000 压力主要验证 signal cursor，不代表真实行情加载和子进程执行。
- **解决**：实现 C14；数据库侧逐票裁剪模板所需窗口，真实 6,000 标的跑完整 loader + runner + signal 落库，冻结 P95、峰值内存和数据库返回行数预算。

## 12. 信号价、当前价与风险距离不一致（代码缺陷，P0）

- **表象**：现行 Planner 先用信号 entry/stop/take 校验和算风险，再把买入成本提高到 `max(entry,current_close)`；上涨跳空时可能出现实际成本高于 take、成本后盈亏比不足或实际风险超过预算。
- **根因**：价格口径映射、tick、费用/滑点和二次风险校验尚未实现。
- **解决**：实现 C5/C10/C11：保留 qfq 信号价，映射为原始订单三价后加入费用/滑点，再计算成本后盈亏比和风险手数。任一关系失败保留 BUY 信号并拒单。

## 13. 数据水位与停牌新鲜度（设计缺口，P0）

- **表象**：只要累计 bars 足够，长期停牌票也可能用旧行情运行；请求日期可能被误展示成实际行情日期。
- **根因**：没有任务级共同市场水位，也没有 `requested/as_of/latest_bar` 三日期合同。
- **解决**：实现 C9；全局水位未齐不执行，单票最新 bar 落后则 `STALE_DATA`。持仓退出意图保留审计，但必须显示不可成交原因，不宣称已执行。

## 14. A 股可交易性、费用与组合开放风险（设计缺口，P1）

- **表象**：市值、现金和单笔风险无法覆盖 T+1、涨跌停、ST、停牌、最低佣金、印花税、滑点、流动性以及多持仓同时止损。
- **根因**：原基础阶段只生成建议预览，没有构造真实成交可行性和组合热度合同。
- **解决**：实现 C11/C12；风险降低订单不被组合熔断阻止，新开仓/加仓必须同时满足可交易性、成本、参与率、单笔风险、组合开放风险和未完成订单预留。

## 15. 策略收益有效性（研究缺口，P1）

- **表象**：七套规则可解释、可测试，但高度共享 MA/MACD/RSI/量能暴露，没有证据表明是七个独立收益来源；score 也不是概率。
- **根因**：用户明确不建设回测引擎，历史参数没有可验证绩效基础。
- **解决**：按 C13/§4.14 分三波 forward shadow；观察口径预注册，报告成本后期望、回撤、MAE/MFE、可成交率和分市场状态结果。未通过不得默认启用或跨策略直接比较 score。
