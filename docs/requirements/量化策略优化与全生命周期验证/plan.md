## 一、背景与动机

目标是形成能验证、能执行、能持续管理的量化策略体系：优化现有七套策略，新增四类候选策略，每日根据行情、账户与实际成交提供持仓建议，覆盖研究、准入、建仓、加减仓、退出、暂停及退役。以扣除成本后的净期望和风险表现判断是否采用，允许最终没有策略达到准入标准，不把高胜率、漂亮回测或代码发布解释为未来盈利保证。

| 维度 | 现状 | 问题 | 目标 |
|------|------|------|------|
| 存量策略 | `backend/modules/quant_strategy/domain/templates.py` 注册七套策略，原方案 §4.7–4.13 描述规则 | 固定 2R 止盈与账户最低成本后 2R 门槛冲突；示例入场10、止损9.5、止盈11，10bps滑点后约为0.99/0.51=1.941，尚未计费用就被拒绝 | 分别验证入场与管理政策，不通过虚抬目标价迎合门槛 |
| 指标口径 | `quant_execution_market_data.py` 使用固定历史窗口；现有股票有 raw OHLC 与 qfq 因子来源 | 调研样本 `000001.SZ` 2025-01-02 原始收盘11.43、bfq MA5为11.754、qfq MA5为11.16051，跨基准比较会改变信号 | 每次策略计算和价格映射具有一致、可追溯基准 |
| 每日账户建议 | `daily_research/application/quant_pipeline.py` 快照使用 `positions=[]`、`portfolio=None`，以 `scan_only` 扫描 | 扫描可以发现候选，却不能据真实现金、已有持仓和冻结政策生成完整账户建议 | 每日输出账户级持有、等待、建仓、加仓、减仓和退出建议 |
| 执行约束 | `position_lifecycle_manager.py::_materialize_delta` 直接物化订单，常规 planner 跳过 lifecycle managed 证券 | 生命周期生成的加减仓存在绕过统一现金、费用、可卖量和开放风险检查的路径 | 所有订单都经过同一规划及约束入口 |
| 持仓归属与窗口 | `execution.py` 读取账户全部生命周期，却按当前扫描策略加载历史和字段 | MA策略仅需很短输入时，另一持仓规则所需的前五日成交量可退化；当前脚本SELL可影响其他策略归属 | 每个持仓按冻结版本运行，按全部管理依赖读取数据 |
| 账户与更正 | `portfolios.py` 仍有持仓及现金直接写入口；成交事件缺实际费用 | 直接覆盖持仓与账本重放会产生两套余额；首笔成交更正后初始风险锚点也需重建 | 账户事实可对账、可重放、可审计 |
| 日事实与重跑 | `0013_position_lifecycle_contract.py` 定义持仓日事实唯一 `(lifecycle_id, trade_date)` | 同日补数据或成交更正不能只给账户运行加修订号；任务ID进入业务hash还会造成同数据不同任务冲突 | 同输入幂等，不同有效输入保留修订，只有一份当前事实 |
| 收益与准入 | 旧任务 N8 仅有基线，N9 影子期未完成；本轮尚无独立验证结果 | 将代码PUBLISHED视为可用会跨过收益、容量及执行证据检查 | 代码发布、软件验收与策略使用资格分别管理 |

本任务覆盖 A 股和境内股票、债券、黄金 ETF，日频决策、下一交易日人工执行。首批不做跨境ETF、盘中交易或券商自动下单。原任务 N7 展示、N8 终验、N9 观察的后续要求通过本任务承接；本轮不改写旧任务历史状态。

### 2.1 数据模型设计

以下是拟新增或修改的关键契约。新增模型的ID、金额与业务记录尚未产生，实际示例待实测；枚举是设计取值域。沿用现有UUID主键、Decimal金额、DATE交易日和带时区时间戳约定。模型名称表示业务对象，最终迁移按所属 schema 命名规范执行。

| 字段或对象 | 类型 | 写入者 | 说明与示例 |
|------------|------|--------|------------|
| dataset manifest | 持久化记录 | 数据集构建服务 | 数据范围、源接口、字段、基准、覆盖、内容hash及文件位置；真实证券样例 `000001.SZ`、`510300.SH` |
| `price_basis` / `observed_at` | enum / timestamptz | 数据适配器 | 基准 `raw/qfq/hfq`，并记录获取时间；历史业务有效时间与本次采集时间分别保存，不能将采集时间冒充历史可用证据 |
| dataset `status` | enum | 数据集构建服务 | `BUILDING/READY/FAILED`；完整文件原子发布并校验后才能标READY |
| `PortfolioTargetIntent.portfolio_id/strategy_version_id` | UUID | 内置组合分配器 | 目标所属账户和不可变策略版本；实际UUID待实现产生 |
| `evaluation_as_of/market_trade_date` | timestamptz / date | 研究或每日执行宿主 | 选择策略证据的截止时点与行情交易日，不得使用晚于决策时点的排名 |
| `instrument_id` | str | 分配器 | 对应 `market.instrument.ts_code`，不是额外的证券UUID；真实值如 `518880.SH` |
| `target_weight` | Decimal | 分配器 | 相对于该策略家族预算的权重；不得复用现有相对于初始容量的 `target_exposure_pct` |
| `reason_code/setup_id/expiry` | str / str / 交易日 | 策略宿主 | 解释目标、关联同一入场机会并规定有效期；业务样例待实测 |
| signal metadata | 结构化对象 | 受限策略/宿主规范化器 | 入场区间、失效条件、证据与政策引用；与既有七键信号合并为单一规范化结果 |
| lifecycle policy | enum + 不可变参数 | 策略发布服务 | `FIXED_TARGET/TRAILING/RULE_BASED`，有持仓后冻结版本与原始锚点 |
| admission state | enum + 范围 | 准入服务 | `EXPERIMENTAL/VALIDATED/SHADOW/ADVISORY/SUSPENDED/RETIRED`；资格绑定版本、资产范围与风险档位，独立于PUBLISHED |
| account snapshot | 不可变记录 | 人工确认/导入入口 | 持仓、现金、可卖数量、来源及快照时间；无变化确认也形成可审计事件 |
| reconciliation item | 持久化记录 | 对账服务 | 数量、现金等差异及解决依据；差异不会自动伪造成成交 |
| ledger entry | 追加式记录 | 成交/资金/公司行为服务 | 有符号现金和数量变动、费用、资金流及更正关系；余额是投影 |
| portfolio valuation | 按日、按修订记录 | 估值服务 | 资产、现金、单位净值、回撤、数据日期及状态；外部入金不计作收益 |
| portfolio daily run | 持久化记录 | 每日账户流水线 | 业务输入hash、修订、来源任务关联及结果；任务ID不进入业务hash |
| daily fact `revision/supersedes_id/is_current` | int / UUID? / bool | 生命周期服务 | 保留替代链，唯一当前版本；实际初始修订样例待实测 |
| research run/trial | 持久化记录 | 研究服务 | 数据版本、代码hash、政策、参数、全部尝试与选择关系，包含失败试验 |
| simulated order/fill/nav | 持久化事实 | 模拟适配器 | 和真实账本隔离；可重放到研究运行和数据快照 |
| evaluation/admission event | 不可变记录 | 评估及准入服务 | 指标、适用门槛、证据不足原因、状态变更与评价截止时点 |

### 2.2 存储方案选择

| 方案 | 收益 | 代价与结论 |
|------|------|------------|
| 扩展既有八张生命周期表 | 保留身份和业务关联，减少迁移断裂 | 需要修订约束及全量消费迁移；生命周期事实继续使用，推荐 |
| 新建账户/研究业务表 | 对账、资金事件、研究试验有独立生命周期、索引和审计语义 | 增加迁移及DAO；优于塞入通用任务JSON，推荐 |
| 不可变Parquet + PG清单 | 大窗口行情可复现、可批量扫描；无需复制一套在线关系库 | 需要独立备份、原子发布及清理规则；只用于研究快照，推荐 |
| 通用任务报告JSON存全部事实 | 初期少建表 | 难约束、难查询、难做更正与长期审计，不采用 |
| Redis保存唯一业务事实 | 读取快 | 无法承担可靠审计和唯一幂等，禁止；仅缓存或去重加速 |

增加独立 `quant_dataset_root`，不套用现有 `artifact_root=var/runs` 的90天清理及普通文件类型/容量限制。先完整写文件并验证hash，再事务登记READY；失败只留诊断，不暴露半成品。数据库承担关键身份、唯一性和版本约束。

### 4.1 数据与研究快照

#### 4.1.1 模块设计

**数据闭环**：Provider结构化结果 → 采集规范化与PG事实 → 覆盖读模型 → 数据集构建/每日读取 → 受控context → 策略/生命周期。来源、基准和异常理由随数据传递至报告与研究清单。

1. 每个策略和生命周期版本声明 `required_fields/required_bars/price_basis`。宿主读取单票策略与全部已持仓冻结政策的依赖并集；需要长窗口的内置分配器读取独立向量化快照，不为它开放沙箱任意循环。
2. 分离持仓保护与新仓扫描readiness。全市场缺口可阻止新增风险，但不能阻止数据完备的已有持仓退出；单个持仓缺数据时保持上次保护、输出等待原因，不推进有效观察天数。
3. 原始价格用于真实现金、订单、成交及证券规则；同一指标计算使用同一复权基准，所有映射记录因子和基准时间。无量纲指标不做价格比例缩放。
4. 上游指标优先。只有实测确认缺字段、基准不一致或算法不满足约定，才启用版本化本地计算；用独立基准样例验证。网络错误、超时或代理暂不可达不能被解释为上游“不准确”。
5. 同一输入先按交易日升序归一，检查重复、空值、完整窗口、证券覆盖、停牌及数据版本。现有刷新链路已具备日线100%、qfq/复权/状态95%等覆盖检查，本方案复用并按场景细化，不能退化成只看最大日期。
6. 历史股票池按当时上市/退市、ST、行业和可交易状态构建；不得用当前证券名称判断历史ST，不得用当前行业成员替代历史。缺可靠历史状态的区间只能探索，相关策略不认证。
7. 基金池仅纳入符合本方案类别的境内ETF，排除LOF、REITs及跨境产品。ETF因子、涨跌停、交易日及规则需独立核验，不能默认股票接口全覆盖。
8. 快照固定数据范围、内容hash、来源、采集批次、基准和质量结果，未来重新采集不覆盖原研究快照。公告/分类/规则等具有信息发布时间的数据按历史可用时点过滤。

调研时的只读库截面表明：当前退市目录中部分证券没有日线，退市qfq覆盖也存在缺口；交易状态仅有近期少数交易日。三只ETF `510300.SH/511010.SH/518880.SH` 各有2,605行日线及复权因子，但当时技术因子为0行。这是调研截面，不是长期固定事实，T1必须重新生成覆盖报告。

### 4.2 策略契约与候选策略

#### 4.2.1 模块设计

**契约**：既有 `strategy(context)` 和七键 `action/score/entry_price/stop_loss/take_profit/sell_ratio/reason` 保留规范化读取；增加受控metadata后，validator、runner、normalizer、planner、DTO、报告和前端同时迁移。旧版本只做输入适配，不改写已发布源码或冻结政策；不新增 `_v2` 字段和运行期双逻辑回退。

**四类新增策略：各12组，共48组**

共同符号：`P`为同一决策基准的调整收盘价；`σ20`为此前20个日对数收益的样本标准差；`B`为家族预算。A股上市满250个交易日、非ST、未停牌、ADV20≥2,000万元。ETF范围为沪深300、中证500、创业板、境内中期国债和黄金，同类别同指数按当时ADV20选代表，每月更新，要求上市250日和ADV20≥2,000万元；没有符合者留现金，不拼接存续产品的历史收益。

| A股短期均值恢复 | 个股与沪深300高于MA120，个股低于MA5；按Z降序选入十槽，每槽B/10 | 初始保护、收盘≥MA5、基准跌破MA120或H日到期退出；不摊低加仓；冷却五个有效交易日 | Q=2/3；z=1.5/2/2.5；H=3/5 |

均值恢复定义 `Z=-ln(P[t]/P[t-Q])/(max(σ20,0.005)*sqrt(Q))`，要求 `Z≥z`。初始止损距离 `d=min(0.10,max(0.03,2*σ20*sqrt(H)))`，用实际成交价冻结 `fill_price*(1-d)`；成交日计第零日。入场已满足任何退出/失效条件时退出优先，不产生新买入。

防御配置按屏蔽后的基础权重和W日历史收益协方差计算组合年化波动，`λ=min(1,v/σ_portfolio)`，权重乘λ；σ为0时λ=1，数据不足不增加风险。所有目标仍需平台风险、现金、单票与最小数量裁剪，尾差留现金。

### 4.3 统一执行与风险预算

#### 4.3.1 模块设计

固定顺序：策略/生命周期意图 → 家族归属与预算 → 保护性最低目标仲裁 → 唯一planner → 原子写意图和建议。生命周期只输出意图，不直接创建绕过约束的订单。所有入口检查现金、费用、成交预留、开放风险、行业/风险桶、可卖量和证券规则。

| 默认参数 | 保守 | 均衡 | 进取 |
|----------|------|------|------|
| 单笔风险占净值 | 0.25% | 0.50% | 0.75% |
| 组合开放风险上限 | 2% | 4% | 6% |
| 最大资金暴露 | 50% | 75% | 90% |
| 单股票权重上限 | 5% | 8% | 10% |
| 单ETF权重上限 | 20% | 25% | 30% |
| 回撤预算 | 8% | 15% | 25% |

每日新增风险上限和单行业/风险桶上限，均为组合开放风险预算的一半。回撤达到预算一半停止增加风险；达到全部预算生成退出建议并暂停资格，受阻退出持续保留。跳空、跌停和人工执行意味着回撤可能超过预算，不能把预算当作保证。旧账户不自动覆盖设置。

执行规格：

1. T日收盘决策，使用真实交易所日历决定下一交易日，替代 `_next_weekday`。日线回测以次日开盘加不利滑点作为人工执行代理，不声称取得真实盘中成交。
2. 默认入场区间为T收盘±0.5ATR20，严格高于止损；均值恢复入场上界还需低于信号MA5一个tick，无合法区间则无单。数量和现金/风险预留按区间上界、最不利tick及费用计算。
3. 开盘加滑点后超区间不买入，入场建议当日失效；后续只有新的夜间有效信号才能重新生成。实际人工超范围成交照实入账，标偏离并重算风险，不能拒绝记录已发生事实。
4. 开盘模拟容量只用T日已知ADV20的1%，按原始成交金额与数量单位换算；T+1全天量只能后验诊断，不能反向裁剪开盘成交。股票10bps、ETF5bps基线滑点，验证双倍成本/滑点。
5. 费率、价格tick、数量单位、涨跌停、交收与权限按证券/日期生效，不能全部硬编码100股或股票印花税。规则缺失阻止新增风险，保留退出等待状态。
6. 收盘规则先用此前生效的保护价判断，再更新下一期只收紧的止损；不根据当日最低价假设以止损价盘中成交。跳空按实际可执行代理价；一字受阻保守不成交，不能凭日线高低范围强行成交。
7. 退出未完成时保留sticky意图，后续普通HOLD不得取消。卖出受阻、T+1不可卖或部分成交只更新可执行差额；同批次买入不提前使用未确认卖出资金。

### 4.4 账户账本与生命周期

#### 4.4.1 模块设计

账户快照/实际成交/外部资金/公司行为 → 追加账本和对账 → 当前持仓/现金/可卖量 → 当日估值 → 冻结生命周期 → 新修订建议。所有写入通过统一账户服务，现有持仓和现金字段成为投影。

- 首次导入建立账户基线；之后旧API的持仓upsert、删除和资金修改同步转为快照对账或带原因的调整，不能继续直接覆盖。受管持仓差异提示对账；不把导入差异伪造成成交。
- 每日以新快照或无变化确认保证账户时效，并合入成交。未解决差异阻止新增风险；仍允许有可靠数量依据的持仓减仓和保护，不凭不可信余额假造交易。
- 保存实际费用、成交时间和来源，超建议数量或价格的真实成交照实记录并产生偏离；重算风险，未处理偏离前不新增风险。
- 更正/撤销采用追加事件和引用关系，重放现金、成本、初始止损、阶段和持仓锚点。未执行建议失效；已向外部报出的订单在确认取消前保留预留，不能单方视为已撤。
- 成交推进实际数量、成本和已成交阶段；有效行情推进观察天数、高水位、保护价和意图。两类事实不可混用；建议订单不是成交。
- 公司行为作为可靠事实调整现金、数量及原始价格锚点，防止除权造成虚假退出。估值使用净值单位化处理外部资金流，不把入金视为盈利。
- 已有持仓按冻结策略与政策管理；准入只限制首仓和加仓等新增风险。SUSPENDED/RETIRED仍可保护、减仓、退出和对账；显式接管事件才能换规则。
- 无可验证策略历史的导入持仓标UNMANAGED，用户明确接管并记录起始政策，不补造买入历史。
- 日事实增加 `revision/supersedes_id/is_current`，唯一 `(lifecycle_id,trade_date,revision)`，并以 `WHERE is_current` 部分唯一约束保证单日一份当前记录。全部读模型默认当前版本，审计接口显式查历史。
- 业务hash包含行情、规则、账户和成交版本，不含source_task_id。同业务输入复用成功修订；失败留审计但不占用成功结果。同日更正保留旧版，在账户锁内原子切换事实、投影和未执行建议。
- 有效观察日按去重交易日计数，更正不重复累计。补跑可重放真实历史事实，不补造历史人工成交；今日输出只展示当前仍可执行建议。

迁移复用既有 `lifecycle_policy_versions/position_lifecycle_states/position_intents/suggested_orders/order_fill_events/position_daily_facts/position_expectations/position_trailing_stops` 八表，不创建一套平行生命周期。存量真实账户建立可解释基线，旧成交费用未知时标未知来源，不伪称精确历史收益。

#### 4.4.2 三方依赖能力评估

使用现有PostgreSQL事务、外键、部分唯一索引及锁能力。第一阶段实际成交通过人工登记或导入，不依赖券商自动交易API。事务失败必须rollback；多条账本与投影更新在同一业务事务提交。

### 4.5 历史验证与策略准入

#### 4.5.1 模块设计

**研究入口与输出**：输入冻结数据集、策略/政策版本、预注册参数集、风险档位和资金情景；通过现有任务系统执行，输出每个trial的模拟订单/成交/净值、完整指标、证据不足理由与准入事件。异常和失败trial也保留，不能只留盈利结果。

**时序划分**：最后252个交易日为独立留出集；此前按756日训练、126日验证、126日测试、步长126日滚动，至少四个外层测试窗口。训练标签不得穿越边界；每个窗口只用开始前已完成的验证结果决定参数及家族排序，冷启动使用预注册稳定顺序。不能以完整OOS最终排名回填过去。

留出集揭示前冻结最终候选和组合；看过留出后修改规则，该留出集转为研究数据，后续需要新的未见样本，不再声称同一次独立验证。

**统计口径**：

- 日收益为扣费后单位净值简单收益，含现金日；未平仓按日估值，不在窗口结束强制虚构平仓。真实外部资金流按单位化排除。
- 交易按完整生命周期归并首仓、加仓、减仓、最终退出及全部费用，避免把一次交易拆成多次提高胜率。
- 以日收益序列做20交易日块bootstrap、5,000次、固定种子20260924；计算均值95%置信区间。DSR按原论文定义，日频矩、完整参与择优的trial集合及独立参考样例固定在评估规格。
- 同时输出胜率、平均盈利/亏损、净期望、利润因子、最大回撤、MAE/MFE、换手、容量、阻塞成交比例、滚动12月盈利频率及区间；提供买入持有/现金等适用基准，并标注收益或价格指数口径。
- 参数邻域、延迟一日、去除最佳月份/单证券、双倍费用滑点是稳健性结果；若用于择优，纳入全部trial记录及多重检验，不隐藏追加试验。

| 阶段 | 验收门槛 |
|------|----------|
| 外层OOS共同条件 | 至少70%窗口净盈利；日收益均值95%置信下界>0；DSR≥0.95；双倍费用滑点后净收益>0；回撤≤档位预算 |
| 交易型额外条件 | 至少100个闭合生命周期、60个独立入场日期，净利润因子≥1.2 |
| 配置型额外条件 | 至少五年OOS、24个计划调仓观察点，成本后复合收益>0；不强套交易笔数/PF门槛 |
| 独立留出集 | 252日净收益>0、回撤合规、双倍费用滑点后为正；不要求单个留出集再满足五年/100笔 |
| 交易型影子观察 | 至少60交易日、30个闭合生命周期，成本后为正且回撤合规 |
| 低频配置影子观察 | 至少120交易日、6次调仓观察，成本后为正且回撤合规 |

影子阶段还要求账本和约束一致、无阻断级缺陷。样本不足、零方差、关键历史数据缺失或不可计算指标均为 `INSUFFICIENT_EVIDENCE`，不能以空值通过；不为凑笔数增加交易。

软件交付可以在影子观察尚未积累够样本时完成，但策略保持SHADOW及证据不足；结果文档必须分别列软件验收和策略资格，不把观察任务自动勾成盈利验证完成。
