# 量化开发约束

> **适用**：量化研究、目标、组合政策、订单、成交、生命周期、账户、历史及相关迁移/测试；按受影响业务判断。
> **规则来源**：承接原根 AGENTS 指引；正文非链接源码路径均以仓库根为基准。
> **入口**：[规范索引](../index.md)；门禁摘要见 [AGENTS.md](../../../AGENTS.md)。

## 持久层、执行与研究门禁

- **SQLAlchemy并发写入**：取得行锁后读取用于计算的既有ORM对象必须显式刷新（如`populate_existing=True`），不得认为`FOR UPDATE`会自动更新identity map。

- **量化组合事务**：跨任务提交、规划和成交入口统一先锁组合再锁策略版本；共同决策的成员资格及owner归属证据必须使用同一时点截止，历史分配投影不得代替实时执行授权。

- **组合目标来源**：组合试验目标必须成对携带trial ID与定义hash，批次消费核对冻结版本/政策；未接专用目标建单与真实持仓执行前，禁止把组合目标交给旧扫描信号建单路径。

- **组合政策BUY门禁**：确认BUY在任何复用/早退或提交前必须核对订单绑定与活动生命周期、信号和任务快照各自版本，缺失单一来源不能视为无组合政策；保护SELL保留账本路径。

- **量化目标时点**：组合目标的候选、基准及ETF代表选择必须以`evaluation_as_of`校验全部行情日期，周/月调仓与冷却才使用`decision_date`；缺候选全集证明或`intent=None`不得自动解释为清仓。

- **量化BUY流动性**：所有新增风险BUY须有截至T日经独立开市日历核满20日的明确正数ADV20；旧信号缺字段、畸形值或单日成交额不得代替。

- **量化风险档**：新增风险BUY必须在实时组合锁下核明确档位与七项实际预算，缺档或超档拒绝；回撤到档位预算一半停止新增风险，保护SELL不受此门禁阻断。

- **量化品种规则**：历史模拟与新增风险订单须按证券和执行日核唯一生效规则及真实下一开市日；不得以普通100股整手推断科创板或以ETF类别推断T+0，未认证规则不得放行生产。

- **量化SELL可卖量**：保护退出可保留意图，但生成SELL订单必须有同一持仓和交易日的可信结算可卖量；缺失、畸形、负值或超实际持仓均拒单，不得由持仓总量回退或静默裁剪。

- **量化在途预留**：EXECUTING、PARTIALLY_FILLED及RECONCILIATION_REQUIRED订单在可信券商终态回执前不得经通用状态或目标改写释放资金/可卖量预留；冲突目标保留待对账，迟到真实成交仍需入账。

- **量化成交修订与幂等**：确认/更正/撤销的幂等重放须核操作、目标成交/订单及请求字段；成交修订不得把券商已接触订单退回可通用取消的PROPOSED，旧完成意图有后继活动意图时须隔离后继及其订单而非重开旧意图。

- **量化已发生事实与偏离**：已报告的真实成交、资金或公司行为即使超本地现金/持仓/建议范围也须保留不可变事实并显式标偏离，不能因重放负余额丢弃；偏离未处置不得授新增风险或把诊断余额当结算可卖量。

- **量化资金流单位化**：账户单位收益须逐笔核完整有效外部资金流事件身份及流前同刻估值；累计净流量不能证明逐笔完整，同刻连续流须核现金与持仓价格连续性，缺来源认证保持收益未知。

- **量化签名摘要与生命周期修订**：审核签名消费端必须从业务字段和原件字节重算规范摘要；首笔成交关联生命周期后，未实现全链路状态重放前不得以局部现金/持仓反转放行撤销或更正。

- **量化生产成交投影门禁**：券商账户归属未核实前，人工复核签名及原件字节均不得使报告成交更新生产现金/持仓；可先实现并隔离验收同事务入账软件，生产入口保持关闭。

- **量化历史可得性**：`market.fact_revision.observed_at`仅为本地写入事件时刻，可早于事务提交；不得代替独立上游发布时间、当时可见性或历史研究认证。

- **量化账户双时点**：账户账本历史重放须分开生效与本地登记截止；`recorded_at`可早于事务提交，不得作为券商上游发布时间、历史可见性或研究认证。

- **量化可空身份**：研究快照中的证券代码等pandas可空字段进入`if`或布尔运算前，必须先形成确定的Python布尔值；`pd.NA`不能直接参与代码相等/不等分支。

- **量化输入认证**：股票候选与基准的本地完整性问题须同独立来源、覆盖和账户事实认证问题分列；本地输入齐全不得自动生成组合目标或放行生产执行。

- **量化近期窗口**：股票/ETF候选最近20个独立交易日的成交额、收盘价与复权因子须逐日核验，累计250根有效日线不能替代近期窗口完整性。

- **股票基准证据**：组合股票目标的沪深300基准必须单列并核指数上市有效期及独立交易日历；基金单独快照不受股票基准行质量影响，来源可得时点未认证时不放行生产目标。

- **量化历史行像**：迁移和导出必须保留SQL NUMERIC精度及JSONB原数值类型；Decimal字符串规范视图不得充当原物理行，读取须从原文与字段重算摘要；原文/解释及不变字段比较必须类型敏感，禁止Python字典相等把1/0与true/false混同。

- **量化前驱连续性**：立即前驱须从冻结完整物理schema与原行像重建管理状态，摘要相符不得替代该关系；原件与管理时间比较的规范化边界必须分开。

- **量化删源选择**：修改前须全局排序锁住跨组合全部活引用，并在任务/信号锁后重查全集；driver自动提交不能返回无锁scope，测试须排除其他FK提前阻断目标反例。

- **量化命令选择**：修改前参与者选择不得仅凭Session脏集合断言尚未写入；必须防止已flush或原始SQL写入把后态充作前态。

- **量化命令封口**：清空关联GUC或提前核验约束不得放行同事务未声明订单写入；精确行像的入口、捕获和核验须固定UTC/ISO序列化环境。
