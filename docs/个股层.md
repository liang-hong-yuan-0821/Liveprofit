## 现状：现有 12 个 Agent

Liveprofit（YoHo）现有 12 个 Agent，全部锚定在"个股"维度：

| Agent | 职责 | 产出报告 |
|-------|------|----------|
| 个股技术分析师 | 个股技术指标分析（均线/MACD/RSI/布林带） | `stock_tech_report`（原名 `market_report`） |
| 基本面分析师 | 财务数据、估值分析 | `fundamentals_report` |
| 新闻分析师 | 个股相关新闻舆情 | `news_report` |
| 情绪分析师 | 市场情绪/社交媒体情绪 | `sentiment_report` |

> ⚠️ **2026-08 重命名**：`market_report` → `stock_tech_report`，消除与市场层 7 份宏观报告的歧义。下游全部改为 `state.get("stock_tech_report", "")`。
> 科技/产业链分析师（`tech_market_analyst.py`）已删除——全球指数归入市场层（us_tech/kr_tech），AI 产业链归入板块层（后续实现）。

### 下游消费者

下游节点（研究员辩论、基金经理决策、风控、交易员）读取 4 份个股报告 + 7 份市场层宏观报告：

- **个股层**：`stock_tech_report`、`fundamentals_report`、`news_report`、`sentiment_report`
- **市场层**：`international_news_report`、`us_news_report`、`us_tech_report`、`kr_news_report`、`kr_tech_report`、`cn_news_report`、`cn_tech_report`

通过 `build_market_layer_context(state)` 组装市场层上下文，注入各下游节点的 prompt。

### 全市场模式：逐票循环（2026-08 新增）

全市场模式（`selectedLayer` 含 `"screening"`）下，个股层子图**不进入顶层图**（顶层拓扑 `Market → Sector → Screening → END`），由 `propagate()` 层对候选池**顺序循环**复用同一编译子图：

- `AI/graph/stock_loop.py`：逐票组装"全局态 + 逐票态重置"输入——`PER_STOCK_FIELDS`（报告/辩论状态/工具计数等）全量重置 + 全新初始消息，防上一只票污染；`stock_subgraph.invoke()` 后收进 `stock_results[code] = {final_trade_decision, decision_json, sector, last_close, ...}`
- 单票失败 → `{"error": ...}` 跳过，不阻断其他票；决策结构化复用 `process_signal`（含 `stop_loss` 抽取）
- 单票模式（默认）行为不变：个股层子图仍在顶层图中，单次 invoke 整图
- **2026-08-15 修复**：个股层挂进顶层图需 `selectedLayer` 显式含 `"stock"`——此前仅选 `["market"]` 等非全市场组合时，Stock Layer 会被无条件挂载（`Market → Stock → END`），导致个股层隐式执行。修复后仅 `market`/`sector` 的组合直接收口到 END（`AI/graph/trading_graph.py::_build_graph`，含 `has_stock` 门控）；`selectedLayer` 不含任何有效层时抛 `ValueError`，不再静默回退

## 改造方向

### 对个股分析师的改动

**最小化改动原则**：现有个股分析师的内部逻辑**不变**。改动仅限于：

1. **输入扩展**：个股分析师在生成报告时，可**可选读取**市场层和板块层的产出作为附加上下文：
   - `market_regime_report` — 了解当前大盘环境基调
   - `historical_case_report` — 参考历史类似事件的市场反应
   - `sector_report` — 了解个股所属行业在当前市场中的相对强弱

2. **prompt 微调**：在个股分析师的 system prompt 中加入一段引导，提醒其在分析时参考大盘环境和板块强弱背景。例如：
   > "当前市场整体处于 {market_regime_label} 状态，建议仓位基调为 {position_stance}。所属板块近期的相对强弱为 {sector_relative_strength}。请在分析该个股时，将上述宏观和板块背景纳入考量。"

### 对下游节点的改动

下游节点（研究员辩论、经理决策、风控）做**增量式 prompt 扩展**：

- 将 `market_regime_report`、`historical_case_report`、`sector_report` 作为新的上下文片段注入 prompt
- 向后兼容：字段不存在时为空字符串，不影响现有逻辑

### 数据流变更示意

```
改造前：
  START → [5个个股分析师] → 研究员辩论 → 经理决策 → 风控 → END
           ↓
  仅产出 4 份个股报告

改造后：
  START → [MacroMarket → HistoricalCase] → [SectorAnalyst] → [5个个股分析师(增强)] → 研究员辩论(增强) → 经理决策(增强) → 风控(增强) → END
           ↓                               ↓                  ↓
  market_regime_report            sector_report      现有4份报告 + 大盘/板块背景
  historical_case_report
```
