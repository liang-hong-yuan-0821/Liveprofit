# 市场层 — 宏观市场分析独立子图

> **架构定位**：三层 Subgraph 金字塔的第一层。先于板块层和个股层执行，不依赖 ticker。
>
> **关联文档**：[index.md](index.md) | [板块层](板块层.md) | [个股层](个股层.md)
>
> **实现状态**：✅ 已实现 → [施工方案](plans/市场层重构方案.md)

---

## 架构

市场层是一个**独立编译的 LangGraph 子图**（`AI/marketAgents/market_layer_graph.py`），与父图共享 `AgentState`，写入市场层字段后由个股层读取。

```
顶层 Graph
├── Subgraph: 市场层（独立编译）  ← 本期已实现
│   ├── Layer 0: 国际新闻分析 (Global)
│   └── Layer 1: 各国市场分析 (US / KR / CN)
├── Subgraph: 板块层（预留占位）
└── 个股层 + 辩论 + 风控
```

## Layer 0 — 国际新闻分析

**合并原设计的"宏观事件驱动层 + 历史案例分析"**，在一个 Agent 内完成。

- 地缘政治冲突、战乱、重大自然灾害
- 全球流动性/利率政策（Fed / PBoC / ECB）
- 宏观经济数据（CPI / 非农 / PMI / 社融）
- 大宗商品/汇率联动（原油 / 黄金 / 美元指数）
- 逐事件检索历史案例，给出相似度 + 传导链条 + 资金虹吸提示
- 系统性风险评估（低/中/高）

## Layer 1 — 中国市场 (CN) ★

主战场，分析最深：

**新闻分析**：三级别事件日历（2026-08 升级）
- **短线（1-5日）**：IPO 抽血强度、解禁抛压、交割日临近、两融异动
- **波段（1-4周）**：解禁高峰窗口、季报披露窗口、重大政策会议、季末调仓
- **长线（1-3月）**：宏观数据发布、流动性政策预期、年报季
- 产出 `market_event_calendar` 结构化字段（≤500 字），供下游完整消费

**技术分析**：三级别市场环境判定器（2026-08 升级）
- 7 指数量价（上证/深证/创业板/科创50/上证50/中证1000/上证红利），支持长周期（days=120）
- 市场宽度（涨跌比、涨停跌停统计、涨停梯队高度）
- 资金流向（北向/主力，标注 2024-08-16 后北向仅日终汇总）
- 风格因子（上证50 vs 中证1000 = 大小盘；创业板 vs 上证红利 = 成长vs价值）
- ★ 三级别环境判定（短线/波段/长线）：仓位建议 + 情绪周期 + 主线容纳性
- 产出 `market_regime` 结构化字段（≤800 字），供下游完整消费

## Layer 1 — 美国/韩国市场

分析深度较中国轻，每国 = 新闻 + 技术两个 Agent：

| 市场 | 新闻分析 | 技术分析 |
|------|----------|----------|
| 美国 | 美联储政策、经济数据（CPI/非农）、VIX、财报季 | 标普500/纳指/道指趋势+均线+RSI |
| 韩国 | 央行政策、出口数据、权重股动态 | KOSPI/KOSDAQ + 与美股科技相关性 |

## 下游消费

市场层 7 份报告通过 `build_market_layer_context()` 组装，注入到个股层的 9 个下游节点（bull/bear researcher、research_manager、trader、risk_manager、3 debators、reflection）。

### 占位函数的降级策略

5 个占位函数统一返回 `"数据不可用"`，Agent prompt 已明确要求"数据不可用时如实标注，靠 LLM 训练知识做方向性判断"。美/韩 Agent 体量轻（每个 prompt ≤ 50 行，工具 ≤ 3 个），不完全依赖实时数据。

> **Tushare 降级**：中国市场新增工具在 Tushare 模式下返回"数据不可用（当前数据源不支持，请切换到 akshare）"。`get_china_market_overview` 扩展在 Tushare 下可正常工作（Tushare 支持 7 个指数的日线）。

> 旧设计（`MacroMarketAnalyst → HistoricalCaseAnalyst` 两阶段串行）已废弃——合并为国际新闻分析的单一 Agent 内完成。

### 交易日历校正（T-1 问题修复）

> **实现日期**：2026-08-11 | **方案归档**：[done/技术指标T-1交易日限制梳理方案.md](done/技术指标T-1交易日限制梳理方案.md)

**问题**：Tushare 日频数据需收盘后才能查询（~18:00-20:00 入库）。非交易日或盘中调用时，精确日期查询（`trade_date=xxx`）返回空/N/A，导致分析报告空洞。

**架构变更**：

| 层级 | 变更 | 文件 |
|------|------|------|
| 新增工具模块 | `AI/dataflows/utils/trading_calendar.py`（三级降级：Tushare `trade_cal` → AKShare `tool_trade_date_hist_sina()` → weekday-only 兜底） | `utils/` |
| State 字段 | 新增 `requested_trade_date`（原始请求日期）、`date_correction`（校正说明） | `agent_states.py` |
| 入口校正 | `create_initial_state()` 调用 `get_available_trade_date()` 校正日期；`propagate()` 防御性校正 | `propagation.py`、`trading_graph.py` |
| 接口防御层 | `interface.py` 新增 `_correct_trade_date()`，在 `get_china_market_overview`、`get_market_breadth`、`get_market_fund_flow` 中自动校正 | `interface.py` |
| Analyst Prompt | 所有 Analyst 统一注入日期校正信息（`date_line` 模式），纯日期传接口 | `cn_tech_analyst.py` 等 10 个文件 |
| B 类标注 | akshare "取最新快照"接口标注 `> ⚠️ 数据日期: YYYY-MM-DD` | `akshare_provider.py` |
| Stockstats | 日期匹配 `== curr_date` → `<= curr_date`（自动容错） | `stockstats.py` |
| 配置 | 新增 `TUSHARE_DATA_READY_HOUR`（默认 20）、`TRADE_CALENDAR_REFRESH_DAYS`（默认 365）、`TRADE_DATE_RETRY_STEPS`（默认 3） | `default_config.py`、`.env.example` |

**校正规则**：
- 历史日期 → 仅校验交易日（是则不变，否则回退）
- 今天 + 交易日 + 当前 >= 20:00 → 不变
- 今天 + 交易日 + 当前 < 20:00 → 回退到上一交易日
- 今天 + 非交易日 → 回退到上一交易日

**降级链路**：Tushare `trade_cal`（需 token）→ AKShare（免费）→ weekday-only（兜底，不识别节假日）→ fail-open（返回原值不阻塞）
