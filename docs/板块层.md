# 板块层 — 全市场行业/概念板块横向对比

> **架构定位**：三层金字塔的第二层。在市场层之后、个股层之前执行。
>
> **关联文档**：[index.md](index.md) | [市场层](市场层.md) | [个股层](个股层.md)

---

## 现状

> **2026-08 更新**：板块层 6 个工具已全部支持 **Tushare + AKShare 双数据源**。通过 `BaseStockDataProvider` 接口契约 + `hasattr` dispatch 自动切换，不再有硬编码数据源判断。
>
> 全市场行业/概念板块的横向强弱对比、轮动排名，已覆盖申万一级行业（31 个）和同花顺概念板块（700+）。

## 架构

板块层是一个**独立编译的 LangGraph 子图**（`AI/sectorAgents/sector_layer_graph.py`），与父图共享 `AgentState`，写入板块层字段后保持独立（不注入个股层决策节点）。

```
顶层 Graph
├── Subgraph: 市场层（独立编译 ✅）
├── Subgraph: 板块层（独立编译）    ← 本期实现
│   ├── 板块新闻分析 (Sector News)      — 行业排名 + 资金流向 + 板块轮动
│   ├── 板块技术分析 (Sector Tech)      — 全行业技术扫描 + AI专题深挖 + 风格验证
│   └── 板块轮动预测 (Sector Rotation)  — 题材板块逐日轮动 + 涨停连板强度 + 明日预测
└── 个股层 + 辩论 + 风控
```

## 板块层内部结构

| Agent | 文件 | 输出字段 | 工具循环 |
|-------|------|----------|:---:|
| 板块新闻分析 | `sector_news_analyst.py` | `sector_news_report` | ✅ |
| 板块技术分析 | `sector_tech_analyst.py` | `sector_tech_report` | — |
| 板块轮动预测 | `sector_rotation_analyst.py` | `rotation_prediction_report` | — |

> 板块层不依赖 `company_of_interest`，使用 `trade_date` + 市场层产出（`cn_tech_report`、`cn_news_report`、`international_news_report`）作为输入上下文。

## 板块新闻分析

**职责**：从"信息面 + 资金面"维度，扫描全市场行业板块和概念板块的状态。

- 申万一级/二级行业近 N 日涨跌幅排名，识别领涨/领跌行业
- 行业板块主力资金净流入/流出排名，判断资金进攻方向
- 热门概念板块的涨幅、成交额变化、持续性判断
- 近期产业政策/事件对相关板块的催化
- 板块轮动主线判断（有主线/快速轮动/无方向）及置信度

## 板块技术分析

**职责**：逐行业做技术面体检，输出全行业技术状态全景图。覆盖 A 股所有申万一级行业（汽车、医药、食品饮料、电力设备、电子、银行……）。

- **全行业技术扫描**：逐行业做均线/趋势/量价分析，输出技术状态矩阵（强势/中性/弱势）
- **行业相对强度 (alpha)**：各行业相对大盘的超额收益排名
- **板块轮动技术验证**：对新闻分析识别的"主线"做技术面确认（趋势健康度、量价配合）
- **行业技术风险扫描**：领涨行业是否出现背离/高位放量滞涨；超跌行业是否出现底部企稳信号
- **AI/科技产业链专题**：科技相关行业的上下游轮动分析（存储芯片→半导体→光模块→AI服务器→算力→AI应用）
- **全球科技映射**：美股科技→韩股科技→A股科技板块的传导有效性判断

## 板块轮动预测

**职责**：基于 Tushare 打板专题数据（`limit_cpt_list`），构造逐日题材板块轮动矩阵，识别强势主线、新晋热点和退潮板块，输出明日最可能上涨的题材板块预测。

- **逐日轮动矩阵**：拉取近 5 个交易日每天单独的题材板块 TOP 排名（含涨停家数、连板家数、连板高度）
- **上榜统计与轮动分类**：识别持续主线（连续上榜）、新晋异动（最后 1-2 天新上榜）、退潮（掉出榜单）、蓄势上升（TOP N 外排名持续爬升）
- **强度分级**：基于涨停家数分位数（P30/P70）和连板高度中位数（P50）自适应分级——强势主线/普涨式轮动/龙头独立行情/边缘题材
- **明日预测**：LLM 推理输出 TOP 3-5 预测板块 + 置信度 + 逻辑链 + 风险提示

> **数据源**：使用同花顺（THS）题材板块分类体系，与板块新闻/技术分析使用的东方财富（EM）概念板块是两套独立分类，不做跨体系名称对齐。

## 输入

- `trade_date`
- 市场层产出（`cn_tech_report`、`cn_news_report`、`international_news_report`）— 板块层子图入口处组装摘要版上下文

## 产出

- `sector_news_report` — 板块新闻分析完整报告
- `sector_tech_report` — 板块技术分析完整报告
- `sector_shortlist` — 三级别候选板块短名单（结构化字段，下游消费，≤1200 字）
- `sector_tech_confirm` — 候选板块技术确认结论（结构化字段，下游消费，≤800 字）
- `rotation_prediction_report` — 板块轮动预测完整报告（主线+新热点+退潮+明日预测）
- `rotation_top_picks` — 轮动预测速览结构化文本（供下游展示，≤1200 字）
- `market_regime`（来自市场层）— 三级别市场环境判定
- `market_event_calendar`（来自市场层）— 三级别事件日历

## 数据源

共 **8 个**接口函数（7 实现 + 1 占位），位于 `AI/dataflows/` 下。Toolkit 定义在 `AI/stockAgents/utils/agent_utils.py`。

### 双数据源实现（6 个接口方法）

所有板块工具通过 `BaseStockDataProvider` 基类定义接口契约，`AKShareProvider` 和 `TushareProvider` 分别实现。

| 接口方法 | AKShare 实现 | Tushare 实现 |
|----------|-------------|-------------|
| `get_industry_sector_performance(days)` | `stock_board_industry_name_em()` + `stock_board_industry_hist_em()` 遍历 | `index_classify(SW2021, L1)` + `sw_daily()` 遍历 31 个申万一级行业 |
| `get_concept_board_heat_rank(days)` | `stock_board_concept_name_em()` + `stock_board_concept_hist_em()` 批量获取，热度=涨跌幅×0.6+成交量×0.4 | `ths_index(exchange='A', type='I')` + `ths_daily()` 遍历 700+ 同花顺概念板块 |
| `get_sector_technical_screening(days)` | 各行业 `stock_board_industry_hist_em()` 长周期数据 → 计算 MA/RSI/MACD/量比 | 各行业 `sw_daily()` → 计算 MA/RSI/MACD/量比 |
| `get_sector_relative_strength(days)` | 各行业数据 + 上证综指基准 → alpha | `sw_daily()` + `index_daily(000001.SH)` → alpha |
| `get_concept_board(concept_name, days)` | `stock_board_concept_hist_em(symbol=name)` 单个板块 | `ths_index` 名称匹配 → `ths_daily(ts_code)` |
| `get_all_concept_boards(days)` | 遍历 `AI_INDUSTRY_CHAIN` 9 个子板块 | 遍历 `AI_INDUSTRY_CHAIN` 关键词匹配 `ths_index` 名称 |

### 已有工具继承（2 个）

| 函数 | 说明 |
|------|------|
| `get_ai_industry_chain(days=10)` | AI 产业链各细分板块数据，从旧 `tech_market_analyst` 继承，底层调用 `get_all_concept_boards` |
| `get_tech_correlation_analysis(days=10)` | 全球科技指数相关性 + 趋势预测，从旧 `tech_market_analyst` 继承 |

### 占位（1 个）

| 函数 | 降级策略 |
|------|----------|
| `get_industry_policy_news(curr_date)` | 占位：无免费行业政策聚合接口，Agent 靠 LLM 知识推断 |

> **数据源切换**：通过 `hasattr(prov, 'method')` 自动检测能力，不支持的 provider 继承基类 `_not_supported()` 默认返回，无需硬编码判断。

## 下游消费

> **设计决策（2026-08 更新）**：板块层产出通过**结构化字段**（`sector_shortlist`、`sector_tech_confirm`）注入个股层决策节点。各分析师额外输出紧凑的结构化结论字段（≤800-1200 字），下游通过 `build_cross_layer_context(state)` 完整消费，避免截断丢失关键结论。

> 旧决策（2026-08-02，已废弃）：板块层产出不注入个股层。新方案通过结构化字段实现跨层上下文传递。
